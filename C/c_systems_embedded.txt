# 4.1 Language Standards & Evolution
What are the major C standard revisions?	C89/C90 (ANSI C, the classic baseline), C99, C11, C17 (bug-fix only), and C23. Each adds features while staying largely backward compatible. Select one with `-std=c11` etc.; check `__STDC_VERSION__` at compile time.
Name key features introduced in C99.	`//` line comments, `inline` functions, variable-length arrays, designated initializers, `<stdint.h>` fixed-width types, `<stdbool.h>`, compound literals, `restrict`, mixed declarations and statements, and `long long`.
Name key features introduced in C11.	`_Static_assert`, `_Generic` type-generic selection, atomics (`<stdatomic.h>`), threads (`<threads.h>`), anonymous structs/unions, `_Alignas`/`_Alignof`, `_Noreturn`, optional bounds-checked functions (Annex K), and removal of `gets`.
What did C17 change?	Nothing functionally new — C17 is a defect-report/clarification release that fixes wording and inconsistencies in C11, so code targeting it uses the same features with cleaner specification.
Name key features introduced in C23.	`nullptr`, `constexpr`, `typeof`, `#embed`, making `bool`/`true`/`false`/`static_assert` keywords, binary literals (`0b`), digit separators, `[[attributes]]`, and checked integer arithmetic helpers.
What is the difference between a freestanding and a hosted implementation?	A hosted implementation provides the full standard library and starts at `main` under an OS. A freestanding implementation (kernels, bare-metal firmware) guarantees only a minimal header subset (`<stddef.h>`, `<stdint.h>`, `<limits.h>`, `<stdbool.h>`, etc.), no `malloc`/`stdio`, and may use a custom entry point.
How do you select a C standard and check which is in effect?	Pass `-std=c11`/`-std=c17`/`-std=c23` (add `-pedantic` for strict ISO, or use `-std=gnu11` for GNU extensions), and read the predefined `__STDC_VERSION__` macro (e.g. `201710L` for C17) to branch on the standard at compile time.

# 4.2 Concurrency & the C Memory Model
What are the "sequenced-before", "happens-before", and "synchronizes-with" relations?	They define ordering of memory effects: sequenced-before orders operations within one thread; synchronizes-with links a release operation to the acquire that reads it across threads; happens-before is the transitive combination that decides which writes a read must observe.
What does "a data race is undefined behavior" mean in C?	If two threads access the same non-atomic object, at least one writing, with no synchronization ordering them, the entire program's behavior is undefined — not just a wrong value. Use mutexes or atomics to establish a happens-before edge between the accesses.
What do the C memory orders permit the compiler/CPU to reorder?	`relaxed`: atomicity only, any reordering. `acquire`: later accesses can't move before this load. `release`: earlier accesses can't move after this store. `acq_rel`: both, for read-modify-write. `seq_cst`: a single global total order (strongest, default).
What is false sharing?	When two threads modify different variables that share a cache line, the cache-coherence protocol bounces the line between cores, destroying performance despite no logical sharing. Fix by padding/aligning hot per-thread data onto separate cache lines.
What is thread-local storage in C?	Per-thread variables declared `_Thread_local` (C11) or `__thread` (GCC), giving each thread its own independent instance — useful for per-thread errno-like state or caches without locking. Each thread initializes and destroys its own copy.
How do you do safe lazy one-time initialization?	Use `call_once` (C11) / `pthread_once` to run an init function exactly once across threads. For a hand-rolled double-checked lock, the flag and pointer must be atomics with acquire/release ordering — otherwise the classic double-checked-locking bug reappears.
When would you choose a mutex vs a spinlock vs a read-write lock?	Mutex: general mutual exclusion, sleeps when contended (good for longer/blocking sections). Spinlock: busy-waits, only worth it for very short critical sections on multiple cores. Read-write lock: many concurrent readers but exclusive writers, when reads dominate.
What is the ABA problem, and how is it mitigated?	In lock-free code, a compare-and-swap sees a value change A→B→A and wrongly assumes nothing changed, though the state (e.g. a freed-and-reused node) did. Mitigations: tagged pointers with version counters, and hazard pointers to defer reuse.
What is the correct pattern for a condition-variable wait?	Hold the mutex and loop on the predicate: `while (!ready) cond_wait(&cv, &m);`, because waits can wake spuriously or be stolen. Barriers and producer-consumer queues build on the same wait-in-a-loop discipline.

# 4.3 Embedded & Bare-Metal
What characterizes a freestanding bare-metal environment?	No operating system, so no `malloc`/`stdio` by default, a custom startup routine (`_start`/reset handler) that sets up the stack and copies/zeros data sections, and only the freestanding subset of headers. Your code owns the hardware directly.
Why must memory-mapped hardware registers be accessed through `volatile`?	A peripheral register can change on its own (status bits) and writes have side effects (triggering hardware), so `volatile` forces the compiler to perform every read/write exactly as written instead of caching or eliding "redundant" accesses.
How do you set, clear, and toggle a bit in a hardware register?	Set: `REG |= (1u << n);` Clear: `REG &= ~(1u << n);` Toggle: `REG ^= (1u << n);` Test: `if (REG & (1u << n))`. `REG` is a `volatile`-qualified pointer/macro so the read-modify-write actually reaches the hardware.
Why keep interrupt service routines (ISRs) short, and how do they share data?	An ISR preempts normal code, so long ISRs add latency/jitter and can miss other interrupts. Do minimal work (set a flag, enqueue data) and defer processing to the main loop; share state via `volatile sig_atomic_t`-style flags, mindful of reentrancy.
What is fixed-point arithmetic, and when is it used?	Representing fractional values as scaled integers (e.g. Q16.16: an `int32_t` where the low 16 bits are the fraction), used on MCUs without a floating-point unit. It gives deterministic, fast math but requires manual scaling on multiply/divide.
Why avoid dynamic allocation in embedded/real-time systems?	The heap can fragment, `malloc` timing is non-deterministic (bad for hard real-time), and there's often no MMU/swap so out-of-memory is fatal. Embedded code favors static allocation, fixed pools, and arenas with bounded, predictable behavior.
What are linker scripts and memory sections for?	A linker script maps code/data into the chip's memory: `.text`/`.rodata` (code/constants in flash), `.data` (initialized RAM globals, copied from flash at startup), `.bss` (zeroed RAM). Custom sections via `__attribute__((section(...)))` place things at specific addresses.
How are constants placed in flash/ROM, and what is a vector table?	Marking data `const` lets the toolchain place it in read-only flash instead of RAM, saving RAM. The interrupt vector table — an array of handler addresses at a fixed location — plus the reset/startup code are placed by the linker script at the addresses the hardware expects.
Why pack structs for wire/register layouts, and what is the trade-off?	`__attribute__((packed))` / `#pragma pack` removes padding so the struct exactly matches a hardware register or on-wire byte layout. The trade-off: members may become unaligned, making access slower or fault-prone on some architectures.
What are weak symbols used for in embedded code?	A `__attribute__((weak))` default (e.g. a default interrupt handler) can be overridden by a strong definition elsewhere without a link error. Firmware provides weak default handlers so applications can override only the ones they need.
Why does endianness matter in embedded protocols and serialization?	Different devices may store multi-byte values in different byte orders, so a struct dumped raw on one machine is misread on another. Serialize with an explicit byte order (often big-endian/network order) and convert on both ends.
What is a ring (circular) buffer used for in embedded systems?	A fixed-size FIFO with head/tail indices that wrap around, giving lock-free-ish producer-consumer (e.g. ISR produces, main loop consumes) without dynamic memory. Careful index/atomic handling makes single-producer/single-consumer use safe without locks.
What are watchdog timers, and why avoid optimizer-exploitable UB in embedded code?	A watchdog resets the system if the code fails to "kick" it periodically, recovering from hangs. Because embedded builds run at high optimization for years unattended, any undefined behavior the optimizer can exploit (signed overflow, aliasing) risks subtle, hard-to-debug failures — so keep timing deterministic and code UB-free.

# 4.4 Real-Time Operating Systems (RTOS)
What distinguishes hard, soft, and firm real-time systems?	Hard real-time: a missed deadline is a failure (airbag, motor control). Soft real-time: occasional misses degrade quality but are tolerable (media). Firm: late results are useless but not catastrophic. An RTOS prioritizes determinism over average throughput.
What scheduler types does an RTOS use?	Preemptive fixed-priority (the common default — the highest-priority ready task runs, preempting lower ones), round-robin/time-sliced (equal-priority tasks share the CPU in turns), and cooperative (tasks yield voluntarily). Preemptive priority scheduling gives bounded latency.
What are the typical states of an RTOS task?	Running (on the CPU), Ready (able to run, waiting for the scheduler), Blocked (waiting on a resource/event/delay), and Suspended (explicitly paused). The scheduler moves tasks between Ready and Running by priority.
What is the tick interrupt, and what is tickless idle?	A periodic timer interrupt (`SysTick`) drives time slicing, delays, and timeouts, and triggers context switches between tasks. Tickless idle stops the periodic tick when the system is idle to save power, waking only for the next scheduled event.
What synchronization primitives does an RTOS provide?	Mutexes (with priority inheritance), binary and counting semaphores, event flags/groups (waiting on bit combinations), and message queues/mailboxes for passing data between tasks. Each has an ISR-safe variant for use from interrupts.
What is priority inversion, and how is it solved?	A high-priority task blocks on a mutex held by a low-priority task, which a medium-priority task then preempts — so the high task waits indirectly on the medium one. Fixes: priority inheritance (the low task temporarily inherits the high priority) or priority-ceiling protocols.
What are deadlock and starvation in a real-time context?	Deadlock: tasks each hold a resource the other needs, so none proceeds (avoided by consistent lock ordering / timeouts). Starvation: a low-priority task never runs because higher-priority tasks monopolize the CPU (avoided by priority design, aging, or bounded execution).
Why must you use "…FromISR" API variants inside an ISR?	Regular blocking RTOS calls can suspend the caller, which is illegal in interrupt context. The `…FromISR` variants (e.g. `xQueueSendFromISR`) are non-blocking and ISR-safe, and report whether a higher-priority task was woken so the ISR can request a context switch on exit.
How are task stacks and heaps managed in an RTOS?	Each task has its own fixed stack; stack-overflow detection (guard words / MPU) catches overruns, which are a common bug. Memory comes from static allocation or fixed pools rather than a general heap, keeping usage bounded and deterministic.
How do RTOS software timers and precise periodic tasks work?	Software timers schedule callbacks after a delay/period off the tick. For precise periodic work a task uses an absolute-deadline delay (e.g. `vTaskDelayUntil`) that accounts for its own run time, avoiding the drift that a relative `vTaskDelay` accumulates.
What latency concepts matter in an RTOS?	Interrupt latency (time from an interrupt to its handler running), scheduling latency (time for the right task to be dispatched), jitter (variation in these), and worst-case execution time (WCET) — the analyzed upper bound needed to prove deadlines are met.
What are rate-monotonic (RMS) and earliest-deadline-first (EDF) scheduling?	RMS is a fixed-priority scheme for periodic tasks where shorter periods get higher priority — optimal among fixed-priority policies, schedulable below a utilization bound (~69% for many tasks). EDF is dynamic (nearest deadline runs first) and can reach 100% utilization.
How does an RTOS protect memory between tasks?	Using the MPU (memory protection unit) to give each task access only to its own stack/data, so a fault in one task can't silently corrupt another — plus memory pools instead of a shared heap to avoid fragmentation. Full MMUs are rare on MCUs.
Name common RTOSes.	FreeRTOS, Zephyr, ThreadX/Azure RTOS, RT-Thread, µC/OS, VxWorks, and RTEMS. They range from tiny open-source kernels for MCUs (FreeRTOS, Zephyr) to certified commercial systems for safety-critical use (VxWorks).
How do you get real-time behavior on Linux?	Apply the `PREEMPT_RT` patch (now largely mainline) for a fully preemptible kernel, use `SCHED_FIFO`/`SCHED_RR` real-time scheduling policies, call `mlockall` to prevent page-fault jitter, and pin work to isolated CPUs (CPU isolation/affinity).
What are core FreeRTOS API calls?	`xTaskCreate` (create a task), `vTaskDelay`/`vTaskDelayUntil` (sleep/periodic), `xQueueSend`/`xQueueReceive` (message queues), `xSemaphoreTake`/`xSemaphoreGive` (semaphores/mutexes), `taskENTER_CRITICAL`/`taskEXIT_CRITICAL` (critical sections), and `configTICK_RATE_HZ` (tick frequency).

# 4.5 Linux / POSIX Systems Programming
What is the difference between a system call and a libc wrapper, and how is `errno` set?	A system call is a direct kernel request (e.g. `read`, `open`); a libc function may wrap one or be pure user space (`strlen`). The `syscall()` interface invokes one by number. On failure syscalls return -1 and set `errno`; the wrapper propagates that.
What does the file-descriptor model mean, and what is `O_CLOEXEC`?	Files, pipes, sockets, and devices are all small integer descriptors used with the same `read`/`write`/`close`. `dup`/`dup2` duplicate/redirect them. `O_CLOEXEC` marks a descriptor to close automatically on `exec`, so children don't inherit it — important for security and leak avoidance.
What is `mmap` used for, and what does `mprotect` do?	`mmap`/`munmap` map a file or anonymous memory into the address space: memory-mapped file I/O, large/aligned allocations, and shared memory (`MAP_SHARED`) or private copies (`MAP_PRIVATE`). `mprotect` changes a region's permissions (e.g. read-only or executable).
Why use `epoll` over `select`/`poll` for many connections?	`select`/`poll` scan the whole fd set each call (O(n)), and `select` is capped by `FD_SETSIZE`. `epoll` registers interest once and returns only the ready fds (O(ready)), scaling to tens of thousands of connections; it supports level- and edge-triggered modes.
What causes a zombie or orphan process, and how do you handle each?	A zombie is a dead child whose exit status the parent hasn't reaped — reap with `wait`/`waitpid` or handle `SIGCHLD`. An orphan is a child whose parent exited first; it is re-parented to `init`, which reaps it. Process groups/sessions organize related processes.
What does `sigaction` offer over `signal`, and what is `SA_RESTART`?	`sigaction` gives reliable, portable control: a signal mask applied during the handler, flags, and `SA_RESTART` to auto-restart interrupted slow syscalls (otherwise they fail with `EINTR`). `signalfd` lets you receive signals as readable file-descriptor events instead.
What IPC mechanisms does POSIX provide?	Pipes and FIFOs (byte streams), System V and POSIX shared memory (fastest, shared address space), semaphores and message queues (synchronization/messaging), and Unix domain sockets (local bidirectional streams/datagrams, can pass file descriptors). Choose by data shape and performance needs.
What are the basics of network sockets on Linux?	Create a `socket` (TCP `SOCK_STREAM` or UDP `SOCK_DGRAM`), resolve addresses with `getaddrinfo`, then `bind`/`listen`/`accept` (server) or `connect` (client), and `send`/`recv`. Sockets can be blocking or non-blocking (for use with `epoll`).
How do you measure time on Linux, and monotonic vs realtime clocks?	`clock_gettime(CLOCK_MONOTONIC, &ts)` gives elapsed time unaffected by clock adjustments (use for intervals/timeouts), while `CLOCK_REALTIME` gives wall-clock time (can jump). `timerfd` delivers timer expirations as fd events; `nanosleep` sleeps with nanosecond resolution.
How do you parse command-line options and read the environment?	`getopt`/`getopt_long` parse `argv` into options and arguments (handling `-x`, `--long`, and option arguments). Environment variables come via `getenv`, and `argv[0]` is the program name; treat all of these as untrusted input in privileged programs.
What are daemonization, `syslog`, and `/proc` and `/sys`?	Daemonizing detaches a process from its controlling terminal to run in the background (fork, `setsid`, redirect std streams). `syslog` sends log messages to the system logger. `/proc` and `/sys` are virtual filesystems exposing process and kernel/device state as readable files.
What is dynamic linking, and what does `LD_PRELOAD` do?	At load time the dynamic linker resolves shared-library symbols, guided by `RPATH`/`RUNPATH` search paths, and supports symbol interposition. `LD_PRELOAD` forces a library to load first so its symbols override others (for profiling/mocking) — and is ignored for setuid programs for safety. `dlopen` loads libraries at runtime.
What are the differences between glibc and musl, and what are feature-test macros?	glibc is the large, feature-rich default on most Linux distros; musl is a small, simple, static-linking-friendly libc (common in Alpine/containers) with stricter standards conformance. Feature-test macros like `_GNU_SOURCE`, `_POSIX_C_SOURCE`, and `_DEFAULT_SOURCE` expose specific extension sets and must be defined before headers.

# 4.6 Toolchain, Debugging, Testing & Analysis
What do the `-O` optimization levels mean in gcc/clang?	`-O0` none (fast compile, best debugging), `-O1`/`-O2` progressively more optimization, `-O3` aggressive (may grow code), `-Os` optimize for size, `-Ofast` `-O3` plus non-conforming fast math. Combine with `-g` for debug info; `-Wall -Wextra -Werror` turns warnings into build-blocking errors.
How do you inspect compiler output and binaries?	`gcc -E` shows preprocessed source, `-S` shows assembly. On binaries: `objdump -d` disassembles, `nm` lists symbols, `readelf` dumps ELF headers/sections, `strings` finds embedded text, and `ldd` shows shared-library dependencies.
What can you do with gdb/lldb?	Set breakpoints and watchpoints (stop when a variable changes), single-step, inspect the call stack with backtraces, examine and modify variables/memory, and load a core dump to diagnose a crash after the fact. Compile with `-g` for source-level debugging.
What runtime memory/UB errors do the sanitizers and Valgrind catch?	AddressSanitizer: heap/stack/global overflows, use-after-free, double-free. UBSan: signed overflow, bad shifts, misalignment. ThreadSanitizer: data races. MemorySanitizer: uninitialized reads. LeakSanitizer: leaks. Valgrind's memcheck catches many of these by interpretation (no recompile). Run your tests under them.
What is the difference between static and dynamic analysis tools?	Static analysis (`clang-tidy`, `cppcheck`, `scan-build`, Coverity) inspects source without running it, flagging suspicious patterns and possible UB across all paths. Dynamic analysis (Valgrind, sanitizers) observes an actual run, catching real errors on exercised paths. They complement each other.
When and why would you fuzz C code?	When it parses untrusted input (file formats, network protocols). A fuzzer (libFuzzer, AFL++) generates and mutates inputs against a small harness, running under sanitizers to surface crashes, hangs, and memory-safety bugs that hand-written tests miss.
What C unit-testing frameworks exist?	Unity (tiny, embedded-friendly), CMocka (with mocking support), Check (fork-isolated tests), and Criterion (modern, auto-registered tests). At minimum, assertion-based tests with `assert`-style macros in a test binary catch regressions.
What do profilers like `perf`, `gprof`, and cachegrind tell you?	`perf` samples where CPU time and cache misses/branch mispredictions occur (low overhead, whole-system). `gprof` gives call-graph timing from instrumented builds. cachegrind (Valgrind) simulates the cache to pinpoint cache-unfriendly code. Use them to find real hot paths before optimizing.
What build and packaging tools are common for C?	Make (classic dependency-driven builds), CMake and Meson (portable build-system generators), autotools (`./configure`), and `pkg-config` (discovering library flags). Cross-compilation toolchains build for a different target architecture than the host.

# 4.7 Compiler Extensions & Inline Assembly
What common GCC/Clang `__attribute__`s should you know?	`packed`/`aligned` (layout), `noreturn` (function never returns), `deprecated`, `always_inline`, `constructor`/`destructor` (run before/after `main`), `format(printf,...)` (enable format checking on your own functions), `cleanup` (run a function when a variable leaves scope), and `warn_unused_result`.
What are the MSVC counterparts to GCC attributes?	`__declspec(...)` (e.g. `__declspec(noreturn)`, `dllexport`/`dllimport`, `align`) and MSVC-specific `#pragma`s (like `#pragma pack`) and intrinsics. Portable code hides these behind macros selected by compiler-detection `#if`s.
What do the common compiler builtins do?	`__builtin_expect(cond, expected)` hints branch likelihood; `__builtin_unreachable()` marks impossible code for optimization; `__builtin_*_overflow` do checked arithmetic; `__builtin_types_compatible_p` and `__builtin_offsetof` support generic macros. They give access to hardware/optimizer features from C.
What are SIMD intrinsics and vector extensions?	Intrinsics like those in `<immintrin.h>` map to CPU SIMD instructions (SSE/AVX/NEON) to process multiple data lanes per instruction, and GCC's `vector_size` attribute defines portable vector types. They accelerate data-parallel loops (image, audio, math) beyond what auto-vectorization achieves.
What is inline assembly, and what are its extended-syntax parts?	`asm`/`__asm__` embeds assembly in C. Extended GCC syntax specifies output operands, input operands, and a clobber list (registers/memory the code modifies) with constraints binding them to C variables, so the compiler schedules around it correctly. Used for privileged instructions and micro-optimizations.
What are some useful pragmas?	`#pragma once` (include-guard shortcut), `#pragma GCC diagnostic push`/`ignored "-Wxxx"` (locally suppress a warning and restore it), and `#pragma pack(n)` (set struct packing/alignment). They give per-region control the command-line flags can't.
What are statement expressions and other common GNU C extensions?	A statement expression `({ int t = a; t*t; })` lets a block yield a value — used to write safe macros with local temporaries. Other GNU extensions include `typeof`, case ranges (`case 1 ... 5:`), and zero-length arrays. They are non-standard, so guard them for portability.

# 4.8 Custom Memory Management
What is an arena (region) allocator?	An allocator that hands out memory by bumping a pointer through a large pre-allocated block, with no per-object free — you free the whole arena at once. Extremely fast and fragmentation-free, ideal when many objects share a lifetime (per-request, per-frame).
What is an object pool / free list?	A pre-allocated set of fixed-size slots linked in a free list; allocation pops a slot and free pushes it back — both O(1) with no fragmentation. Ideal for frequently created/destroyed same-size objects and for deterministic embedded/real-time allocation.
What is slab allocation?	A kernel-style scheme (Linux slab/slub) that keeps caches of pre-initialized objects of a given type/size, so allocation avoids repeated construction and reduces fragmentation. Objects are grouped in "slabs" of pages per size class.
Why is `alloca` dangerous?	`alloca(n)` allocates on the stack and is auto-freed at return, but it has no failure indication — a large or attacker-controlled `n` silently overflows the stack (crash/exploit), and its interaction with inlining/loops is subtle. Prefer a bounded VLA or `malloc`.
How do you allocate aligned memory for SIMD/DMA?	Use `aligned_alloc(alignment, size)` (C11) or `posix_memalign`, or over-allocate and round the pointer up to the required boundary yourself (storing the original for `free`). Alignment matters for SIMD loads/stores and DMA engines that require aligned buffers.
What are `malloc` internals worth knowing?	Allocators (e.g. glibc) split memory into chunks tracked by size-class bins and use per-thread arenas to reduce lock contention. Understanding chunk headers, bins, and how freed blocks coalesce explains fragmentation, performance, and heap-exploitation techniques.
How can you replace the memory allocator?	Link against a different allocator like jemalloc or tcmalloc (better multithreaded performance/fragmentation), or use `LD_PRELOAD`/allocator hooks to interpose `malloc`/`free` at runtime — useful for profiling, debugging, or tuning without changing source.
What are ownership and lifetime conventions in C APIs?	Since C has no automatic memory management, an API must document who allocates and who frees each object (e.g. "caller must `free` the returned buffer"). Patterns include caller-owns, callee-owns, and reference counting to share objects with a tracked lifetime.

# 4.9 Secure Coding Standards & Hardening
What is the CERT C Secure Coding Standard?	A set of rules and recommendations for secure C grouped by topic — INT (integers), STR (strings), MEM (memory), FIO (file I/O), ERR (error handling), etc. — each pairing a risky pattern with its compliant fix. Widely used as a checklist and for static-analysis rulesets.
What is MISRA-C and where is it used?	A coding standard for safety-critical/embedded systems (automotive, medical, aerospace) that restricts C to a safer, analyzable subset: no (or controlled) dynamic memory, no recursion, no reliance on undefined/unspecified behavior, strong typing, and single-exit rules.
How do common C vulnerability classes map to CWE IDs?	CWE-119/787/125 = out-of-bounds write/read (buffer errors), CWE-416 = use-after-free, CWE-190 = integer overflow/wraparound, CWE-78 = OS command injection, CWE-134 = uncontrolled format string, CWE-476 = null pointer dereference. These dominate the CWE Top 25 for C programs.
What is the first step in threat-modeling a C program?	Identify the trust boundaries and attack surface — every place untrusted input enters (argv, files, network, environment, IPC) — then trace each input to its sinks (allocation sizes, indices, format strings, command strings, paths) and ensure validation happens before use. Mitigations layer on top of validation, not instead of it.
Which compiler/linker hardening flags should you enable?	`-fstack-protector-strong` (canaries), `-D_FORTIFY_SOURCE=2/3` (buffer-size checks), `-fPIE -pie` (ASLR for the executable), `-Wl,-z,relro,-z,now` (read-only GOT), and `-Wformat -Wformat-security -Wall -Wextra`. Run `-fsanitize=address,undefined` in CI.
What hardware-assisted control-flow protections exist?	Shadow stacks and indirect-branch tracking via Intel CET, pointer authentication (ARM PAC) that signs return addresses/pointers, and branch-target identification (ARM BTI). They enforce control-flow integrity in hardware, making ROP/JOP and return-address overwrites much harder.
What runtime mechanisms enforce least privilege on Linux?	`seccomp` filters restrict which syscalls a process may make; Linux capabilities split root's powers into droppable fine-grained bits; explicit privilege dropping (`setuid`/`setgid` to an unprivileged user after setup); and namespaces/sandboxes isolate the process — limiting the blast radius of an exploit.
What are safer-by-construction patterns to avoid raw pointer+length bugs?	Carry a buffer's size with it — a "fat pointer"/slice struct `{ ptr, len }` passed as one unit — so length is never separated from the data, and use bounds-checked accessors. Compiler options like `-fbounds-safety` enforce this, eliminating whole classes of overflow.

# 4.10 Performance & Micro-Optimization
Why do cache misses dominate performance more than raw instruction count?	Modern CPUs execute instructions in ~1 ns but a main-memory access takes ~100 ns. A loop chasing linked-list pointers spends most of its time stalling on cache misses. Keeping data in L1/L2 cache is the single biggest performance lever.
What is spatial locality and why should C arrays be traversed row-major?	Spatial locality means accessing addresses close together lets the CPU prefetch cache lines. A C 2D array a[R][C] is stored row-major — iterating a[i][j] by incrementing j is sequential. Column-first traversal (a[j][i]) jumps by C*sizeof(a[0][0]) bytes per step, causing cache misses.
What does restrict tell the compiler and how does it improve performance?	restrict on a pointer parameter promises no other pointer in the function aliases the same memory. This lets the compiler eliminate redundant loads and enables auto-vectorization of loops that would otherwise be blocked by potential aliasing.
What is __builtin_expect and when should you use it?	__builtin_expect(cond, likely_value) hints which path is taken most often, letting the compiler lay out code so the common path has no branch jump. Use it for error checks that almost never fire (e.g. __builtin_expect(ptr != NULL, 1)).
What is profile-guided optimization (PGO)?	Compile with -fprofile-generate, run representative workloads to record branch frequencies and call counts, then recompile with -fprofile-use. The compiler inlines hot functions and reorganizes cold/hot paths — yielding 10–30% speedups on real programs.
What is false sharing and how do you fix it?	Two threads update different variables that share a 64-byte cache line. Every write by one core invalidates the line on the other, forcing a coherence roundtrip — performance collapses despite no logical sharing. Fix: pad or align per-thread hot variables to separate cache lines with alignas(64).
When does loop unrolling help vs hurt?	Unrolling reduces loop-overhead instructions and enables better scheduling. It hurts when the expanded body exceeds the I-cache window, causing instruction-cache misses. Profile before unrolling manually; compilers do it automatically at -O2/-O3.
What does perf stat measure and what are key counters to watch?	perf stat ./program reports task-clock (wall time), cache-misses (last-level cache), branch-misses (mispredictions), instructions, and cycles. Derived IPC (instructions per cycle) < 1 suggests cache-bound or misprediction-bound execution; near 3–4 suggests compute-bound.

# 4.11 Cross-Platform Data Models & Portability
What is the difference between LP64 and LLP64 data models?	LP64 (Linux/macOS 64-bit): int=32, long=64, pointer=64 bits. LLP64 (Windows 64-bit): int=32, long=32, long long=64, pointer=64 bits. The key: long is 32-bit on Windows but 64-bit on Linux/macOS. Use int64_t/intptr_t/size_t for portable 64-bit and pointer-sized values.
Why should you use %zu for size_t in printf?	size_t is unsigned and matches the address width (32 or 64 bits by platform). %u (32-bit unsigned) or %lu (64-bit unsigned long) produce wrong output or UB on platforms where they don't match. %zu is always correct for size_t.
Why does wchar_t size differ between platforms?	On Linux/macOS wchar_t is 32 bits (UTF-32, one code point per wchar_t). On Windows it is 16 bits (UTF-16, supplementary characters need surrogate pairs). Wide-character code assuming one wchar_t per code point is silently broken on Windows for characters outside the BMP.
What is the signedness pitfall of plain char?	char may be signed or unsigned depending on platform and compiler flags. On x86/GCC it is signed; on ARM or with -funsigned-char it is unsigned. Storing 0x80–0xFF in a char and passing it to is*() functions without casting to unsigned char causes sign-extended negative values — UB in the is* functions.
What are feature-test macros and where should you define them?	Macros like _POSIX_C_SOURCE 200809L or _GNU_SOURCE unlock extensions in system headers. Define them in source files before the first #include, or via -D compiler flags — not in headers, which would pollute all TUs that include that header.

# 4.12 C Interoperability — FFI & Embedding
How does Python ctypes call a C function in a shared library?	lib = ctypes.CDLL('libfoo.so') loads the library; lib.add.argtypes = [ctypes.c_int, ctypes.c_int]; lib.add.restype = ctypes.c_int; result = lib.add(3, 4). Setting argtypes and restype is critical — without them ctypes assumes int for everything, which is wrong for pointers and 64-bit types.
What is the difference between cffi ABI mode and API mode?	ABI mode: declare function signatures in Python and load the .so at runtime — no compilation, but type mismatches are runtime bugs. API mode: parse a real C header and compile a binding — mismatches are caught at binding-compile time and the binding runs faster. Prefer API mode for production.
How do you export a C function to Rust FFI?	In C: declare the function normally (with extern "C" if from C++). In Rust: extern "C" { fn my_func(x: i32) -> i32; } to import, marking calls as unsafe. To export Rust to C: #[no_mangle] pub extern "C" fn bar(x: i32) -> i32 { ... }. Use cbindgen to auto-generate the C header.
What is the biggest cgo performance pitfall?	Each cgo call crosses the Go/C boundary: Go must switch from a goroutine's small stack to an OS thread stack, pin the goroutine, and unwind back — ~60–200 ns per call vs nanoseconds for a plain Go call. Minimize cgo call frequency by batching work on the C side.
What is extern "C" and why does a C API exposed from C++ require it?	extern "C" prevents C++ name mangling for the enclosed declarations. Without it, C++ generates mangled symbol names (e.g. _Z7computei) that C callers and FFI layers cannot find. Any C API exposed from C++ must be wrapped in extern "C" { ... }.
What is a common ownership pitfall at FFI boundaries?	C allocates memory and returns a pointer; the caller in Python/Rust/Java doesn't know it must call free (or a destructor). The GC in the other language will not free C memory. Always document ownership and provide a companion _free function, or have the consuming side call the correct free from its FFI bindings.

# 4.13 Windows-Specific C
Why is INVALID_HANDLE_VALUE not the same as NULL?	INVALID_HANDLE_VALUE is (HANDLE)-1 (all bits set), used as the error sentinel by file-related APIs like CreateFile. Other APIs use NULL. Mixing them up means missing error checks. Always check against the value the specific API documents.
What is the difference between Win32 A and W API variants?	A variants (e.g. CreateFileA) accept ANSI/MBCS strings and convert internally. W variants (e.g. CreateFileW) take wchar_t* UTF-16 directly and are the real implementation. Always use W variants to correctly handle non-ASCII filenames and paths.
What is Windows SEH and how does it differ from C signals?	SEH (__try/__except/__finally) is a Windows kernel mechanism delivering hardware faults (access violation, divide-by-zero) as catchable exceptions in user mode. POSIX signals (SIGSEGV, SIGFPE) serve a similar role on Unix. They are incompatible — portable code cannot rely on either for fault recovery.
What does __declspec(dllexport) do and when do you need __declspec(dllimport)?	dllexport marks a symbol to be exported from a DLL. dllimport in the consuming header lets the compiler generate faster indirect calls via the import table. Standard pattern: #ifdef BUILDING_DLL #define API __declspec(dllexport) #else #define API __declspec(dllimport) #endif.
What is the /MD vs /MT CRT linking choice and why does it matter?	/MD links the CRT dynamically (smaller binary, shared heap). /MT links statically (no DLL dependency but larger binary). Mixing /MD and /MT modules gives each module its own heap — passing malloc'd pointers across module boundaries causes crashes when freed in the wrong heap.

# 4.14 ABI Compatibility in Practice
What changes to a C library break ABI?	Adding/removing/reordering struct members (changes sizeof and offsetof); changing a function's parameter types, return type, or calling convention; removing or renaming exported symbols; changing the width/sign of a public typedef. Any of these require a major .so version bump.
What changes to a C library are ABI-safe?	Adding new exported functions (old consumers don't call them); changing a function body without touching its signature; adding new fields at the end of a struct (safe only if consumers always use the library's headers to compute sizeof).
What is ELF symbol versioning and why is it useful?	Using a GNU ld version script you can export func@@LIBFOO_2.0 (for new consumers) and func@LIBFOO_1.0 (a compatibility alias for old consumers) in the same .so. Both groups link and get the correct implementation — the only way to change a function's behavior without breaking old binaries.
How do you audit a shared library's exported symbols?	nm -D libfoo.so, readelf -s --wide libfoo.so, or objdump -T libfoo.so show the dynamic symbol table. Use abidiff (libabigail) or abi-compliance-checker to compare two library versions and get a report of ABI-breaking changes.
What does __attribute__((visibility("hidden"))) do?	Marks a symbol hidden so it is not exported in the dynamic symbol table. This reduces the library's public ABI surface, speeds up dynamic linking (fewer relocations), and prevents consumers from accidentally depending on internal symbols that might change.

# 4.15 Sanitizer-Driven Development & Fuzzing in Depth
What does AddressSanitizer (-fsanitize=address) detect?	Heap buffer overflow, heap use-after-free, heap double-free, stack buffer overflow, global buffer overflow, use-after-return, use-after-scope, invalid free. Uses shadow memory to track byte validity. ~2x slowdown; combine with -fsanitize=undefined in CI.
What does UndefinedBehaviorSanitizer detect and at what cost?	Signed integer overflow, null pointer dereference, misaligned access, invalid shift, out-of-bounds array index (when size is statically known), invalid enum value. Very low overhead (~5–10%), suitable even for release-mode testing.
What does ThreadSanitizer detect and why can't it run with ASan?	TSan detects data races by tracking memory accesses and synchronization events. It uses a shadow-memory scheme incompatible with ASan's, so both cannot instrument the same binary. TSan has 5–15x overhead; run it in a dedicated CI job.
How do you write a libFuzzer harness?	Define int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) { /* call target with data */ return 0; } — no main function. Compile with -fsanitize=address,fuzzer. The fuzzer calls your function millions of times with coverage-guided mutations, stopping on any crash or sanitizer error.
What is structure-aware fuzzing and when is it valuable?	Standard byte mutation rarely produces syntactically valid inputs for parsers. Structure-aware fuzzing uses a grammar or schema (libprotobuf-mutator, custom LLVMFuzzerCustomMutator) to generate well-formed inputs. This pushes past surface-level validation into deep parser logic where most real bugs hide.

# 4.16 Debugging Deep Dive
How do you enable core dumps and load one in gdb?	Enable: ulimit -c unlimited or setrlimit(RLIMIT_CORE, ...) programmatically. On Linux, /proc/sys/kernel/core_pattern controls the path. Load: gdb ./program core — gdb restores the process image at the crash point so you can inspect registers, the stack, and memory.
What is a gdb watchpoint and when is it more useful than a breakpoint?	A watchpoint (watch var, rwatch var for reads, awatch for both) pauses execution whenever the watched variable is accessed or modified. It finds silent corruption without knowing where the write happens — you only need to know which variable was corrupted.
What is rr (record and replay) and what problem does it solve?	rr record ./program records a complete, reproducible execution trace. rr replay replays it deterministically with full gdb support and reverse-continue/reverse-next/reverse-finish. It solves heisenbugs — non-deterministic crashes that disappear under the debugger.
What does strace show, and how is it useful without source code?	strace ./program intercepts every system call and prints its arguments and return value — which files a program opens, what it writes to sockets, where it gets blocked, and what errors it receives. ltrace does the same for library function calls.
What does -Og do and why is it better for debugging than -O0?	-Og applies optimizations that don't significantly harm debuggability (no inlining, no register promotion hiding locals) while still generating idiomatic code faster than -O0. Variables are visible, line numbers are accurate, and test runs are practical.
How do conditional breakpoints reduce noise in gdb?	break file.c:42 if x > 1000 only pauses when the condition is true — the breakpoint fires once in a million hits instead of every iteration. Essential for finding the single bad iteration in a large loop without stepping through thousands of normal ones.
