# 4.1 Language Standards & Evolution
What are the major C standard revisions?	C89/C90 (ANSI C, the classic baseline), C99, C11, C17 (bug-fix only), and C23. Each adds features while staying largely backward compatible. Select one with `-std=c11` etc.; check `__STDC_VERSION__` at compile time.
Name key features introduced in C99.	`//` line comments, `inline` functions, variable-length arrays, designated initializers, `<stdint.h>` fixed-width types, `<stdbool.h>`, compound literals, `restrict`, mixed declarations and statements, and `long long`.
Name key features introduced in C11.	`_Static_assert`, `_Generic` type-generic selection, atomics (`<stdatomic.h>`), threads (`<threads.h>`), anonymous structs/unions, `_Alignas`/`_Alignof`, `_Noreturn`, optional bounds-checked functions (Annex K), and removal of `gets`.
What did C17 and C23 change?	C17 is a defect-fix release with no new language features. C23 adds `nullptr`, `constexpr`, `typeof`, `#embed`, makes `bool`/`true`/`false`/`static_assert` keywords, and adds binary literals, digit separators, `[[attributes]]`, and checked integer arithmetic.
What is the difference between a freestanding and a hosted implementation?	A hosted implementation provides the full standard library and starts at `main` under an OS. A freestanding implementation (kernels, bare-metal firmware) guarantees only a minimal header subset (`<stddef.h>`, `<stdint.h>`, `<limits.h>`, `<stdbool.h>`, etc.), no `malloc`/`stdio`, and may use a custom entry point.

# 4.2 Concurrency & the C Memory Model
What does "a data race is undefined behavior" mean in C?	If two threads access the same non-atomic object, at least one writing, without synchronization ordering them, the whole program's behavior is undefined — not just a wrong value. You must use mutexes or atomics to establish a happens-before relationship between the accesses.
What do acquire and release memory orders establish?	A release store publishes all prior writes; an acquire load that reads that store sees them. Together they create a synchronizes-with edge, so an acquire/release pair on a flag safely hands off data written before the release to the thread that acquires. `seq_cst` additionally gives a single global order.
What is false sharing?	When two threads modify different variables that happen to sit on the same cache line, the cache-coherence protocol bounces the line between cores, killing performance even though there is no logical sharing. Fix by padding/aligning hot per-thread data to separate cache lines.
What is the ABA problem in lock-free code?	A compare-and-swap sees a value change from A to B and back to A and wrongly concludes nothing happened, though the underlying state (e.g. a freed-and-reused node) changed. Mitigations include tagged pointers (version counters) and hazard pointers.

# 4.3 Embedded & Bare-Metal
Why must memory-mapped hardware registers be accessed through `volatile`?	A peripheral register can change independently of the program (status bits) and writes have side effects (triggering hardware). `volatile` forces the compiler to perform every read/write exactly as written, instead of caching the value in a register or eliding "redundant" accesses.
How do you set, clear, and toggle a bit in a hardware register?	Set: `REG |= (1u << n);` Clear: `REG &= ~(1u << n);` Toggle: `REG ^= (1u << n);` Test: `if (REG & (1u << n))`. On real registers `REG` is a `volatile` pointer/macro so the read-modify-write actually hits the hardware.
Why avoid dynamic allocation (`malloc`) in embedded/real-time systems?	The heap can fragment, `malloc` timing is non-deterministic (bad for hard real-time), and there is often no MMU or swap so an out-of-memory condition is fatal. Embedded code favors static allocation, fixed pools, and arenas with predictable, bounded behavior.
What are the `.text`, `.data`, `.bss`, and `.rodata` sections?	`.text` = executable code (often in flash/ROM); `.rodata` = read-only constants; `.data` = initialized read-write globals (copied from flash to RAM at startup); `.bss` = zero-initialized globals (just reserved RAM, zeroed by startup code). Linker scripts place these into the chip's memory map.
Why keep interrupt service routines (ISRs) short, and how do they share data?	An ISR preempts normal code, so long ISRs increase latency/jitter and can miss other interrupts. Do minimal work (set a flag, enqueue data) and defer processing to the main loop. Shared variables must be `volatile` (and accessed atomically or with interrupts briefly disabled) to be seen consistently.

# 4.4 Real-Time Operating Systems (RTOS)
What distinguishes a hard real-time system from a soft one?	Hard real-time: missing a deadline is a system failure (airbag, motor control) — correctness depends on timing guarantees. Soft real-time: deadlines are targets and occasional misses degrade quality but are tolerable (media playback). An RTOS prioritizes determinism over average throughput.
What are the typical states of an RTOS task?	Running (currently on the CPU), Ready (able to run, waiting for the scheduler), Blocked (waiting on a resource/event/delay), and Suspended (explicitly paused). The scheduler moves tasks between Ready and Running, usually by fixed priority with preemption.
What is priority inversion, and how is it solved?	A high-priority task is blocked waiting for a mutex held by a low-priority task, which is itself preempted by a medium-priority task — so the high task waits on the medium one indirectly. Fixes: priority inheritance (the low task temporarily inherits the high priority) or priority-ceiling protocols.
Why must you use the "…FromISR" API variants inside an ISR?	Regular blocking RTOS calls can suspend the caller, which is illegal in interrupt context. The `…FromISR` variants (e.g. FreeRTOS `xQueueSendFromISR`) are non-blocking, ISR-safe, and signal whether a higher-priority task was woken so the ISR can request a context switch on exit.
What is rate-monotonic scheduling (RMS)?	A fixed-priority scheme for periodic tasks where shorter-period tasks get higher priority. It is optimal among fixed-priority policies and schedulable if total CPU utilization stays under a bound (~69% for many tasks). EDF (earliest-deadline-first) is a dynamic alternative that can reach 100% utilization.
Name common RTOSes and a real-time Linux approach.	RTOSes: FreeRTOS, Zephyr, ThreadX/Azure RTOS, µC/OS, VxWorks, RTEMS, RT-Thread. For Linux, the `PREEMPT_RT` patch set plus `SCHED_FIFO`/`SCHED_RR` scheduling policies, `mlockall` (to avoid page-fault jitter), and CPU isolation/affinity provide bounded latency.
What does a basic FreeRTOS task and delay look like?	`xTaskCreate(vTask, "name", STACK_SZ, param, PRIORITY, &handle);` creates a task; inside it a loop uses `vTaskDelay(pdMS_TO_TICKS(100));` to sleep, or `vTaskDelayUntil` for precise periodic timing. Tasks communicate via queues (`xQueueSend`/`xQueueReceive`) and synchronize with semaphores (`xSemaphoreTake`/`Give`).

# 4.5 Linux / POSIX Systems Programming
What is the difference between a system call and a libc function?	A system call is a direct request to the kernel (e.g. `read`, `write`, `open`). A libc function may be a thin wrapper around one (`fopen` → `open`) or pure user space (`strlen`). Syscalls are more expensive (mode switch) and set `errno` on failure by returning −1.
What does "everything is a file" mean, and what is a file descriptor?	Files, pipes, sockets, and devices are all accessed through small integer handles called file descriptors returned by `open`/`socket`/etc. The same `read`/`write`/`close` calls work on all of them. `dup2` lets you redirect them (e.g. wire a pipe to `stdout`).
What is `mmap` used for?	Mapping a file or anonymous memory into the process address space. Uses: memory-mapped file I/O (access a file as an array), large/aligned anonymous allocations, and shared memory between processes (`MAP_SHARED`). `mprotect` changes page permissions (e.g. make a region read-only or executable).
Why use `epoll` over `select` for many connections?	`select`/`poll` scan the entire fd set on every call (O(n)) and `select` is capped by `FD_SETSIZE`. `epoll` (Linux) registers interest once and returns only the ready fds (O(ready)), scaling to tens of thousands of connections — the basis of high-performance servers.
What causes a zombie process, and how do you prevent it?	After a child exits, its exit status lingers until the parent reaps it; an unreaped child is a "zombie". Prevent it by calling `wait`/`waitpid` (or handling `SIGCHLD`) in the parent. Orphans (parent exits first) are re-parented to `init`, which reaps them.
What is `LD_PRELOAD`?	An environment variable that forces a shared library to load before all others, letting its symbols override later ones (function interposition). Used legitimately for profiling/mocking/allocator replacement, and maliciously to hijack calls — which is why setuid programs ignore it.

# 4.6 Toolchain, Debugging, Testing & Analysis
What do the `-O` optimization levels mean in gcc/clang?	`-O0` none (fast compile, best debugging), `-O1`/`-O2` progressively more optimization, `-O3` aggressive (may increase size), `-Os` optimize for size, `-Ofast` `-O3` plus non-standard-conforming math. Combine with `-g` for debug info. Higher levels can expose latent UB bugs.
What does AddressSanitizer (ASan) catch, and how is it used?	Compile and link with `-fsanitize=address`; at run time it detects heap/stack/global buffer overflows, use-after-free, use-after-return, and double-free, printing the offending location. You run your test suite under it. Pair with `-fsanitize=undefined` (UBSan) to catch signed overflow, bad shifts, misalignment.
When would you use a fuzzer like libFuzzer or AFL++?	To find memory-safety and logic bugs in code that parses untrusted input (file formats, network protocols). The fuzzer generates and mutates inputs, running them against your parser under sanitizers to surface crashes/hangs. You write a small harness taking a byte buffer.
What is the difference between static and dynamic analysis?	Static analysis (`clang-tidy`, `cppcheck`, Coverity, `scan-build`) inspects source without running it, flagging suspicious patterns and possible UB. Dynamic analysis (Valgrind, sanitizers) observes an actual run, catching real memory/UB errors on the paths exercised. They are complementary.

# 4.7 Compiler Extensions & Inline Assembly
What does GCC/Clang `__attribute__((packed))` do, and what is the risk?	It removes padding so a struct's members are laid out with no alignment gaps — useful for matching wire/hardware layouts. The risk: members may become unaligned, and taking a pointer to one (then dereferencing) can cause slow or faulting unaligned access on some architectures.
What is `__builtin_expect` used for?	Giving the compiler a branch-prediction hint: `if (__builtin_expect(err, 0))` tells it the error path is unlikely, so it lays out code with the common path fall-through. Usually wrapped as `likely()`/`unlikely()` macros. It affects code layout, not correctness.
How do you check for overflow using compiler builtins?	`__builtin_add_overflow(a, b, &result)` (and `_mul_`/`_sub_` variants) compute `a+b` into `result` and return `true` if it overflowed — a portable, efficient way to validate size arithmetic before allocating, without manual `INT_MAX` comparisons.

# 4.8 Custom Memory Management
What is an arena (region) allocator?	An allocator that hands out memory by bumping a pointer through a large pre-allocated block, with no per-object free — you free the whole arena at once. It is extremely fast and fragmentation-free, ideal when many objects share a lifetime (e.g. per-request or per-frame).
Why is `alloca` dangerous?	`alloca(n)` allocates on the stack and is auto-freed at function return, but it has no failure indication — a large or attacker-controlled `n` silently overflows the stack (crash or exploit), and its interaction with inlining/loops is tricky. Prefer a VLA with a bounded size or `malloc`.
What is an object pool / free list?	A pre-allocated set of fixed-size slots linked in a free list; allocation pops a slot and free pushes it back — both O(1) with no fragmentation. Ideal for frequently created/destroyed same-size objects (network buffers, particles) and for deterministic embedded/real-time allocation.

# 4.9 Secure Coding Standards & Hardening
What is the CERT C Secure Coding Standard?	A set of rules and recommendations for writing secure C, grouped by topic (INT integers, STR strings, MEM memory, FIO file I/O, ERR error handling, etc.), each describing a risky pattern and its compliant fix. Widely used as a checklist and for static-analysis rulesets.
What is MISRA-C and where is it used?	A coding standard for safety-critical and embedded systems (automotive, medical, aerospace) that restricts C to a safer subset: no (or controlled) dynamic memory, no recursion, no reliance on undefined/unspecified behavior, and strong typing rules — trading expressiveness for analyzability and determinism.
How do common C vulnerability classes map to CWE IDs?	CWE-119/787/125 = out-of-bounds write/read (buffer errors), CWE-416 = use-after-free, CWE-190 = integer overflow/wraparound, CWE-78 = OS command injection, CWE-134 = uncontrolled format string, CWE-476 = null pointer dereference. These dominate the CWE Top 25 for C programs.
What is the first step in threat-modeling a C program?	Identify the trust boundaries and attack surface: every place untrusted input enters (argv, files, network, environment, IPC). Then trace each input to its sinks (allocation sizes, indices, format strings, command strings, paths) and ensure validation happens before use. Mitigations layer on top of, not instead of, input validation.
What runtime mechanisms enforce least privilege on Linux?	`seccomp` filters restrict which system calls a process may make; Linux capabilities split root's powers into fine-grained bits you can drop; explicit privilege dropping (`setuid`/`setgid` to an unprivileged user after setup); and sandboxes/namespaces isolate the process. Combined, they limit the damage of a successful exploit.
