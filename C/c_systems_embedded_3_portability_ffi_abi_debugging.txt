# 4.11 Cross-Platform Data Models & Portability
What is the difference between LP64 and LLP64 data models?	LP64 (Linux/macOS 64-bit): int=32, long=64, pointer=64 bits. LLP64 (Windows 64-bit): int=32, long=32, long long=64, pointer=64 bits. The key: long is 32-bit on Windows but 64-bit on Linux/macOS. Use int64_t/intptr_t/size_t for portable 64-bit and pointer-sized values.
Why should you use %zu for size_t in printf?	size_t is unsigned and matches the address width (32 or 64 bits by platform). %u (32-bit unsigned) or %lu (64-bit unsigned long) produce wrong output or UB on platforms where they don't match. %zu is always correct for size_t.
Why does wchar_t size differ between platforms?	On Linux/macOS wchar_t is 32 bits (UTF-32, one code point per wchar_t). On Windows it is 16 bits (UTF-16, supplementary characters need surrogate pairs). Wide-character code assuming one wchar_t per code point is silently broken on Windows for characters outside the BMP.
What is the signedness pitfall of plain char?	char may be signed or unsigned depending on platform and compiler flags. On x86/GCC it is signed; on ARM or with -funsigned-char it is unsigned. Storing 0x80–0xFF in a char and passing it to is*() functions without casting to unsigned char causes sign-extended negative values — UB in the is* functions.
What are feature-test macros and where should you define them?	Macros like _POSIX_C_SOURCE 200809L or _GNU_SOURCE unlock extensions in system headers. Define them in source files before the first #include, or via -D compiler flags — not in headers, which would pollute all TUs that include that header.


# 4.12 C Interoperability — FFI & Embedding
How does Python ctypes call a C function in a shared library?	lib = ctypes.CDLL('libfoo.so') loads the library; lib.add.argtypes = [ctypes.c_int, ctypes.c_int]; lib.add.restype = ctypes.c_int; result = lib.add(3, 4). Setting argtypes and restype is critical — without them ctypes assumes int for everything, which is wrong for pointers and 64-bit types.
What is the difference between cffi ABI mode and API mode?	ABI mode: declare function signatures in Python and load the .so at runtime — no compilation, but type mismatches are runtime bugs. API mode: parse a real C header and compile a binding — mismatches are caught at binding-compile time and the binding runs faster. Prefer API mode for production.
How do you export a C function to Rust FFI?	In C: declare the function normally (with extern "C" if from C++). In Rust: extern "C" { fn my_func(x: i32) -> i32; } to import, marking calls as unsafe. To export Rust to C: #[no_mangle] pub extern "C" fn bar(x: i32) -> i32 { ... }. Use cbindgen to auto-generate the C header.
What is the biggest cgo performance pitfall?	Each cgo call crosses the Go/C boundary: Go must switch from a goroutine's small stack to an OS thread stack, pin the goroutine, and unwind back — ~60–200 ns per call vs nanoseconds for a plain Go call. Minimize cgo call frequency by batching work on the C side.
What is extern "C" and why does a C API exposed from C++ require it?	extern "C" prevents C++ name mangling for the enclosed declarations. Without it, C++ generates mangled symbol names (e.g. _Z7computei) that C callers and FFI layers cannot find. Any C API exposed from C++ must be wrapped in extern "C" { ... }.
What is a common ownership pitfall at FFI boundaries?	C allocates memory and returns a pointer; the caller in Python/Rust/Java doesn't know it must call free (or a destructor). The GC in the other language will not free C memory. Always document ownership and provide a companion _free function, or have the consuming side call the correct free from its FFI bindings.


# 4.13 Windows-Specific C
Why is INVALID_HANDLE_VALUE not the same as NULL?	INVALID_HANDLE_VALUE is (HANDLE)-1 (all bits set), used as the error sentinel by file-related APIs like CreateFile. Other APIs use NULL. Mixing them up means missing error checks. Always check against the value the specific API documents.
What is the difference between Win32 A and W API variants?	A variants (e.g. CreateFileA) accept ANSI/MBCS strings and convert internally. W variants (e.g. CreateFileW) take wchar_t* UTF-16 directly and are the real implementation. Always use W variants to correctly handle non-ASCII filenames and paths.
What is Windows SEH and how does it differ from C signals?	SEH (__try/__except/__finally) is a Windows kernel mechanism delivering hardware faults (access violation, divide-by-zero) as catchable exceptions in user mode. POSIX signals (SIGSEGV, SIGFPE) serve a similar role on Unix. They are incompatible — portable code cannot rely on either for fault recovery.
What does __declspec(dllexport) do and when do you need __declspec(dllimport)?	dllexport marks a symbol to be exported from a DLL. dllimport in the consuming header lets the compiler generate faster indirect calls via the import table. Standard pattern: #ifdef BUILDING_DLL #define API __declspec(dllexport) #else #define API __declspec(dllimport) #endif.
What is the /MD vs /MT CRT linking choice and why does it matter?	/MD links the CRT dynamically (smaller binary, shared heap). /MT links statically (no DLL dependency but larger binary). Mixing /MD and /MT modules gives each module its own heap — passing malloc'd pointers across module boundaries causes crashes when freed in the wrong heap.


# 4.14 ABI Compatibility in Practice
What changes to a C library break ABI?	Adding/removing/reordering struct members (changes sizeof and offsetof); changing a function's parameter types, return type, or calling convention; removing or renaming exported symbols; changing the width/sign of a public typedef. Any of these require a major .so version bump.
What changes to a C library are ABI-safe?	Adding new exported functions (old consumers don't call them); changing a function body without touching its signature; adding new fields at the end of a struct (safe only if consumers always use the library's headers to compute sizeof).
What is ELF symbol versioning and why is it useful?	Using a GNU ld version script you can export func@@LIBFOO_2.0 (for new consumers) and func@LIBFOO_1.0 (a compatibility alias for old consumers) in the same .so. Both groups link and get the correct implementation — the only way to change a function's behavior without breaking old binaries.
How do you audit a shared library's exported symbols?	nm -D libfoo.so, readelf -s --wide libfoo.so, or objdump -T libfoo.so show the dynamic symbol table. Use abidiff (libabigail) or abi-compliance-checker to compare two library versions and get a report of ABI-breaking changes.
What does __attribute__((visibility("hidden"))) do?	Marks a symbol hidden so it is not exported in the dynamic symbol table. This reduces the library's public ABI surface, speeds up dynamic linking (fewer relocations), and prevents consumers from accidentally depending on internal symbols that might change.


# 4.15 Sanitizer-Driven Development & Fuzzing in Depth
What does AddressSanitizer (-fsanitize=address) detect?	Heap buffer overflow, heap use-after-free, heap double-free, stack buffer overflow, global buffer overflow, use-after-return, use-after-scope, invalid free. Uses shadow memory to track byte validity. ~2x slowdown; combine with -fsanitize=undefined in CI.
What does UndefinedBehaviorSanitizer detect and at what cost?	Signed integer overflow, null pointer dereference, misaligned access, invalid shift, out-of-bounds array index (when size is statically known), invalid enum value. Very low overhead (~5–10%), suitable even for release-mode testing.
What does ThreadSanitizer detect and why can't it run with ASan?	TSan detects data races by tracking memory accesses and synchronization events. It uses a shadow-memory scheme incompatible with ASan's, so both cannot instrument the same binary. TSan has 5–15x overhead; run it in a dedicated CI job.
How do you write a libFuzzer harness?	Define int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) { /* call target with data */ return 0; } — no main function. Compile with -fsanitize=address,fuzzer. The fuzzer calls your function millions of times with coverage-guided mutations, stopping on any crash or sanitizer error.
What is structure-aware fuzzing and when is it valuable?	Standard byte mutation rarely produces syntactically valid inputs for parsers. Structure-aware fuzzing uses a grammar or schema (libprotobuf-mutator, custom LLVMFuzzerCustomMutator) to generate well-formed inputs. This pushes past surface-level validation into deep parser logic where most real bugs hide.


# 4.16 Debugging Deep Dive
How do you enable core dumps and load one in gdb?	Enable: ulimit -c unlimited or setrlimit(RLIMIT_CORE, ...) programmatically. On Linux, /proc/sys/kernel/core_pattern controls the path. Load: gdb ./program core — gdb restores the process image at the crash point so you can inspect registers, the stack, and memory.
What is a gdb watchpoint and when is it more useful than a breakpoint?	A watchpoint (watch var, rwatch var for reads, awatch for both) pauses execution whenever the watched variable is accessed or modified. It finds silent corruption without knowing where the write happens — you only need to know which variable was corrupted.
What is rr (record and replay) and what problem does it solve?	rr record ./program records a complete, reproducible execution trace. rr replay replays it deterministically with full gdb support and reverse-continue/reverse-next/reverse-finish. It solves heisenbugs — non-deterministic crashes that disappear under the debugger.
What does strace show, and how is it useful without source code?	strace ./program intercepts every system call and prints its arguments and return value — which files a program opens, what it writes to sockets, where it gets blocked, and what errors it receives. ltrace does the same for library function calls.
What does -Og do and why is it better for debugging than -O0?	-Og applies optimizations that don't significantly harm debuggability (no inlining, no register promotion hiding locals) while still generating idiomatic code faster than -O0. Variables are visible, line numbers are accurate, and test runs are practical.
How do conditional breakpoints reduce noise in gdb?	break file.c:42 if x > 1000 only pauses when the condition is true — the breakpoint fires once in a million hits instead of every iteration. Essential for finding the single bad iteration in a large loop without stepping through thousands of normal ones.
