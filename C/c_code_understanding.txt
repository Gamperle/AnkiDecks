# 1.1 Variables, Types & Expressions
What are C's primitive integer and floating types?	Integers: `char`, `short`, `int`, `long`, `long long`, each `signed` or `unsigned`. Floats: `float`, `double`, `long double`. The standard fixes only minimum widths (e.g. `int` ≥ 16 bits, `long` ≥ 32, `long long` ≥ 64); exact sizes are platform-dependent.
What does `unsigned` change about an integer type?	It removes the sign bit, so the type holds only non-negative values but twice the positive range (e.g. `unsigned char` is 0–255 vs `signed char` −128–127). Unsigned arithmetic wraps modulo 2^N and never overflows in the UB sense.
What are the "usual arithmetic conversions" / integer promotions?	Before most binary operators, operands narrower than `int` are promoted to `int` (or `unsigned int`), then both operands are converted to a common type. This is why `char a=200,b=100; a+b` is computed in `int` and does not overflow at char width.
What is the difference between signed and unsigned overflow behavior?	Unsigned overflow is defined: it wraps modulo 2^N. Signed overflow is undefined behavior — the compiler may assume it never happens and optimize on that basis. So `INT_MAX+1` is UB but `UINT_MAX+1u` is defined as 0.
Why can mixing `int` and `unsigned int` in one expression be a pitfall?	The signed operand is converted to unsigned, so a negative value becomes a huge positive one. `-1 < 0u` is false because `-1` becomes `UINT_MAX`. Comparisons and arithmetic mixing signedness are a classic bug source.
What does the `sizeof` operator give, and why does it vary by platform?	`sizeof x` yields the size of `x` in bytes as a `size_t`. Because `int`/`long`/pointer widths differ across platforms and ABIs, `sizeof(long)` may be 4 or 8. Use `<stdint.h>` fixed-width types when an exact size is required.
What are the fixed-width types in `<stdint.h>` for?	Types like `int32_t`, `uint8_t`, `int64_t` guarantee an exact width and signedness on every platform, unlike `int`/`long`. Use them for file formats, network protocols, hardware registers, and any code where representation must be portable.
What is the difference between `#define`, `const`, and `enum` constants?	`#define N 10` is an untyped, unscoped text macro. `const int n = 10;` is a typed, scoped variable (may take storage, has an address). `enum { N = 10 };` is a scoped named `int` constant with no storage. Prefer `const`/`enum` for typed constants.
What does `typedef` do, and what is a downside of typedef'ing pointers?	It creates an alias for an existing type (`typedef unsigned long ulong;`) — not a new distinct type. Hiding a pointer behind a typedef (`typedef struct S *Handle;`) can improve encapsulation but obscures that the value is a pointer, hurting `const`-correctness and readability.
What do integer and floating-point literal suffixes mean?	Integer suffixes set the type: `u`(unsigned), `l`(long), `ul`, `ll`(long long). Bases: `0x` hex, leading `0` octal (`010`==8!), `0b` binary (GNU/C23). Float suffixes: `f`(float), `l`(long double); no suffix is `double`.
What is the difference between `'a'` and `"a"`?	`'a'` is a character constant of type `int` in C (value 97), a single value. `"a"` is a string literal: a `char[2]` array holding `'a'` and a terminating `'\0'`. They are not interchangeable.
What is a compound literal?	An unnamed object created inline as `(type){ initializers }`, e.g. `(int[]){1,2,3}` or `(struct Point){.x=1}`. It has automatic (block) storage duration unless at file scope, and can be passed directly to a function expecting that type.
What is the difference between an lvalue and an rvalue?	An lvalue names an object with a location and can appear on the left of `=` (a variable, `*p`, `arr[i]`). An rvalue is just a value (`3`, `a+b`) and cannot be assigned to; `a+b = 5;` is an error.
Why is `if (x = 0)` almost always a bug?	`=` assigns, so `x = 0` sets `x` to 0 and evaluates to 0 (false) — the branch never runs and `x` is clobbered. The intended `if (x == 0)` compares. "Yoda" style `if (0 == x)` turns the typo into a compile error.
How does short-circuit evaluation of `&&` and `||` work?	`&&` stops and yields 0 at the first false operand; `||` stops and yields 1 at the first true operand. The right side is not evaluated if the result is already known, enabling guards like `if (p && p->x)`.
What is the difference between the comma operator and a comma separator?	The comma *operator* evaluates its left operand, discards it, and yields the right (`a = (b, c)` assigns `c`). A comma *separator* between function arguments or declarators is not the operator — `f(a, b)` passes two arguments, it does not sequence them.
What is the type of a ternary expression `cond ? a : b`?	The common type of `a` and `b` after the usual conversions, regardless of which branch runs. A common misuse: `cond ? 1 : "x"` mixes incompatible types, and mixing signed/unsigned or int/double in the two arms silently converts the result.
What is the difference between `*p++` and `(*p)++`?	`*p++` is `*(p++)`: dereference `p`, then increment the pointer `p`. `(*p)++` dereferences `p` and increments the pointed-to value, leaving `p` unchanged. The precedence of postfix `++` over unary `*` is the reason.
Why does `a & b == c` not do what it looks like?	`==` has higher precedence than `&`, so it parses as `a & (b == c)`. To test bits you must write `(a & b) == c`. Bitwise operators binding looser than comparison is one of C's most notorious precedence traps.
How do you set, clear, toggle, and test a single bit?	Set: `x |= (1u << n)`. Clear: `x &= ~(1u << n)`. Toggle: `x ^= (1u << n)`. Test: `if (x & (1u << n))`. The bitwise operators are `&` AND, `|` OR, `^` XOR, `~` NOT, `<<`/`>>` shifts.
Is `sizeof` evaluated at compile time or run time, and is its operand executed?	Compile time for everything except variable-length arrays (whose size is computed at run time). The operand is not evaluated: `sizeof(i++)` yields the size and does not increment `i`.

# 1.2 Storage Classes, Scope & Lifetime
What are C's storage-class specifiers?	`auto` (default for locals, automatic storage), `register` (hint, address cannot be taken), `static` (static storage / internal linkage), `extern` (declaration referring to a definition elsewhere), and `_Thread_local` (one instance per thread).
What is the difference between block, file, and function-prototype scope?	Block scope: visible inside the enclosing `{}` (locals). File scope: visible from declaration to end of the translation unit (globals). Function-prototype scope: parameter names in a prototype, visible only within that declaration.
What are the four storage durations in C?	Automatic (locals — exist during their block), static (whole program run), thread (whole life of a thread, C11 `_Thread_local`), and allocated (from `malloc` until `free`). Duration is about lifetime, distinct from scope (visibility).
What does `static` on a local variable do?	It gives the variable static storage duration: a single instance, initialized once (to zero if no initializer), that retains its value across calls. `int next(void){ static int n=0; return ++n; }` returns 1, 2, 3, ….
What is the difference between `static` and `extern` at file scope?	`static` gives internal linkage — the name is private to its translation unit. `extern` declares a name defined in another translation unit (external linkage), letting you reference a shared global/function without redefining it.
Are uninitialized variables zeroed in C?	Only objects with static or thread storage duration (globals, `static` locals) are zero-initialized. Automatic (local) variables are not — they contain indeterminate garbage, and reading them is undefined behavior.
How can a variable's lifetime differ from its scope?	A `static` local is in scope only inside its block (you can only name it there) but has a lifetime spanning the whole program run. So it keeps its value between calls even though it is not visible elsewhere.
What does the `register` storage class do today?	It is a hint that a variable is used heavily; modern optimizing compilers ignore it for register allocation. Its one remaining semantic effect: you may not take the address (`&`) of a `register` variable.

# 1.3 Pointers & Memory
Are `int *p`, `int* p`, and `int * p` different declarations?	No — whitespace is irrelevant; all three declare a pointer to `int`. Beware `int* a, b;`: only `a` is a pointer, `b` is a plain `int`, because `*` binds to the declarator, not the type.
How far does `p + 1` move a pointer?	By `sizeof(*p)` bytes — one element of the pointed-to type, not one byte. For `int *p` with 4-byte ints, `p + 1` is 4 bytes further. All pointer arithmetic is in units of the element type.
What happens when you dereference a `NULL` pointer?	Undefined behavior. In practice it usually faults (crash), but the standard guarantees nothing and the optimizer may assume it cannot happen. Always check pointers that might be null before dereferencing.
What is a pointer to a pointer used for?	`int **pp` holds the address of a pointer. Uses: output parameters that must modify the caller's pointer (`bool alloc(int **out)`), arrays of pointers (`char *argv[]`, i.e. `char **`), and mutating linked structures.
Explain `const int *p` vs `int * const p` vs `const int * const p`.	`const int *p`: pointer to const int — cannot change `*p`, can repoint `p`. `int * const p`: const pointer to int — can change `*p`, cannot repoint. `const int * const p`: neither changeable. Read right-to-left.
What is array-to-pointer decay?	In most expressions an array name is implicitly converted to a pointer to its first element (`arr` → `&arr[0]`). This is why a parameter `int a[]` is really `int *a`. Exceptions: operands of `sizeof`, `&`, and string-literal initialization.
Is there any difference between `array[i]`, `*(array + i)`, and `i[array]`?	No — `array[i]` is defined as `*(array + i)`, and since addition commutes, `i[array]` is equivalent (though obscure). `array[i]` is the conventional readable form.
What is the difference between stack and heap allocation?	Stack: automatic variables, allocated/freed automatically as functions enter/exit, fast, limited size. Heap: `malloc`/`free`, manually managed, larger, lives until explicitly freed. Forgetting to `free` heap memory leaks it; using stack memory after return dangles.
What is a dangling pointer?	A pointer to memory that is no longer valid — after `free(p)`, or a pointer to a local variable whose function has returned. Dereferencing it is undefined behavior. Setting freed pointers to `NULL` makes accidental reuse fail loudly.
What is a memory leak?	Heap memory that was allocated but never freed and is no longer reachable, so it cannot be reclaimed while the program runs. Repeated leaks exhaust memory. Every `malloc` needs a matching `free` on all paths.
Why must a `void *` be converted before dereferencing?	`void *` has no element type, so it has no size for arithmetic or dereference. Convert it to a concrete pointer first: `int *ip = vp; *ip = 5;`. The conversion is implicit in C, but requires a cast in C++.
Is an uninitialized pointer the same as a NULL pointer?	No. `int *p;` holds indeterminate garbage; dereferencing is UB and may not crash. Only `int *p = NULL;` is guaranteed null. Initialize pointers to `NULL` when you cannot give them a valid target immediately.
What is the difference between pointer identity and the objects pointed to?	Two pointers can be equal (same address, same object) or unequal yet point to equal *values*. `p == q` compares addresses; comparing what they point at needs dereferencing (`*p == *q`) or `strcmp`/`memcmp` for aggregates.

# 1.4 Arrays & Strings
How are partially-initialized arrays filled?	Elements you do not explicitly initialize are zero-initialized. `int a[5] = {1,2};` gives `{1,2,0,0,0}`; `int a[100] = {0};` zeroes the whole array.
What are designated array initializers?	Initializing specific elements by index: `int a[10] = {[0]=1, [9]=5};` sets those two and zeroes the rest. Order-independent and useful for sparse or lookup-table arrays.
How is a 2D array `int m[3][4]` laid out in memory?	Row-major: all of row 0's four ints, then row 1's, then row 2's — contiguous. `m[i][j]` is at offset `i*4 + j` ints. Iterating with the last index innermost is cache-friendly.
What is the difference between `char *argv[]` and `char (*p)[N]`?	`char *argv[]` is an array of pointers to char (each element a separate string). `char (*p)[N]` is a pointer to an array of N chars (one contiguous block). The parentheses change binding entirely.
What is a variable-length array (VLA), and what is its risk?	An array whose size is a runtime value: `void f(int n){ int a[n]; }` (C99; optional since C11). It lives on the stack, so a large or attacker-controlled `n` can overflow the stack. Prefer `malloc` for big or untrusted sizes.
Why do C strings need a `\0` terminator?	C tracks no separate length; functions like `strlen`, `printf %s`, and `strcpy` scan until they hit the `\0` byte. A missing terminator makes them read past the buffer — a common crash and security bug.
Where are string literals stored, and can they be shared?	In read-only (static) memory; identical literals may be pooled to the same address. Writing through `char *s = "hi"; s[0]='H';` is undefined behavior. Use `const char *` for literals so writes are caught at compile time.
What is the difference between `char buf[] = "hi";` and `char *p = "hi";`?	`char buf[]` creates a modifiable local array (3 bytes here) that you own and can write. `char *p` points at a read-only literal; writing through it is UB. Use the array form when you need a mutable string.
What happens to an array's size information when passed to a function?	The array decays to a pointer, so the parameter is a pointer and the size is lost. You must pass the length separately (`void f(int *a, size_t n)`); `sizeof` inside the function gives the pointer size, not the array's.
When does `sizeof` give the array size vs the pointer size?	It gives the true byte size only where the array is a real array in scope (`int a[10]; sizeof a` == 40). Once the array has decayed to a pointer (e.g. a function parameter), `sizeof` gives the pointer's size instead.
What does `argv[argc]` equal in `main`?	It is guaranteed to be a `NULL` pointer. `argv` holds `argc` string pointers followed by a null terminator, so you can loop with an index up to `argc` or walk until you reach `NULL`.
Why does iteration order matter for `arr[i][j]` vs `arr[j][i]`?	Because 2D arrays are row-major, walking with the last index fastest (`arr[i][j]` inner loop over `j`) touches contiguous memory and is cache-friendly; swapping to `arr[j][i]` strides across rows, causing cache misses and slower loops.
How are wide characters and UTF-8 handled in C?	`wchar_t` and `L"..."` literals with `<wchar.h>` provide wide characters (width is platform-dependent). UTF-8 text is just bytes and is stored in ordinary `char[]`; multibyte handling needs care, but no special type is required for storage.

# 1.5 Control Flow & Functions
When should you use `for`, `while`, or `do-while`?	`for` when the iteration count/step is known up front (counting loops). `while` when you loop until a condition and may run zero times. `do-while` when the body must run at least once before the condition is tested (e.g. input-then-validate).
What is the difference between `break` and `continue` in nested loops?	`break` exits the innermost enclosing loop/`switch`; `continue` skips to the next iteration of the innermost loop. Neither affects outer loops — to break out of nested loops use a flag or `goto`.
What is switch fall-through, and when is it a bug?	Without `break`, execution falls into the next `case`. Intentional when labels share code (`case 1: case 2: do_x();`); a bug when a missing `break` runs the following case unintentionally. C23's `[[fallthrough]]` documents the deliberate case.
Distinguish a function declaration, definition, and prototype.	A declaration introduces the name and type so it can be called. A definition also supplies the body. A prototype is a declaration specifying parameter types (`int f(int, char*);`), letting the compiler type-check calls.
What is the difference between `f()` and `f(void)`?	`f(void)` explicitly declares no parameters. `f()` (empty parens) is the legacy "unspecified arguments" form — the compiler will not check the call's arguments. Always use `(void)` for no-argument functions in C.
What does "C passes arguments by value" mean?	The function receives copies of the argument values; assigning to a parameter does not affect the caller. To modify a caller's variable, pass its address (a pointer) and write through it: `void inc(int *p){ (*p)++; }`.
Why is returning a pointer to a local variable a bug?	The local's lifetime ends at return, so the returned pointer dangles into reclaimed stack space (UB). `int *f(void){ int x=5; return &x; }` is broken. Return by value, use `static`, or allocate with `malloc` instead.
What is the risk of deep or unbounded recursion?	Each call consumes a stack frame; too many nested calls exhaust the stack and cause a stack overflow (crash). Recursion depth driven by untrusted input is a denial-of-service risk. Ensure a bounded base case or convert to iteration.
How do `static` local variables behave across calls?	They are initialized once (before first use, to zero by default) and retain their value between calls, since they have static storage duration but block scope. Useful for counters and caches, but not thread-safe without synchronization.
How does a variadic function read its arguments?	Via `<stdarg.h>`: `va_list ap; va_start(ap, last);` (last = the final named parameter), then `va_arg(ap, type)` per argument, and `va_end(ap)`. There is no built-in count, so a format string or explicit count says how many/what types.
What are the default argument promotions for variadic calls?	Arguments passed through `...` are promoted: `float`→`double`, and integer types narrower than `int`→`int`/`unsigned`. So you must `va_arg(ap, int)` for a char/short and `va_arg(ap, double)` for a float; using the narrow type is UB.
How do function-like macros differ from real functions in evaluation?	A macro is textual substitution, so it may evaluate its arguments zero or multiple times (side effects repeat) and has no type checking. A function evaluates each argument exactly once and is type-checked. Prefer `inline` functions when semantics matter.
When is `goto` a reasonable choice in C?	For centralized cleanup on error paths (`goto cleanup;` to free resources and return) and for breaking out of nested loops. Both keep the happy path flat. Avoid uncontrolled `goto` that produces tangled control flow.
What are `_Noreturn` / `noreturn` functions?	Functions declared not to return to the caller — e.g. wrappers around `exit`, `abort`, or `longjmp`. The `_Noreturn` (C11) / `[[noreturn]]` marker lets the compiler optimize and warn if such a function ever falls through to a return.

# 1.6 Structs, Unions & Enums
How do you access struct members with `.` and `->`?	Use `.` on a struct value (`p.x`) and `->` on a pointer to a struct (`ptr->x`), which is shorthand for `(*ptr).x`. Mixing them up is a common compile error.
Why can `sizeof(struct)` exceed the sum of its members?	The compiler inserts padding so each member meets its alignment requirement (e.g. an `int` on a 4-byte boundary), and pads the whole struct to its largest alignment. `struct{char c; int i;}` is often 8 bytes, not 5.
How does reordering struct members reduce size?	Grouping members largest-to-smallest minimizes the padding inserted for alignment. `struct{char a; int b; char c;}` may be 12 bytes, while `struct{int b; char a; char c;}` is 8 — same data, less padding.
What are designated initializers for structs?	Initializing members by name: `struct Point p = {.y=2, .x=1};`. It is order-independent, self-documenting, and zeroes any members you omit — safer than positional initialization when the struct changes.
How does a `union` differ from a `struct`?	All union members share the same storage and the union is only as large as its biggest member; only one member is "active" at a time. A struct gives each member its own storage. Writing one union member and reading another is type-punning.
What is the `typedef struct` pattern, and what are anonymous structs/unions?	`typedef struct Point { int x, y; } Point;` lets you write `Point p;` without the `struct` keyword. An anonymous struct/union (no name, e.g. nested inside another struct) exposes its members directly to the enclosing type.
How do `enum` constant values work?	Enumerators start at 0 and increment by 1 unless assigned: `enum {A, B, C=10, D};` gives A=0,B=1,C=10,D=11. They are of type `int`. The enum's underlying type is implementation-defined but must hold all its values.
What is a scoping caveat when using `enum` for flags/state machines?	Enum constants are placed in the enclosing scope (not namespaced under the enum name), so two enums with a shared constant name clash. Prefix names (`COLOR_RED`) to avoid collisions. Enums are ideal for readable state/flag values.
What is a bit field?	A struct member with an explicit bit width: `struct{unsigned flag:1; unsigned mode:3;};`, packing small values into fewer bits. Layout, ordering, and straddling are implementation-defined, so bit fields are not portable for wire formats.
What is the opaque pointer / forward declaration pattern?	A header declares `typedef struct Widget Widget;` and functions taking `Widget *`, without exposing the struct's members; the full definition lives in the `.c` file. Callers can hold the pointer but not depend on the layout — clean encapsulation and ABI stability.
How do self-referential structs work?	A struct contains a pointer to its own type: `struct Node { int v; struct Node *next; };`. A struct cannot contain itself by value (infinite size), but it can contain a pointer to itself — the basis of linked lists and trees.
How do you initialize nested structs and arrays of structs?	With nested braces or designators: `struct Line l = {.a={.x=0,.y=0}, .b={.x=1,.y=1}};` or `struct Point pts[] = {{0,0},{1,2},{3,4}};`. Omitted members are zero-initialized.
What does `offsetof(type, member)` return?	The byte offset of `member` within `type`, from `<stddef.h>`. It underlies the "container_of" idiom (recover the enclosing struct from a member pointer), serialization, and hardware register-map definitions.

# 1.7 Pointers — Advanced Patterns
How do you declare and call a function pointer?	`int (*fp)(int,int) = add;` (the `&` on the function is optional). Call with `fp(2,3)` or `(*fp)(2,3)`. The parentheses around `*fp` are required; without them `int *fp(int,int)` declares a function returning `int*`.
What is an array of function pointers used for?	A dispatch table: `void (*ops[])(void) = {start, stop, reset};` lets you call `ops[i]()` to pick behavior by index — a compact alternative to a `switch` and the basis for hand-rolled vtables and state machines.
What is the difference between `int (*p)[5]` and `int *p`?	`int (*p)[5]` is a pointer to an array of 5 ints — `p+1` moves 5 ints forward, and it is what `&arr` yields for `int arr[5]`. `int *p` is a pointer to a single int. The parentheses bind `*` before `[5]`.
What does the `restrict` keyword promise?	That, for the pointer's lifetime, the pointed-to object is accessed only through that pointer (no aliasing), letting the compiler skip reloads and optimize (e.g. `memcpy`'s parameters). Violating it with overlapping regions is undefined behavior.
What does `volatile` tell the compiler?	That the object may change outside the program's visible control (hardware register, signal handler, another thread), so every read/write in the source must actually be performed and not cached in a register. It is not a thread-synchronization primitive.
What is the strict aliasing rule?	An object may generally be accessed only through an lvalue of its own type (or `char`). Reading an `int` through a `float*` is UB even if the bits align. To reinterpret bytes portably use `memcpy` or a `union`, not a pointer cast.
When must you use `memmove` instead of `memcpy`?	When the source and destination overlap. `memcpy` has undefined behavior on overlap (it may copy in any order); `memmove` handles overlap correctly, as if copying through a temporary. Use it when shifting elements within one array.
What is a flexible array member?	A final struct member with empty brackets: `struct Buf { size_t len; char data[]; };`. You allocate `malloc(sizeof(struct Buf) + n)` so `data` occupies the trailing bytes, keeping a header and its variable-length payload in one allocation.
What is the opaque-handle / PIMPL pattern in C?	A library exposes only a forward-declared type and functions on a pointer to it (`typedef struct Ctx Ctx; Ctx *ctx_new(void);`), hiding the implementation struct in the `.c` file. Callers cannot see or depend on internals, giving encapsulation and ABI stability.
Why use a double pointer for an output parameter?	To let a function set the caller's pointer, e.g. allocate and return a buffer: `bool make(int **out){ *out = malloc(...); return *out != NULL; }`. Passing `int *` would only copy the pointer; you need `int **` to modify it.
What is a pointer-to-const-pointer used for in APIs?	Read-only iteration/interfaces: `const char *const *names` lets a function read an array of strings without modifying either the pointers or the strings, documenting and enforcing that it will not mutate the caller's data.
How do callback APIs pass context with a function pointer?	They accept a `void *user_data` alongside the callback and pass it back on each call: `void each(void (*cb)(int, void*), void *ud)`. The callback casts `user_data` to its real type, letting closures/state ride along without globals.

# 1.8 Undefined, Unspecified & Implementation-Defined Behavior
What is the difference between undefined, unspecified, and implementation-defined behavior?	Undefined (UB): no requirements at all — anything may happen. Unspecified: the implementation picks among valid options and need not document it (e.g. argument evaluation order). Implementation-defined: a documented choice (e.g. whether `char` is signed).
Why is reading an uninitialized variable undefined behavior?	Its value is indeterminate, and for some types the bit pattern may be a trap representation; the standard places no constraints on using it. The optimizer may even assume the read cannot happen, producing surprising results. Always initialize before use.
Contrast signed overflow with unsigned wraparound.	Signed integer overflow is UB (not guaranteed to wrap; the optimizer assumes it never occurs). Unsigned arithmetic is defined to wrap modulo 2^N. So `INT_MAX+1` is UB, while `UINT_MAX+1u` is defined as 0.
Why is out-of-bounds array access undefined behavior?	Indexing outside `[0, N-1]` (except one-past-the-end for pointer comparison) accesses memory the object does not own — reads may leak data or crash, writes may corrupt other variables, and the optimizer may assume it never happens.
Why is `printf("%d", (size_t)x)` undefined behavior?	The conversion specifier must match the argument type. `%d` expects `int`; passing a `size_t`/`unsigned` mismatches the type the way `printf` reads its varargs — UB, and it prints wrong values on platforms where the widths differ. Use `%zu` for `size_t`.
Why is modifying a string literal undefined behavior?	Literals live in read-only memory and may be shared. `char *s = "hi"; s[0]='H';` writes there — UB, often a crash. Use `char s[] = "hi";` for a writable copy.
Why are `i++ + i++` and `a[i] = i++` undefined behavior?	They modify `i` more than once (or modify and separately read it) with no sequence point ordering the operations, so the standard makes the result undefined — not merely unspecified. Split into separate statements.
Is the evaluation order of function arguments defined?	No — it is unspecified. In `f(g(), h())` either call may run first, and it can vary by compiler or call site. Never rely on side-effect ordering across arguments, e.g. `f(x++, x++)`.
When is comparing two pointers with `<` valid?	Only when they point into the same array object (or one past its end). Ordering pointers to unrelated objects with `<`/`>` is undefined behavior. Equality (`==`/`!=`) comparison is always well-defined.
What is the `setjmp`/`longjmp` pitfall with local variables?	Non-`volatile` locals that are modified between `setjmp` and a `longjmp` back have indeterminate values after the jump (the compiler may have kept them in registers). Mark such locals `volatile` if you rely on them after the jump.
What is a strict-aliasing violation via type punning?	Accessing an object through a pointer of an unrelated type — e.g. `float f; int i = *(int*)&f;`. It breaks the compiler's aliasing assumptions (UB) and can miscompile under optimization. Use `memcpy` or a `union` to reinterpret bytes.
What are the edge cases of null pointer arithmetic and comparison?	Adding a nonzero offset to a null pointer, or dereferencing it, is UB; only `NULL == NULL` and comparing a null pointer for equality are well-defined. Do not compute `NULL + 0` semantics or order null pointers with `<`.
Why is calling a function through an incompatible function-pointer type UB?	If the pointer's declared signature differs from the function's actual type, the call is undefined even if it "happens to work" on your ABI. Argument passing/return may be interpreted wrongly. Cast pointers only when the signatures genuinely match.
What happens if a non-`void` function reaches its end without `return`?	Falling off the end is allowed, but if the caller *uses* the returned value, the behavior is undefined (the value is indeterminate). Always `return` a value on every path of a value-returning function.
Why are multiple unsequenced side effects on one object UB?	Because the standard leaves the order (and even whether they conflict) unspecified/undefined when there is no sequence point between them. `x = x++ + 1;` both assigns and increments `x` unsequenced — UB. Keep at most one modification of an object per full expression.
Give examples of implementation-defined behavior.	Whether plain `char` is signed or unsigned, the result of right-shifting a negative value (arithmetic vs logical), the sizes of `int`/`long`, and integer representation details. These are documented per compiler/platform but vary, so portable code must not assume one choice.

# 1.9 Preprocessor & Compilation
What is the difference between `#include` guards and `#pragma once`?	Both stop a header being processed twice in one translation unit. Include guards (`#ifndef X_H / #define X_H / … / #endif`) are standard and fully portable. `#pragma once` is a widely-supported non-standard one-liner. Guards are the safest choice.
Why must macro parameters be parenthesized?	Because macros substitute text, unparenthesized parameters inherit surrounding precedence. `#define SQ(x) x*x` makes `SQ(a+1)` expand to `a+1*a+1`. Write `#define SQ(x) ((x)*(x))` — parenthesize each parameter and the whole body.
What is the double-evaluation macro pitfall?	A macro using an argument more than once repeats its side effects. `#define MAX(a,b) ((a)>(b)?(a):(b))` with `MAX(i++, j++)` increments one of them twice. Prefer an inline function, which evaluates each argument once.
What do `#ifdef`, `#ifndef`, and `#if defined(...)` do?	They conditionally include code based on whether a macro is defined. `#ifdef X` / `#ifndef X` test one macro; `#if defined(X) && !defined(Y)` allows compound conditions. Used for platform/feature selection and include guards.
Name key standard predefined macros.	`__FILE__` (source file name), `__LINE__` (current line), `__func__` (function name, C99), `__DATE__` / `__TIME__` (compile date/time), and `__STDC_VERSION__` (C standard version, e.g. `201710L`). Common in logging and assertion macros.
What does `static` at file scope do to linkage?	It gives the function or variable internal linkage — visible only within its translation unit and not linkable from other `.c` files. It is C's way to make a module-private helper or global.
What does the `extern` keyword declare?	That a name (variable or function) is defined elsewhere, with external linkage — a declaration without a definition. You put `extern int g;` in a header and define `int g;` once in a single `.c` file.
What are the phases of the C compilation pipeline?	Preprocessing (handle `#include`/`#define`/conditionals) → compilation (source to assembly) → assembly (to object code) → linking (combine objects and libraries, resolve symbols, into an executable). `gcc -E`, `-S`, `-c` stop after each early phase.
How do `inline` functions differ from function-like macros?	An `inline` function is a real function (type-checked, single argument evaluation, has an address) that the compiler may expand in place. A macro is textual substitution with no type checking and possible repeated evaluation. Prefer `inline` for correctness.
What do the `##` and `#` preprocessor operators do?	`#x` stringizes an argument: `#define STR(x) #x` makes `STR(hi)`→`"hi"`. `a##b` pastes tokens: `#define CAT(a,b) a##b` makes `CAT(foo,bar)`→`foobar`. Used to generate identifiers and debug/log macros.
What is a variadic macro?	A macro taking a variable number of arguments via `...`, captured by `__VA_ARGS__`: `#define LOG(fmt, ...) fprintf(stderr, fmt, __VA_ARGS__)`. C23/GNU add `__VA_OPT__` to handle the zero-argument case cleanly.
What do the `#error` and `#pragma` directives do?	`#error msg` aborts compilation with a message (used to catch unsupported configurations). `#pragma` issues an implementation-specific instruction to the compiler (e.g. `#pragma once`, `#pragma pack`, `#pragma GCC diagnostic`).
How is conditional compilation used for platform/feature detection?	Predefined/feature macros gate code: `#if defined(_WIN32)` … `#elif defined(__linux__)` …, or feature-test macros like `_POSIX_C_SOURCE`. This lets one source tree compile correctly across platforms and library versions.

# 1.10 Multi-File Programs, Linkage & Build
Where do declarations vs definitions belong in a multi-file program?	Declarations (prototypes, `extern` variable declarations, type/macro definitions) go in header (`.h`) files included where needed. Definitions (function bodies, the single definition of each global) go in exactly one `.c` file — declare in many places, define once.
What are the three kinds of linkage in C?	External linkage (default for file-scope functions/variables): visible across translation units. Internal linkage (`static` at file scope): visible only within one file. No linkage (locals, parameters, typedefs): each declaration is its own entity.
What is C's "one definition" rule for objects and functions?	Each function or object with external linkage may be *defined* in exactly one translation unit across the whole program, though it may be *declared* in many. Multiple definitions cause a linker "duplicate symbol" error.
How do you share a global variable across files?	Declare it `extern` in a header (`extern int g;`) that all users include, and provide exactly one definition (`int g = 0;`) in a single `.c` file. The `extern` declaration says "defined elsewhere"; the lone definition allocates it.
What is a tentative definition / common symbol?	A file-scope declaration like `int g;` with no initializer is a "tentative definition"; if no other definition appears, it becomes a definition initialized to zero. Historically multiple tentative definitions merged as "common" symbols — modern `-fno-common` treats duplicates as errors.
What is separate compilation?	Compiling each `.c` file independently into an object file (`.o`/`.obj`) with `gcc -c`, then linking the objects (and libraries) together into an executable. It enables incremental rebuilds — only changed files are recompiled.
What does a build system like Make provide?	It describes targets, their dependencies, and the commands to build them, so only out-of-date files are rebuilt (incremental builds). It automates the compile-then-link pipeline across many files and captures build flags/order.
What is the difference between a static and a shared library?	A static library (`.a`/`.lib`) is copied into the executable at link time — no runtime dependency, larger binary. A shared/dynamic library (`.so`/`.dll`) is resolved at load/run time — smaller binaries, one shared copy, but it must be present and ABI-compatible at runtime.
Why is `extern "C"` needed when mixing C and C++?	C++ mangles function names to encode parameter types (for overloading); C does not. Wrapping C declarations in `extern "C" { … }` tells the C++ compiler to use C linkage/naming so the linker finds the C symbols. Guard it with `#ifdef __cplusplus`.
How do circular header dependencies get resolved?	When two headers need each other's types, use a forward declaration (`struct A;`) in place of a full `#include` where only a pointer/reference is required, breaking the cycle. Include the full definition only in the `.c` files that need the members.
Why does changing a struct layout break ABI in a shared library?	Callers compiled against the old layout use the old member offsets and struct size; a new library with a different layout mismatches them, corrupting data. Preserve ABI by appending members carefully, using opaque pointers, or versioning the library.

# 1.11 Error-Handling Idioms
What are common error-signaling conventions in C?	Return an `int` status (0 success, non-zero error), return `-1` and set `errno`, return a sentinel (`NULL`, `EOF`), or return a dedicated status enum. C has no exceptions, so each caller must check and propagate errors explicitly.
How do you use `errno` correctly?	`errno` is meaningful only right after a call documented to set it *fails*; many functions don't clear it on success. Check the function's own failure indicator first, then read `errno`. For functions that can validly return -1, set `errno = 0` before the call.
What is the `goto cleanup` idiom?	A single-exit pattern where each error path `goto`s a label that releases resources acquired so far (in reverse order) and returns. It avoids duplicating cleanup and prevents leaks from forgotten frees on early returns — an idiomatic use of `goto`.
What is the output-parameter plus boolean-success pattern?	The function returns success/failure and writes the real result through a pointer: `bool parse(const char *s, int *out)`. This keeps the return channel for error status while still delivering a value, avoiding sentinel ambiguity.
How do you distinguish a valid result that looks like an error from a real error?	Use the function's dedicated failure signal, not the value alone. `strtol("0", …)` legitimately returns 0, so check `endptr` (did it parse anything?) and `errno == ERANGE` (overflow) rather than treating 0 as failure.
How are errors propagated up a call stack without exceptions?	Each function checks its callees' return codes and returns its own error code upward, cleaning up as it goes — often with the `goto cleanup` pattern. There is no automatic unwinding; propagation is manual `if (err) return err;` at every level.
Why does resource-acquisition order matter for cleanup?	So cleanup can unwind in reverse order, releasing the most recently acquired resource first and only freeing what was actually acquired. Acquire A then B; on failure free B then A. Ordered acquisition plus reverse release avoids double-frees and leaks.

# 1.12 Security-Relevant Code Patterns (Reading)
How do you spot a buffer overflow risk when reading code?	Look for copies into a fixed-size buffer whose length is external and unbounded: `strcpy`, `strcat`, `sprintf`, `gets`, `scanf("%s", buf)`, or manual loops with no size check. Ask "can the source exceed the destination?" — if attacker-influenced and unchecked, it can smash memory.
What do you look for to catch an unvalidated length used in allocation/indexing?	A size or index taken from input (a header field, `argv`, a read count) fed straight into `malloc(n)`, `arr[i]`, or a copy length without a range/overflow check. The fix is validating against the real buffer size and against overflow before use.
How do you recognize a format-string vulnerability?	A `printf`/`fprintf`/`syslog` whose *format* argument is not a string literal but comes from input: `printf(user)` instead of `printf("%s", user)`. An attacker can insert `%x` (leak memory) or `%n` (write memory).
What is a trust boundary, and why find it first?	It is where data crosses from untrusted (argv, stdin, files, network, environment, IPC) into your program. Every value crossing it must be validated (length, range, format) before reaching a sensitive sink. Security review starts by locating these boundaries.
How can an integer computation become a memory-safety bug?	A size like `count * elem` can overflow `size_t` to a small value, so `malloc(count*elem)` under-allocates and the following loop overflows the heap. Look for size arithmetic on untrusted counts with no overflow guard (`count > SIZE_MAX/elem`).
How do you spot a missing bounds check in a copy/index loop?	Find loops that index or copy using a count or index derived from input, then check whether that value is validated against the destination's capacity before the loop runs. An attacker-influenced index with no `< size` guard is an out-of-bounds read or write.
Why is a signed length compared with `<` against a max dangerous?	If `len` is signed and attacker-supplied negative, `len < MAX` passes, but when `len` is later used as an unsigned size (e.g. `memcpy`'s `size_t` parameter), the negative becomes a huge value — a bounds-check bypass. Use unsigned types and check both ends.
What should you check around privilege-sensitive calls like `setuid`/`system`/`exec*`?	Whether their return values and preconditions are honored: an ignored `setuid` failure means privileges were not dropped; `system`/`popen` with untrusted data invites command injection; `exec*` with an attacker-controlled `PATH` runs the wrong binary. Each is a privilege-escalation vector if mishandled.
How do you spot a potential use-after-free while reading code?	Find where a pointer is `free`d and then check whether any alias (another pointer, a stored field, a container entry) still references that memory and is later used. A freed block reachable through a second pointer is a use-after-free waiting to happen.
What is an information-disclosure pattern to watch for?	A buffer or struct sent/returned to a caller without being fully initialized — padding bytes or unfilled tail bytes leak stale stack/heap data (keys, other users' data). `memset` before filling, or serialize field-by-field.
How do you tell a benign copy from a risky manual reimplementation of `strcpy`/`memcpy`?	A hand-rolled `while (*d++ = *s++);` or index loop copies with no bound and no care for the terminator or destination size — the same danger as `strcpy`. A benign copy checks the destination capacity and respects the terminator.
How does a stack-buffer-overflow snippet map to "overwrite the return address"?	On a typical frame the return address and saved frame pointer sit above the local buffers; an unbounded write into a local array climbs into them, so on return control jumps to an attacker-chosen address. Recognizing this is the core of reading stack-smash code.

# 1.13 Memory Model & Low-Level (Pro)
What does `_Atomic` / `<stdatomic.h>` provide?	Atomic types and operations (`atomic_load`, `atomic_store`, `atomic_fetch_add`, `atomic_compare_exchange`) that execute indivisibly and, with a chosen memory order, order accesses between threads. They let you build lock-free counters/flags without data races (which are UB).
What do the C memory orders mean?	`memory_order_relaxed` (atomicity only, no ordering), `_acquire` (later reads/writes cannot move before this load), `_release` (earlier reads/writes cannot move after this store), `_seq_cst` (a single global total order — the default and safest). Acquire/release pairs hand off data between threads.
What do `_Alignas` and `_Alignof` do?	`_Alignof(type)` queries a type's alignment requirement. `_Alignas(N)` or `_Alignas(type)` forces a variable/member to a stricter alignment (e.g. cache-line or SIMD alignment). Both are C11; `<stdalign.h>` provides `alignas`/`alignof` spellings.
What is `_Generic` used for?	Compile-time type-based selection (C11): a `_Generic(expr, int: fi, double: fd, default: fg)` expression picks a branch by the controlling expression's type. It underlies type-generic macros like `<tgmath.h>` and custom overload-like macros.
What is `_Static_assert`?	A compile-time assertion: `_Static_assert(sizeof(int)==4, "need 32-bit int");` fails the build if the constant condition is false, with zero runtime cost. Ideal for checking type sizes, struct layouts, and configuration invariants.
What is endianness, and how do you detect it at run time?	The byte order of multi-byte integers: little-endian stores the least-significant byte first (x86, ARM default), big-endian the most-significant first (network order). Detect via `union { uint32_t i; char c[4]; } u = {1}; little = (u.c[0]==1);`.
Why isn't `0.1` exact in IEEE 754?	Binary floating point stores values as sign × mantissa × 2^exponent; 0.1 is a repeating fraction in binary (like 1/3 in decimal) and is rounded to the nearest representable `double`. Hence `0.1 + 0.2 != 0.3` exactly, and you compare floats within an epsilon.
What are subnormals and signed zero in IEEE 754?	Subnormals (denormals) fill the gap between the smallest normal number and zero, trading precision for gradual underflow. Signed zero (`+0.0` and `-0.0`) compare equal but differ in sign-sensitive operations like `1.0/x` (which gives `+Inf` vs `-Inf`).
Why is `NaN == NaN` false, and how do you test for NaN?	IEEE 754 defines NaN (e.g. `0.0/0.0`) as unordered — it compares false against everything, including itself. So `x != x` is a valid NaN test; the standard way is `isnan(x)` from `<math.h>`.
What are the three ways to type-pun, and which are safe?	Reading a different `union` member than written is defined in C. Reinterpreting via a pointer cast violates strict aliasing (UB). Copying bytes with `memcpy` between the two objects is always defined and portable — the recommended method.
What do calling conventions and ABI define?	How functions pass arguments and return values (in which registers or on the stack), which registers are caller- vs callee-saved, stack alignment, and name mangling. Both sides of a call must agree, which is why ABI stability matters for shared libraries.
What is position-independent code (PIC)?	Code that executes correctly regardless of its load address, using relative addressing (and a GOT/PLT for globals) instead of absolute addresses. It is required for shared libraries (loaded at varying addresses) and for ASLR-hardened executables (PIE).
How does `volatile` support memory-mapped I/O?	Hardware registers mapped into the address space can change on their own and have side effects on access, so pointers to them are `volatile` to force every read/write to actually occur in program order and not be cached or elided by the optimizer.
What is the difference between a compiler barrier, a memory fence, and `volatile`?	A compiler barrier stops the compiler from reordering across it but emits no CPU instruction. A memory fence (from atomics) also stops the CPU/cache from reordering. `volatile` only prevents the compiler from eliding/caching a specific object's accesses — it provides no inter-thread ordering.
What is the ABA problem in lock-free code?	A compare-and-swap sees a value change A→B→A and wrongly concludes nothing happened, though the underlying state (e.g. a freed-and-reused node) changed. Mitigations: tagged pointers (version counters) and hazard pointers.
What are the standard memory segments of a process?	Text (executable code, read-only), rodata (constants), data (initialized globals), BSS (zero-initialized globals), heap (grows up, `malloc`), and stack (grows down, locals/frames). `mmap` regions (files, anonymous memory, shared libraries) sit in between.

# 1.14 Exploit Mitigations (Pro / Security)
How does a stack buffer overflow overwrite the return address?	The stack frame holds the return address and saved frame pointer above the local buffers (which grow toward them). Writing past a local array climbs into the saved frame pointer and return address, so on `ret` control jumps to an attacker-chosen location — "stack smashing".
What does a stack canary do, and what does it miss?	The compiler places a random value between local buffers and the return address, checked before return; a linear overflow that clobbers it aborts the program. It detects contiguous stack overflows but not heap overflows, not overwrites of locals below the canary, and not targeted non-linear writes.
What is ASLR, and how do information leaks defeat it?	Address Space Layout Randomization randomizes base addresses of stack, heap, and libraries each run, so attackers cannot hardcode targets for return-to-libc/ROP. A memory-disclosure bug that leaks a real runtime address reveals the randomization offset and defeats ASLR.
Why did NX/DEP (W^X) lead to return-oriented programming?	NX marks writable memory (stack/heap) non-executable, so injected shellcode won't run. Attackers responded with ROP: chaining existing executable code fragments ("gadgets" ending in `ret`) already in the binary/libraries to compute arbitrarily without injecting new code.
What do PIE and RELRO harden?	PIE (position-independent executable) lets the main program be loaded at a random base, extending ASLR to its code. RELRO makes the GOT (global offset table) read-only after relocation, preventing attackers from overwriting resolved function pointers to hijack control flow.
What does Fortify Source (`_FORTIFY_SOURCE`) do?	When the destination size is known at compile time, it swaps calls like `memcpy`/`strcpy`/`sprintf` for checked variants (`__memcpy_chk`, …) that abort on overflow, catching many buffer overflows at low cost. Enable with `-D_FORTIFY_SOURCE=2` and optimization.
What is Control-Flow Integrity (CFI)?	A mitigation that restricts indirect calls/jumps to a set of valid targets computed at compile/link time, so an attacker who corrupts a function pointer or vtable cannot redirect execution to arbitrary code. Hardware forms include Intel CET and ARM PAC/BTI.
What do AddressSanitizer, UBSan, and Valgrind detect?	They catch memory/UB errors at run time during testing: ASan finds heap/stack/global overflows, use-after-free, and double-free; UBSan finds signed overflow, bad shifts, misalignment, and other UB; Valgrind's memcheck finds leaks and invalid accesses. Run your test suite under them.
What are the overflow-checking builtins for?	`__builtin_add_overflow(a, b, &res)` (and `_sub_`/`_mul_`) compute the result and return `true` on overflow, letting you validate size/index arithmetic before it causes a downstream memory bug — portable and cheaper than manual `INT_MAX` comparisons.
Why does "defense in depth" matter for exploit mitigations?	Any single mitigation can be bypassed (canaries via leaks/overwrites below them, ASLR via info leaks, NX via ROP). Layering canaries + ASLR + NX + CFI + Fortify raises the number of bugs/primitives an attacker needs, sharply increasing exploitation cost.

# 1.15 The Abstract Machine, Sequence Points & Evaluation Order
What is the C abstract machine?	An abstract execution model defined by the standard — the compiler may generate any code as long as observable behavior (I/O, volatile accesses, program exit) matches what the abstract machine would produce. Real hardware can differ freely inside those constraints.
What is the as-if rule?	The compiler may apply any transformation (reorder, fold, eliminate code) as long as observable behavior is unchanged. Unused computations, dead stores, and non-volatile memory accesses can all disappear under optimization.
What replaced sequence points in C11?	The sequenced-before/sequenced-after/indeterminately-sequenced relations. "A is sequenced before B" means all side effects of A complete before any evaluation of B begins — a more precise partial-order model than the C99 sequence-point concept.
Which constructs impose sequencing in C?	The comma operator, short-circuit && and ||, the ?: ternary (condition is sequenced before either branch), and the function-call boundary (all arguments are fully evaluated before the callee starts). Statement boundaries also establish sequencing between complete expressions.
Why is i++ + i++ undefined behavior?	The two increments are unsequenced relative to each other. The standard says a side effect on a scalar object that is unsequenced with another side effect (or read) on the same object is UB — not just unspecified, but fully undefined.
What counts as observable behavior that the compiler must preserve?	Reads and writes to volatile objects, I/O operations via library functions, and the program's exit status. Pure computations with no externally visible effect are not observable and may be silently removed.

# 1.16 C Object Model — Value, Representation & Effective Type
What is an object in C (formally)?	A region of storage. An object has an address, a size, a type (its effective type), and a value. Every local variable, every malloc'd block, every hardware-register mapping is an object in this sense.
What is the difference between value bits and padding bits?	Value bits participate in encoding the mathematical value. Padding bits exist for alignment and have unspecified values — comparing two structs byte-by-byte with memcmp may give false "not equal" because padding bytes differ. unsigned char has no padding bits by definition.
What is the effective type of an object?	The type that governs which lvalue accesses are legal. For declared objects it is the declared type. For malloc'd memory it is the last type stored into it. Accessing an object through an incompatible type violates the strict aliasing rule.
Why are char * and unsigned char * universal aliases?	The standard explicitly exempts them from the strict aliasing rule — any object's representation may be read through these pointer types. This is why serialization, memcpy, and byte-level inspection work correctly.
What is a trap representation?	A bit pattern that does not correspond to any valid value for a type; reading it is UB. Unsigned integer types and unsigned char are guaranteed trap-representation-free. Signed types and other types may have them on exotic architectures.
What is the strict aliasing rule?	An object may be accessed only through an lvalue of its effective type, a qualified version of it, a signed/unsigned variant, or char/unsigned char. Casting a float* to int* and dereferencing it is a strict-aliasing violation; the compiler may assume no such aliasing occurs.

# 1.17 Two's Complement, Number Representations & C23
What signed integer representations did C89–C17 allow, and what does C23 mandate?	C89–C17 allowed two's complement, ones' complement, and sign-magnitude. C23 mandates two's complement for all signed integer types, ending portability concerns about negative-value representation.
Why is signed integer overflow still UB in C23 despite mandated two's complement?	C23 fixes the representation but not the arithmetic guarantee — compilers may still assume overflow never happens and optimize on that basis (e.g. prove x+1 > x is always true for signed x). Wrapping on overflow is only guaranteed for unsigned arithmetic.
What are the key properties of two's complement?	Unique zero; negation is bitwise NOT plus 1; INT_MIN has no positive counterpart (-INT_MIN overflows); addition, subtraction, and multiplication work identically for signed and unsigned at the bit level.
Why is CHAR_BIT not always 8?	The standard requires at least 8 bits per char, but some DSPs use 16 or 32-bit bytes. Hardcoding 8 (e.g. x >> 8 to extract a high byte) is wrong on such targets. Use CHAR_BIT from <limits.h> for portable bit-level code.
How do you safely type-pun between float and uint32_t?	Copy the bits via memcpy: uint32_t u; memcpy(&u, &f, sizeof u); Reading a union member other than the one last written is also defined in C for this purpose. Casting float* to uint32_t* and dereferencing violates strict aliasing (UB).

# 1.18 Internationalization, Encoding & Multi-Byte Strings
What are C's two character models?	Multi-byte characters: variable-width sequences stored in char[], encoding determined by locale/implementation. Wide characters: fixed-width wchar_t values (size is platform-defined, 16-bit on Windows, 32-bit on Linux/macOS). Neither model maps cleanly to Unicode by itself.
What is mbstate_t?	An opaque object tracking conversion state for shift-state multi-byte encodings. Pass it to the reentrant converters mbrtowc/wcrtomb/mbsrtowcs to correctly handle multi-byte characters split across separate reads.
What does strlen return on a UTF-8 string?	The number of bytes (code units), not Unicode code points and not grapheme clusters. A 4-byte emoji occupies 4 bytes, so strlen counts 4, not 1. Use a UTF-8-aware library when code-point counts are needed.
What is char8_t (C23)?	A distinct unsigned integer type for UTF-8 string data, paired with u8"..." literals. It makes encoding intent explicit in the type system, unlike plain char[] which could hold any encoding.
What do locale categories control?	LC_CTYPE affects is*()/to*() character classification; LC_NUMERIC controls the decimal point and thousands separator in printf/scanf; LC_TIME controls strftime output; LC_COLLATE controls strcoll ordering. LC_ALL sets all categories at once.

# 1.19 Generic Programming Idioms in C
How does _Generic work in C11?	_Generic(expr, type1: val1, type2: val2, ..., default: valN) selects the branch whose type matches the type of expr. The expression is not evaluated — only its type is used. This enables type-safe dispatch macros without preprocessor tricks.
What is the X-macro pattern?	Define a list macro like #define ERRORS X(E_OK,"ok") X(E_IO,"i/o error"). Reuse it with different #define X(code,msg) definitions to generate enum values, string-name arrays, and switch cases from a single source of truth, keeping them all synchronized automatically.
How does container_of / offsetof work?	Given a pointer to a struct member, recover the enclosing struct pointer: (T*)((char*)ptr - offsetof(T, member)). Used in Linux kernel intrusive lists and other zero-overhead containers to iterate without extra allocation.
What is a tagged union (discriminated union) in C?	A struct pairing a type-tag enum with a union of possible values. The tag indicates which union member is currently valid, giving type-safe variant storage without vtables or dynamic allocation.
What is an intrusive linked list?	One where the list next/prev links are embedded inside the user's data struct, not in a separate wrapper node. The container manipulates links without owning elements — no extra allocation per element. The container_of trick recovers the enclosing struct from a node pointer.
How do you simulate closures in C?	Pass a function pointer together with a void *ctx pointer that points to the captured state. The callee invokes callback(arg, ctx); the callback casts ctx back to its real type to access the closed-over variables. This is the standard C callback pattern.

# 1.20 Implementing Dynamic Data Structures in C
How do you implement a growable array in C?	Keep size (used count) and capacity (allocated count). On append, if size == capacity, double the capacity with realloc into a temp pointer to detect failure, then update. This gives amortized O(1) append with minimal allocator pressure.
What is the difference between separate chaining and open addressing?	Separate chaining: each bucket holds a linked list of colliding keys — simple but pointer-heavy with poor cache behavior. Open addressing: collisions are resolved by probing adjacent slots — better cache locality but more complex insertion and deletion.
How is a binary heap stored in an array?	Root at index 0; children of node i at 2i+1 and 2i+2; parent of node i at (i-1)/2. This complete-tree layout needs no pointers and is cache-friendly for sift-up/sift-down operations.
What are sift-up and sift-down?	Sift-up: after inserting at the end, swap the new element with its parent while it violates the heap property — O(log n). Sift-down: after removing the root, swap in the last element and push it down by swapping with its smaller child — O(log n).
What is the ownership question when designing a C container?	Does the container own its elements (calling free on removal/destruction) or merely hold borrowed pointers (caller manages lifetime)? Document it explicitly to prevent double-free and leaks when the container is destroyed.

# 1.21 C API Design Conventions
What is the opaque handle (PIMPL) pattern in C?	Forward-declare typedef struct Foo Foo; in the public header; put the full struct definition only in the .c file. Callers hold and pass Foo * but cannot inspect or stack-allocate the struct — implementation details are hidden and the ABI is stable.
What should a C API document about ownership?	For every pointer returned or passed: who allocates it, who frees it, when ownership transfers, and what happens on error. Common conventions: "caller must free the returned buffer", "ownership transfers to callee on success", "callee does not retain the pointer after return".
What is the constructor/destructor convention in C APIs?	Heap-based: Obj *obj_create(...) / void obj_destroy(Obj *). Init-based for caller-allocated objects: void obj_init(Obj *, ...) / void obj_fini(Obj *). Always provide a matching pair and document which side allocates and frees.
How does struct versioning with a size field work?	Make the first member uint32_t size; — callers set it to sizeof(struct Opts) before passing. The library checks opts->size >= sizeof(struct V1) before reading V1 fields and >= sizeof(struct V2) for newer fields. Older callers pass a smaller struct safely.
Why is const-correctness important in a C API surface?	Declaring parameters const char * communicates that the function will not modify the pointed-to data, letting callers pass string literals and const objects safely. Using char * when mutation is not intended silently removes the compiler's ability to catch accidental writes.
What naming conventions do C APIs typically follow?	module_verb or module_noun_verb (e.g. buf_append, list_node_remove). The _t suffix for typedef'd types. Names starting with __ or _[A-Z] are reserved by the C implementation and must not be defined in application or library code.
