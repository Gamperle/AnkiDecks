# Reading, tracing, and explaining C code: types, pointers, memory, UB, expressions, compilation, security patterns.

# 1.1 Variables, Types & Expressions
What are the fundamental integer types in C, from smallest to largest?	`char`, `short`, `int`, `long`, `long long`, each with a `signed` and `unsigned` variant. The standard only guarantees minimum widths (e.g. `int` ≥ 16 bits, `long` ≥ 32, `long long` ≥ 64); actual sizes are implementation-defined. Use `<stdint.h>` fixed-width types when exact size matters.
What are the "usual arithmetic conversions" (integer promotion)?	Before most binary operations, operands narrower than `int` are promoted to `int` (or `unsigned int`). Then both operands are converted to a common type. This is why `char a = 200, b = 100; a + b` computes in `int` and does not overflow at the `char` level.
Why is `-1 < 0u` false in C?	The comparison mixes signed and unsigned. Under the usual arithmetic conversions, `-1` is converted to `unsigned`, becoming `UINT_MAX` (a huge positive value), so `UINT_MAX < 0u` is false. Mixing signed and unsigned in comparisons is a classic bug source.
What is the difference between `#define`, `const`, and `enum` constants?	`#define N 10` is a textual macro with no type or scope. `const int n = 10;` is a typed, scoped variable (may occupy storage, address can be taken). `enum { N = 10 };` gives a named integer constant of type `int` with scope and no storage. Prefer `const`/`enum` over `#define` for typed constants.
What does the `typedef` keyword do?	It creates an alias for an existing type, e.g. `typedef unsigned long ulong;` or `typedef struct Node Node;`. It does not create a new distinct type — just a synonym. Hiding pointers behind typedefs (`typedef struct S *SHandle;`) can aid encapsulation but also obscure that a value is a pointer.
What is a compound literal?	An unnamed object created inline with `(type){ initializers }`, e.g. `(int[]){1, 2, 3}` or `(struct Point){.x = 1}`. It has automatic storage duration (block scope) unless at file scope. Useful for passing a temporary struct/array directly to a function.
What is the difference between an lvalue and an rvalue?	An lvalue designates an object with an identifiable location and can appear on the left of `=` (e.g. a variable, `*p`, `arr[i]`). An rvalue is just a value (e.g. `3`, `a + b`) and cannot be assigned to. `a + b = 5;` is an error because `a + b` is an rvalue.
Why is `if (x = 5)` almost always a bug?	`=` is assignment, not comparison. `x = 5` assigns 5 to `x` and evaluates to 5 (truthy), so the branch always runs and `x` is silently modified. The intended `if (x == 5)` compares. Some prefer "Yoda conditions" (`if (5 == x)`) so a typo becomes a compile error.
How does short-circuit evaluation work for `&&` and `||`?	`&&` stops and yields 0 as soon as a false operand is found; `||` stops and yields 1 as soon as a true operand is found. The right operand is not evaluated if the result is already determined. This lets you write `if (p && p->x)` — safe because `p->x` is skipped when `p` is null.
What does `*p++` do, and how does it differ from `(*p)++`?	`*p++` parses as `*(p++)`: it dereferences `p`, then increments the pointer `p` (the increment applies to `p`, the dereference yields the old pointed-to value). `(*p)++` dereferences `p` and increments the pointed-to value, leaving `p` unchanged.
Why does `flags & MASK == 0` not do what it looks like?	`==` has higher precedence than `&`, so it parses as `flags & (MASK == 0)`. You almost always want `(flags & MASK) == 0`. Bitwise operators binding looser than comparison operators is one of C's most notorious precedence traps.
Is `sizeof` evaluated at compile time or run time?	Compile time for everything except variable-length arrays (VLAs), whose size is computed at run time. The operand of `sizeof` is not evaluated: `int i = 0; sizeof(i++)` yields the size and leaves `i` unchanged.

# 1.2 Storage Classes, Scope & Lifetime
What is the difference between scope and lifetime?	Scope is *where* a name is visible in the source; lifetime (storage duration) is *when* the object exists at run time. A `static` local variable has block scope (visible only in its function) but static lifetime (exists for the whole program run).
What does `static` mean on a local variable?	The variable has static storage duration: a single instance that is initialized once (before `main`, to zero if no initializer) and retains its value across calls. `int counter(void){ static int n = 0; return ++n; }` returns 1, 2, 3, … on successive calls.
What does `static` mean at file scope?	It gives the function or global variable *internal linkage*: the name is private to that translation unit and cannot be referenced from other `.c` files. This is the C way to make a helper "module-private".
What is the difference between `static` and `extern` on a global?	`static` = internal linkage (private to the file). `extern` declares that a name is defined elsewhere (external linkage), letting you reference a global/function from another translation unit without defining it here. The definition lives in exactly one `.c` file.
Are uninitialized variables zero-initialized in C?	Only variables with static or thread storage duration (globals, `static` locals) are zero-initialized. Automatic (local) variables are *not* — they hold indeterminate garbage, and reading them is undefined behavior.
What does the `register` storage class do today?	It is a hint that a variable is heavily used; modern compilers ignore it for optimization purposes. Its one lasting effect: you may not take the address (`&`) of a `register` variable.

# 1.3 Pointers & Memory
Are `int *p`, `int* p`, and `int * p` different?	No — whitespace is irrelevant; all three declare `p` as a pointer to `int`. Note the pitfall in `int* a, b;` — only `a` is a pointer, `b` is a plain `int`. The `*` binds to the declarator, not the type, which is why many write `int *p`.
How much does `p + 1` advance a pointer?	By `sizeof(*p)` bytes — one element, not one byte. For `int *p` on a 32-bit-int platform, `p + 1` is 4 bytes further along. Pointer arithmetic is always in units of the pointed-to type.
What happens when you dereference a `NULL` pointer?	Undefined behavior. On most hosted systems it triggers a segmentation fault (crash), but the standard imposes no requirement — the compiler may assume it never happens and optimize accordingly. Always check pointers that could be null before dereferencing.
What is array-to-pointer decay?	In most expressions, an array name is implicitly converted ("decays") to a pointer to its first element. So `arr` becomes `&arr[0]`. Decay is why a function parameter `int a[]` is really `int *a` and loses the array's size. Exceptions: operands of `sizeof`, `&`, and string-literal initialization.
Is there any difference between `arr[i]` and `*(arr + i)`?	No — `arr[i]` is defined as `*(arr + i)`. A curious consequence is that `i[arr]` is also legal and equivalent, since addition commutes. `arr[i]` is the readable form everyone uses.
What is a dangling pointer?	A pointer that refers to memory that is no longer valid — e.g. after `free(p)`, or a pointer to a local variable after its function returned. Dereferencing it is undefined behavior. Setting a pointer to `NULL` after `free` makes accidental reuse crash predictably instead of silently corrupting.
What is the difference between `const int *p`, `int * const p`, and `const int * const p`?	`const int *p`: pointer to const int — you cannot modify `*p`, but can repoint `p`. `int * const p`: const pointer to int — you can modify `*p`, but cannot repoint `p`. `const int * const p`: neither the pointee nor the pointer can be changed. Read right-to-left: "p is a const pointer to const int".
Why does `void *` require a cast before use?	`void *` is a generic pointer with no element type, so it has no size to do arithmetic or dereference. You must convert it to a concrete pointer type first, e.g. `int *ip = vp; *ip = 5;`. In C the conversion is implicit (no cast needed) but in C++ a cast is required.
Is an uninitialized pointer the same as a NULL pointer?	No. `int *p;` (uninitialized) holds indeterminate garbage — dereferencing is UB and may not crash. Only `int *p = NULL;` is guaranteed null. Always initialize pointers to `NULL` if you cannot give them a valid target immediately.

# 1.4 Arrays & Strings
How are partially-initialized arrays filled?	Any elements you do not explicitly initialize are zero-initialized. `int a[5] = {1, 2};` gives `{1, 2, 0, 0, 0}`. `int a[100] = {0};` (or `= {}` in C23) zeroes the whole array.
How is a 2D array `int m[3][4]` laid out in memory?	Row-major: all of row 0's four ints, then row 1's, then row 2's — contiguous. `m[i][j]` is at offset `i*4 + j` ints from the start. Iterating with the last index innermost (`for i … for j … m[i][j]`) is cache-friendly.
Why do C strings need a `\0` terminator?	C has no built-in length for strings; functions like `strlen`, `printf %s`, and `strcpy` scan until they hit the `\0` byte. A missing terminator makes them read past the buffer (out-of-bounds), a common crash and security bug.
What is the difference between `char buf[] = "hi";` and `char *p = "hi";`?	`char buf[]` creates a modifiable local array (here 3 bytes) that you own and can change. `char *p` points at a read-only string literal in static storage; writing `p[0] = 'H'` is undefined behavior. Prefer `const char *` for literals so the compiler catches writes.
What is a variable-length array (VLA)?	An array whose size is a runtime expression, e.g. `void f(int n){ int a[n]; }`. Introduced in C99, made optional in C11 (`__STDC_NO_VLA__`). It lives on the stack, so a large or attacker-controlled `n` risks stack overflow — often better to `malloc`.
Why does `sizeof(arr)` give the wrong answer inside a function?	When an array is passed to a function it decays to a pointer, so the parameter is really a pointer. `sizeof(arr)` then yields the pointer size (e.g. 8), not the original array's byte size. Pass the length as a separate parameter.
What does `argv[argc]` equal in `main`?	It is guaranteed to be a `NULL` pointer. `argv` is an array of `argc` string pointers followed by a null terminator, so you can iterate either with an index up to `argc` or by walking until you hit `NULL`.

# 1.5 Control Flow & Functions
When is `do-while` preferable to `while`?	When the body must run at least once before the condition is tested — e.g. reading input then validating it, or menu loops. `do { ... } while (cond);` checks `cond` at the bottom.
What is switch fall-through, and when is it a bug?	Without a `break`, execution falls from one `case` into the next. It is intentional when several labels share code (`case 1: case 2: do_x();`), but an accidental missing `break` runs the following case's body too. C23's `[[fallthrough]]` documents the intentional case.
What is the difference between a function declaration, definition, and prototype?	A declaration introduces the name/type so it can be called. A definition additionally provides the body. A prototype is a declaration that specifies parameter types, e.g. `int f(int, char*);`, enabling the compiler to type-check calls.
What is the difference between `f()` and `f(void)` in a declaration?	`f(void)` explicitly declares "no parameters". `f()` (empty parens) is a legacy form meaning "unspecified arguments" — the compiler won't check the call. Always use `(void)` for no-argument functions in C.
Why is returning a pointer to a local variable a bug?	The local variable's lifetime ends when the function returns, so the returned pointer dangles — its memory may be reused. `int *f(void){ int x = 5; return &x; }` is undefined behavior. Return by value, use `static`, or allocate with `malloc` instead.
How do variadic functions read their arguments?	Via `<stdarg.h>`: declare `va_list ap; va_start(ap, last);` (last = the final named parameter), then `va_arg(ap, type)` for each argument, and `va_end(ap)`. There is no built-in count, so a format string or explicit count tells the function how many/what types to expect.
What are the default argument promotions in a variadic call?	Arguments passed through `...` are promoted: `float` becomes `double`, and integer types narrower than `int` become `int` (or `unsigned int`). So you must `va_arg(ap, int)` for a char/short and `va_arg(ap, double)` for a float — using the narrow type is UB.
When is `goto` a reasonable choice in C?	For centralized cleanup on error paths (`goto cleanup;` to free resources and return) and for breaking out of nested loops. Both keep the "happy path" flat and avoid deeply nested `if`s. Uncontrolled `goto` producing spaghetti control flow is what to avoid.

# 1.6 Structs, Unions & Enums
Why can `sizeof(struct)` be larger than the sum of its members?	The compiler inserts padding so each member meets its alignment requirement (e.g. an `int` on a 4-byte boundary). `struct { char c; int i; }` is often 8 bytes, not 5. Reordering members largest-to-smallest can reduce padding.
How does a `union` differ from a `struct`?	All members of a union share the same memory and it is only large enough for its biggest member; only one member is "active" at a time. Writing one member and reading another is type-punning. A struct gives each member its own distinct storage.
What are designated initializers?	Initializing specific members/elements by name or index: `struct Point p = {.y = 2, .x = 1};` or `int a[9] = {[8] = 5};`. Order-independent and self-documenting; unspecified members are zero-initialized.
How do `enum` constant values work?	Enumerators start at 0 and increment by 1 unless assigned. `enum { A, B, C = 10, D };` gives A=0, B=1, C=10, D=11. Enum constants are of type `int` and live in the enclosing scope (not namespaced), so watch for name clashes.
What is a bit field?	A struct member with an explicit bit width: `struct { unsigned flag : 1; unsigned mode : 3; };`. It packs small values into fewer bits, useful for flags/hardware registers. Layout, ordering, and straddling are implementation-defined, so bit fields are not portable for wire formats.
What is the opaque pointer / forward declaration pattern?	A header exposes `typedef struct Widget Widget;` and functions taking `Widget *`, but not the struct's members. Callers can hold and pass the pointer but cannot see or depend on the layout, giving encapsulation and ABI stability. The full definition lives in the `.c` file.
What does `offsetof(type, member)` return?	The byte offset of `member` from the start of `type`, from `<stddef.h>`. Useful for serialization, hardware register maps, and the "container_of" idiom that recovers a struct pointer from a pointer to one of its members.

# 1.7 Pointers — Advanced Patterns
How do you declare and call a function pointer?	`int (*fp)(int, int) = &add;` (the `&` is optional). Call with `fp(2, 3)` or `(*fp)(2, 3)`. The parentheses around `*fp` are required — without them `int *fp(int,int)` declares a function returning `int*`.
What is an array of function pointers used for?	A dispatch table: `void (*ops[])(void) = {start, stop, reset};` lets you call `ops[i]()` to select behavior by index — a compact alternative to a `switch`, and the basis for hand-rolled vtables/state machines.
What does the `restrict` keyword promise?	That for the lifetime of the pointer, the object it points to is accessed only through that pointer (no aliasing). This lets the compiler skip reloads and optimize, e.g. `memcpy(void *restrict dst, const void *restrict src, size_t n)`. Violating the promise (overlapping regions) is undefined behavior.
What does `volatile` tell the compiler?	That the object may change outside the program's visible control (memory-mapped hardware register, variable modified in a signal handler or another thread), so the compiler must not cache it in a register and must perform every read/write in the source. It is *not* a synchronization primitive between threads.
What is the strict aliasing rule?	An object may generally only be accessed through an lvalue of its own type (or `char`). Reading an `int` through a `float*` is undefined behavior even if the bits line up. To reinterpret bytes portably, use `memcpy` or a `union`, not a pointer cast.
When must you use `memmove` instead of `memcpy`?	When the source and destination regions overlap. `memcpy` has undefined behavior on overlap (it may copy in any order); `memmove` handles overlap correctly by copying as if through a temporary buffer. Use `memmove` for shifting elements within one array.
What is a flexible array member?	A final struct member declared with empty brackets: `struct Buf { size_t len; char data[]; };`. You allocate `malloc(sizeof(struct Buf) + n)` so `data` occupies the trailing bytes. It lets a header and its variable-length payload live in one allocation.

# 1.8 Undefined, Unspecified & Implementation-Defined Behavior
What is the difference between undefined, unspecified, and implementation-defined behavior?	Undefined (UB): the standard imposes no requirements — anything may happen (crash, silent corruption, "works"). Unspecified: the implementation chooses among valid options but need not document it (e.g. argument evaluation order). Implementation-defined: a valid choice the implementation must document (e.g. whether `char` is signed).
Why is signed integer overflow undefined but unsigned overflow defined?	Unsigned arithmetic is defined to wrap modulo 2^N. Signed overflow is UB — the standard does not guarantee wraparound, and compilers optimize assuming it never happens (e.g. assuming `x + 1 > x`). So `INT_MAX + 1` is UB, while `UINT_MAX + 1u` is defined as 0.
Why is `i = i++ + 1;` undefined behavior?	It modifies `i` twice (the `++` and the assignment) with no sequence point between them, and also reads `i` to compute the value. The standard leaves such unsequenced multiple modifications of one object undefined; the result is not merely unspecified — it is UB.
Is the evaluation order of function arguments defined?	No — it is unspecified. In `f(g(), h())`, either `g` or `h` may run first, and it can differ between compilers or calls. Never rely on side-effect ordering across arguments, e.g. `f(x++, x++)`.
Why is modifying a string literal undefined behavior?	String literals like `"hello"` are stored in read-only memory and may be shared between identical literals. `char *s = "hi"; s[0] = 'H';` attempts to write there — UB, often a crash. Use `char s[] = "hi";` for a writable copy.
Is comparing two pointers with `<` always valid?	Only if they point into the same array object (or one-past-the-end). Comparing pointers to unrelated objects with `<`/`>` is undefined behavior. Equality (`==`/`!=`) comparison is always well-defined.

# 1.9 Preprocessor & Compilation
What is the difference between `#include` guards and `#pragma once`?	Both prevent double inclusion of a header. Include guards (`#ifndef X_H / #define X_H / … / #endif`) are standard and portable. `#pragma once` is a non-standard but widely-supported one-liner that lets the compiler track files directly. Guards are safest for maximum portability.
Why must macro parameters be parenthesized?	Because macros are textual substitution, unparenthesized parameters inherit surrounding precedence. `#define SQ(x) x*x` makes `SQ(a+1)` expand to `a+1*a+1`. Write `#define SQ(x) ((x)*(x))` — parenthesize each parameter and the whole body.
What is the double-evaluation macro pitfall?	A macro that uses a parameter more than once evaluates its argument's side effects repeatedly. `#define MAX(a,b) ((a)>(b)?(a):(b))` with `MAX(i++, j++)` increments one of them twice. Prefer an inline function, which evaluates each argument exactly once.
What do the `#` and `##` preprocessor operators do?	`#x` stringizes a macro argument: `#define STR(x) #x` makes `STR(hi)` become `"hi"`. `a ## b` pastes two tokens into one: `#define CAT(a,b) a##b` makes `CAT(foo, bar)` become `foobar`. Used for generating names and debug macros.
Name several standard predefined macros.	`__FILE__` (current file name), `__LINE__` (current line number), `__func__` (current function name, C99), `__DATE__` / `__TIME__` (compile date/time), and `__STDC_VERSION__` (the C standard version, e.g. `201710L` for C17). Common in logging/assert macros.
What are the phases of the C compilation pipeline?	Preprocessing (handle `#include`/`#define`/conditionals) → compilation (C source to assembly) → assembly (to object code/machine instructions) → linking (combine object files and libraries, resolve symbols, into an executable). `gcc -E`, `-S`, `-c` stop after each early phase.

# 1.10 Multi-File Programs, Linkage & Build
Where should declarations vs definitions live in a multi-file program?	Declarations (prototypes, `extern` variable declarations, type/struct definitions, macros) go in header (`.h`) files that are `#include`d where needed. Definitions (function bodies, the single definition of each global) go in exactly one `.c` file. This satisfies "declare many places, define once".
What is the difference between a static library and a shared library?	A static library (`.a`/`.lib`) is copied into the executable at link time — no runtime dependency, larger binary. A shared/dynamic library (`.so`/`.dll`) is resolved at load/run time — smaller binaries, one copy shared across programs, but the library must be present at runtime and ABI-compatible.
What are the three kinds of linkage in C?	External linkage (default for functions and file-scope variables): the name is visible across translation units. Internal linkage (`static` at file scope): visible only within one file. No linkage (locals, parameters, typedefs): each declaration is a distinct entity.
Why use `extern "C"` when mixing C and C++?	C++ mangles function names to encode types (for overloading); C does not. Wrapping C declarations in `extern "C" { … }` tells the C++ compiler to use C linkage/naming so the linker can find the C-compiled symbols. Typically guarded with `#ifdef __cplusplus`.

# 1.11 Error-Handling Idioms
What are the common error-signaling conventions in C?	Return an `int` status (0 = success, non-zero/negative = error), return `-1` and set `errno`, return a sentinel like `NULL`/`EOF`, or return a dedicated status enum. C has no exceptions, so errors must be checked and propagated explicitly at each call.
How should you use `errno` correctly?	`errno` is only meaningful right after a function documented to set it *fails*. Many functions don't clear it on success, so check the function's own failure indicator first (e.g. return value), then read `errno`. To detect errors in functions that can legitimately return -1, set `errno = 0` before the call.
What is the `goto cleanup` idiom?	A single-exit pattern where each error path `goto`s a cleanup label that frees resources acquired so far, in reverse order, then returns. It avoids duplicating cleanup code and forgetting to free on early returns — a very common and idiomatic use of `goto` in C.

# 1.12 Security-Relevant Code Patterns (Reading)
When reading code, how do you spot a buffer overflow risk?	Look for copies into a fixed-size buffer where the length comes from outside and is not bounded: `strcpy`, `strcat`, `sprintf`, `gets`, `scanf("%s", buf)`, or manual loops without a size check. Ask: "can the source be longer than the destination?" If the length is attacker-influenced and unchecked, it is a smash waiting to happen.
What is a format string vulnerability, and how do you recognize it?	It occurs when user-controlled data is passed as the *format* argument: `printf(user)` instead of `printf("%s", user)`. An attacker can insert `%x` (leak stack memory) or `%n` (write to memory). The tell is a `printf`/`syslog`/`fprintf` whose format argument is not a string literal.
What is a "trust boundary" and why identify it when reading code?	It is where data crosses from untrusted (argv, stdin, files, network, environment variables) into your program. Every value that crosses it must be validated (length, range, format) before use. Security review starts by finding these boundaries and checking whether validation happens before the data reaches a sensitive sink (allocation size, index, format string, command).
How can an integer overflow become a memory-safety bug?	A size computed as `count * elem_size` can overflow `size_t`, producing a small value. `malloc(count * elem_size)` then under-allocates, and the subsequent loop writing `count` elements overflows the heap. Look for size arithmetic on untrusted counts with no overflow check (e.g. `if (count > SIZE_MAX / elem_size)`).

# 1.13 Memory Model & Low-Level (Pro)
What does `_Atomic` / `<stdatomic.h>` provide?	Atomic types and operations (`atomic_load`, `atomic_store`, `atomic_fetch_add`, `atomic_compare_exchange`) that execute indivisibly and, with a chosen memory order, establish inter-thread ordering. They let you build lock-free counters/flags without a mutex and without data races (which are UB).
What is endianness, and how can you detect it at run time?	It is the byte order of multi-byte integers in memory: little-endian stores the least-significant byte first (x86, ARM default), big-endian the most-significant first (network byte order). Detect via `union { uint32_t i; char c[4]; } u = {1}; if (u.c[0] == 1) little_endian;`.
What is the only well-defined way to type-pun in C, and what are the alternatives?	Reading a different `union` member than the one written is defined in C (implementation-defined value). Reinterpreting via a pointer cast violates strict aliasing (UB). The portable, always-safe method is `memcpy` between objects of the two types. `float f; uint32_t bits; memcpy(&bits, &f, sizeof bits);`.
Why does `0.1` have no exact representation in IEEE 754?	Binary floating point represents values as sign × mantissa × 2^exponent. 0.1 is a repeating fraction in binary (like 1/3 in decimal), so it is rounded to the nearest representable double. This is why `0.1 + 0.2 != 0.3` exactly and why you compare floats within an epsilon, not with `==`.
Why is `NaN == NaN` false?	IEEE 754 defines NaN (not-a-number, e.g. `0.0/0.0`) as unordered: it compares false against everything, including itself. So `x != x` is a valid NaN test; the standard-library way is `isnan(x)` from `<math.h>`.

# 1.14 Exploit Mitigations (Pro / Security)
How does a stack buffer overflow overwrite the return address?	On a typical call, the stack holds the return address, saved frame pointer, then local buffers, growing downward. Writing past a local array upward can overwrite the saved frame pointer and return address, so when the function returns, control jumps to an attacker-chosen location. This is classic "stack smashing".
What does a stack canary do, and what does it not protect against?	The compiler places a random "canary" value between the local buffers and the return address, checked before return; if a linear overflow clobbered it, the program aborts. It detects contiguous stack overflows but not heap overflows, not overwrites of adjacent locals *below* the canary, and not targeted (non-linear) writes.
What is ASLR and how do information leaks defeat it?	Address Space Layout Randomization randomizes the base addresses of the stack, heap, and libraries each run, so an attacker cannot hardcode target addresses for return-to-libc/ROP. A memory-disclosure bug that leaks a real runtime address lets the attacker compute the randomization offset and defeat ASLR.
Why did NX/DEP lead to return-oriented programming (ROP)?	NX (non-executable stack/heap, W^X) prevents executing injected shellcode in writable memory. Attackers responded with ROP: chaining together existing executable code fragments ("gadgets" ending in `ret`) already present in the binary/libraries to perform arbitrary computation without injecting new code.
What do AddressSanitizer and Valgrind detect that a normal build does not?	They instrument or interpret the program to catch memory errors at run time: heap/stack/global buffer overflows, use-after-free, double-free, memory leaks, and (UBSan) undefined behavior like signed overflow and misaligned access. They are testing tools — you run your test suite under them to surface latent bugs before shipping.
