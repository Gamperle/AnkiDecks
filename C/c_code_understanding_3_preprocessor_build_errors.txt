# 1.9 Preprocessor & Compilation
What is the difference between `#include` guards and `#pragma once`?	Both stop a header being processed twice in one translation unit. Include guards (`#ifndef X_H / #define X_H / … / #endif`) are standard and fully portable. `#pragma once` is a widely-supported non-standard one-liner. Guards are the safest choice.
Why must macro parameters be parenthesized?	Because macros substitute text, unparenthesized parameters inherit surrounding precedence. `#define SQ(x) x*x` makes `SQ(a+1)` expand to `a+1*a+1`. Write `#define SQ(x) ((x)*(x))` — parenthesize each parameter and the whole body.
What is the double-evaluation macro pitfall?	A macro using an argument more than once repeats its side effects. `#define MAX(a,b) ((a)>(b)?(a):(b))` with `MAX(i++, j++)` increments one of them twice. Prefer an inline function, which evaluates each argument once.
What do `#ifdef`, `#ifndef`, and `#if defined(...)` do?	They conditionally include code based on whether a macro is defined. `#ifdef X` / `#ifndef X` test one macro; `#if defined(X) && !defined(Y)` allows compound conditions. Used for platform/feature selection and include guards.
Name key standard predefined macros.	`__FILE__` (source file name), `__LINE__` (current line), `__func__` (function name, C99), `__DATE__` / `__TIME__` (compile date/time), and `__STDC_VERSION__` (C standard version, e.g. `201710L`). Common in logging and assertion macros.
What does `static` at file scope do to linkage?	It gives the function or variable internal linkage — visible only within its translation unit and not linkable from other `.c` files. It is C's way to make a module-private helper or global.
What does the `extern` keyword declare?	That a name (variable or function) is defined elsewhere, with external linkage — a declaration without a definition. You put `extern int g;` in a header and define `int g;` once in a single `.c` file.
What are the phases of the C compilation pipeline?	Preprocessing (handle `#include`/`#define`/conditionals) → compilation (source to assembly) → assembly (to object code) → linking (combine objects and libraries, resolve symbols, into an executable). `gcc -E`, `-S`, `-c` stop after each early phase.
How do `inline` functions differ from function-like macros?	An `inline` function is a real function (type-checked, single argument evaluation, has an address) that the compiler may expand in place. A macro is textual substitution with no type checking and possible repeated evaluation. Prefer `inline` for correctness.
What do the `##` and `#` preprocessor operators do?	`#x` stringizes an argument: `#define STR(x) #x` makes `STR(hi)`→`"hi"`. `a##b` pastes tokens: `#define CAT(a,b) a##b` makes `CAT(foo,bar)`→`foobar`. Used to generate identifiers and debug/log macros.
What is a variadic macro?	A macro taking a variable number of arguments via `...`, captured by `__VA_ARGS__`: `#define LOG(fmt, ...) fprintf(stderr, fmt, __VA_ARGS__)`. C23/GNU add `__VA_OPT__` to handle the zero-argument case cleanly.
What do the `#error` and `#pragma` directives do?	`#error msg` aborts compilation with a message (used to catch unsupported configurations). `#pragma` issues an implementation-specific instruction to the compiler (e.g. `#pragma once`, `#pragma pack`, `#pragma GCC diagnostic`).
How is conditional compilation used for platform/feature detection?	Predefined/feature macros gate code: `#if defined(_WIN32)` … `#elif defined(__linux__)` …, or feature-test macros like `_POSIX_C_SOURCE`. This lets one source tree compile correctly across platforms and library versions.


# 1.10 Multi-File Programs, Linkage & Build
Where do declarations vs definitions belong in a multi-file program?	Declarations (prototypes, `extern` variable declarations, type/macro definitions) go in header (`.h`) files included where needed. Definitions (function bodies, the single definition of each global) go in exactly one `.c` file — declare in many places, define once.
What are the three kinds of linkage in C?	External linkage (default for file-scope functions/variables): visible across translation units. Internal linkage (`static` at file scope): visible only within one file. No linkage (locals, parameters, typedefs): each declaration is its own entity.
What is C's "one definition" rule for objects and functions?	Each function or object with external linkage may be *defined* in exactly one translation unit across the whole program, though it may be *declared* in many. Multiple definitions cause a linker "duplicate symbol" error.
How do you share a global variable across files?	Declare it `extern` in a header (`extern int g;`) that all users include, and provide exactly one definition (`int g = 0;`) in a single `.c` file. The `extern` declaration says "defined elsewhere"; the lone definition allocates it.
What is a tentative definition / common symbol?	A file-scope declaration like `int g;` with no initializer is a "tentative definition"; if no other definition appears, it becomes a definition initialized to zero. Historically multiple tentative definitions merged as "common" symbols — modern `-fno-common` treats duplicates as errors.
What is separate compilation?	Compiling each `.c` file independently into an object file (`.o`/`.obj`) with `gcc -c`, then linking the objects (and libraries) together into an executable. It enables incremental rebuilds — only changed files are recompiled.
What does a build system like Make provide?	It describes targets, their dependencies, and the commands to build them, so only out-of-date files are rebuilt (incremental builds). It automates the compile-then-link pipeline across many files and captures build flags/order.
What is the difference between a static and a shared library?	A static library (`.a`/`.lib`) is copied into the executable at link time — no runtime dependency, larger binary. A shared/dynamic library (`.so`/`.dll`) is resolved at load/run time — smaller binaries, one shared copy, but it must be present and ABI-compatible at runtime.
Why is `extern "C"` needed when mixing C and C++?	C++ mangles function names to encode parameter types (for overloading); C does not. Wrapping C declarations in `extern "C" { … }` tells the C++ compiler to use C linkage/naming so the linker finds the C symbols. Guard it with `#ifdef __cplusplus`.
How do circular header dependencies get resolved?	When two headers need each other's types, use a forward declaration (`struct A;`) in place of a full `#include` where only a pointer/reference is required, breaking the cycle. Include the full definition only in the `.c` files that need the members.
Why does changing a struct layout break ABI in a shared library?	Callers compiled against the old layout use the old member offsets and struct size; a new library with a different layout mismatches them, corrupting data. Preserve ABI by appending members carefully, using opaque pointers, or versioning the library.


# 1.11 Error-Handling Idioms
What are common error-signaling conventions in C?	Return an `int` status (0 success, non-zero error), return `-1` and set `errno`, return a sentinel (`NULL`, `EOF`), or return a dedicated status enum. C has no exceptions, so each caller must check and propagate errors explicitly.
How do you use `errno` correctly?	`errno` is meaningful only right after a call documented to set it *fails*; many functions don't clear it on success. Check the function's own failure indicator first, then read `errno`. For functions that can validly return -1, set `errno = 0` before the call.
What is the `goto cleanup` idiom?	A single-exit pattern where each error path `goto`s a label that releases resources acquired so far (in reverse order) and returns. It avoids duplicating cleanup and prevents leaks from forgotten frees on early returns — an idiomatic use of `goto`.
What is the output-parameter plus boolean-success pattern?	The function returns success/failure and writes the real result through a pointer: `bool parse(const char *s, int *out)`. This keeps the return channel for error status while still delivering a value, avoiding sentinel ambiguity.
How do you distinguish a valid result that looks like an error from a real error?	Use the function's dedicated failure signal, not the value alone. `strtol("0", …)` legitimately returns 0, so check `endptr` (did it parse anything?) and `errno == ERANGE` (overflow) rather than treating 0 as failure.
How are errors propagated up a call stack without exceptions?	Each function checks its callees' return codes and returns its own error code upward, cleaning up as it goes — often with the `goto cleanup` pattern. There is no automatic unwinding; propagation is manual `if (err) return err;` at every level.
Why does resource-acquisition order matter for cleanup?	So cleanup can unwind in reverse order, releasing the most recently acquired resource first and only freeing what was actually acquired. Acquire A then B; on failure free B then A. Ordered acquisition plus reverse release avoids double-frees and leaks.


# 1.12 Security-Relevant Code Patterns (Reading)
How do you spot a buffer overflow risk when reading code?	Look for copies into a fixed-size buffer whose length is external and unbounded: `strcpy`, `strcat`, `sprintf`, `gets`, `scanf("%s", buf)`, or manual loops with no size check. Ask "can the source exceed the destination?" — if attacker-influenced and unchecked, it can smash memory.
What do you look for to catch an unvalidated length used in allocation/indexing?	A size or index taken from input (a header field, `argv`, a read count) fed straight into `malloc(n)`, `arr[i]`, or a copy length without a range/overflow check. The fix is validating against the real buffer size and against overflow before use.
How do you recognize a format-string vulnerability?	A `printf`/`fprintf`/`syslog` whose *format* argument is not a string literal but comes from input: `printf(user)` instead of `printf("%s", user)`. An attacker can insert `%x` (leak memory) or `%n` (write memory).
What is a trust boundary, and why find it first?	It is where data crosses from untrusted (argv, stdin, files, network, environment, IPC) into your program. Every value crossing it must be validated (length, range, format) before reaching a sensitive sink. Security review starts by locating these boundaries.
How can an integer computation become a memory-safety bug?	A size like `count * elem` can overflow `size_t` to a small value, so `malloc(count*elem)` under-allocates and the following loop overflows the heap. Look for size arithmetic on untrusted counts with no overflow guard (`count > SIZE_MAX/elem`).
How do you spot a missing bounds check in a copy/index loop?	Find loops that index or copy using a count or index derived from input, then check whether that value is validated against the destination's capacity before the loop runs. An attacker-influenced index with no `< size` guard is an out-of-bounds read or write.
Why is a signed length compared with `<` against a max dangerous?	If `len` is signed and attacker-supplied negative, `len < MAX` passes, but when `len` is later used as an unsigned size (e.g. `memcpy`'s `size_t` parameter), the negative becomes a huge value — a bounds-check bypass. Use unsigned types and check both ends.
What should you check around privilege-sensitive calls like `setuid`/`system`/`exec*`?	Whether their return values and preconditions are honored: an ignored `setuid` failure means privileges were not dropped; `system`/`popen` with untrusted data invites command injection; `exec*` with an attacker-controlled `PATH` runs the wrong binary. Each is a privilege-escalation vector if mishandled.
How do you spot a potential use-after-free while reading code?	Find where a pointer is `free`d and then check whether any alias (another pointer, a stored field, a container entry) still references that memory and is later used. A freed block reachable through a second pointer is a use-after-free waiting to happen.
What is an information-disclosure pattern to watch for?	A buffer or struct sent/returned to a caller without being fully initialized — padding bytes or unfilled tail bytes leak stale stack/heap data (keys, other users' data). `memset` before filling, or serialize field-by-field.
How do you tell a benign copy from a risky manual reimplementation of `strcpy`/`memcpy`?	A hand-rolled `while (*d++ = *s++);` or index loop copies with no bound and no care for the terminator or destination size — the same danger as `strcpy`. A benign copy checks the destination capacity and respects the terminator.
How does a stack-buffer-overflow snippet map to "overwrite the return address"?	On a typical frame the return address and saved frame pointer sit above the local buffers; an unbounded write into a local array climbs into them, so on return control jumps to an attacker-chosen address. Recognizing this is the core of reading stack-smash code.
