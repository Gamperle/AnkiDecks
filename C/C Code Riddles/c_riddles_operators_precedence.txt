# Predict-the-output riddles on operator precedence traps, sequence points, and macro expansion pitfalls.

# 1. Precedence Traps
What does this print? `printf("%d", 5 & 3 == 3);`	`1` — surprising if you expected `(5 & 3) == 3` (which would be `0`). `==` actually binds *tighter* than `&`, so this parses as `5 & (3 == 3)`, i.e. `5 & 1` = `1`. Bitwise operators binding looser than comparisons is one of C's oldest traps — parenthesize whenever you mix them.
What does this print? `int x = 1, y = 2; printf("%d", (x, y));`	`2` — the comma *operator* evaluates its left side purely for its side effects, throws the result away, and the whole expression takes the value of the right side. (This is different from the comma that separates function arguments, which doesn't discard or sequence anything.)
What does this print? `printf("%f", 1 ? 1 : 2.0);`	`1.000000` — even though the condition picks the `int` branch, the *type* of a `?:` expression is decided by combining both branches' types before anything runs. `int` and `double` combine to `double`, so the whole expression is `double`, and the chosen value `1` gets converted to `1.0`.
What does this print? `int a = 5; if (a = 0) printf("true"); else printf("false: a=%d", a);`	`false: a=0` — `=` assigns, it doesn't compare. `a = 0` sets `a` to `0`, and the assignment itself evaluates to `0` (falsy), so the `else` branch runs — and `a` has been overwritten as a side effect of the typo. Writing `0 == a` instead ("Yoda style") turns this exact mistake into a compile error rather than a silent bug.
What does this print? `printf("%d", !!5);`	`1` — `!5` is `0` (5 is truthy, so negating it gives false), and negating again, `!0`, gives `1`. Double negation (`!!x`) is a common idiom for squashing any nonzero value down to exactly `1`.

# 2. Sequencing (Undefined in C — Contrast with Java!)
What does this print? `int i = 1; int r = i++ + i++; printf("%d %d", r, i);`	Undefined behavior. Nothing in the standard says which `i++` has to happen first, because both modify the same variable with no rule forcing an order between them. This is a genuine difference from Java, where the equivalent expression is fully specified (left side first, always) and gives the same answer on every run.
What does this print? `int a[3] = {0}; int i = 0; a[i] = i++;`	Undefined behavior. Whether the index `i` on the left is read before or after the increment on the right isn't defined by the standard, so which array element actually gets written — and with what value — can differ between compilers or optimization levels.
What happens here? `int x = 0; if (x != 0 && 10 / x > 1) { ... }`	No crash, no UB. `&&` short-circuits: since `x != 0` is false, C guarantees the right-hand side `10 / x` is never even evaluated. (Plain `&`, unlike `&&`, does *not* short-circuit — this guard pattern only works with the logical operators.)

# 3. Macro Pitfalls
What does this print? `#define SQUARE(x) x*x` then `printf("%d", SQUARE(1+2));`	`5`, not `9`. Macros are pure text substitution, so `SQUARE(1+2)` literally becomes `1+2*1+2`. With normal precedence (`*` before `+`), that's `1 + 2 + 2 = 5`. The fix is parenthesizing everything: `#define SQUARE(x) ((x)*(x))`.
What does this print? `#define MAX(a,b) ((a)>(b)?(a):(b)) int i=5, j=3; printf("%d %d", MAX(i++, j++), i);`	Undefined/surprising: since `i > j`, the "then" branch of the ternary is selected — but that branch is *another* copy of `i++`, separate from the one already evaluated inside the comparison. So `i` gets incremented twice by this one `MAX(...)` call, not once. This happens because a macro parameter used more than once in the expansion gets *evaluated* more than once — unlike a real function argument, which is only ever evaluated a single time.
What does this print? `#define N 5+1 printf("%d", 10 * N);`	`51`, not `60`. The macro's replacement text is substituted literally, with no protective parentheses, so `10 * N` becomes `10 * 5 + 1` = `51`. Always wrap a macro's whole body in parentheses: `#define N (5+1)`.
