# Predict-the-output riddles on pointer arithmetic, array decay, and pointer/array equivalence quirks.

# 1. sizeof, Decay & Arithmetic
What does this print? `int arr[5]; printf("%zu", sizeof(arr));` (in the same scope as the declaration)	`20` — inside the scope where `arr` is a true array (not a parameter), `sizeof` reports the *whole array's* size (5 elements × 4 bytes).
What does this print? `void f(int arr[5]) { printf("%zu", sizeof(arr)); } int main(){ int a[5]={0}; f(a); }`	`8` (or `4` on a 32-bit platform) — a function parameter declared `int arr[5]` is really just `int *arr`; arrays always decay to a pointer when passed to a function, so `sizeof(arr)` inside `f` reports the *pointer's* size, silently losing the "5" entirely.
What does this print? `int a[3] = {1,2,3}; int *p = a; printf("%d", *(p+1));`	`2` — pointer arithmetic is scaled by the pointed-to type's size automatically: `p+1` moves forward by `sizeof(int)` bytes, i.e. one element, landing on `a[1]`.
Does this compile, and what does it print? `int a[5] = {10,20,30,40,50}; printf("%d", 2[a]);`	Compiles and prints `30` — `a[i]` is defined as `*(a + i)`, and pointer addition is commutative, so `2[a]` means `*(2 + a)`, which is identical to `*(a + 2)` = `a[2]`. Legal C, but write `a[2]` — nobody should actually use this.
What does this print? `int a[2][3] = {{1,2,3},{4,5,6}}; printf("%d", a[1][0] - a[0][0]);`	`3` — 2D arrays are laid out row-major (contiguous), so `a[1][0]` sits exactly one full row (3 `int`s) after `a[0][0]` in memory; the pointer/index difference equals the row width.
What does this print? `void mod(int a[]) { a[0] = 99; } int main(){ int arr[3]={1,2,3}; mod(arr); printf("%d", arr[0]); }`	`99` — despite C's "everything is passed by value" rule, arrays decay to a pointer *value* when passed, and that pointer still points at the caller's original storage. So mutations through it are visible to the caller — there is no true pass-by-value for arrays in C, only for the pointer that represents them.

# 2. Lifetime & Undefined Behavior
What happens here? `char *s = "hello"; s[0] = 'H'; printf("%s", s);`	Undefined behavior — string literals have static storage duration and are commonly placed in read-only memory by the linker; writing through `s` may segfault immediately, silently corrupt something else, or (on some old/embedded toolchains) "work". Always use `const char *` for literals, or copy into a mutable `char[]` if you need to modify it.
What happens here? `int *p; { int x = 5; p = &x; } printf("%d", *p);`	Undefined behavior — `x`'s automatic storage duration ends when its enclosing block `{ }` exits, well before the `printf`. `p` is now dangling; dereferencing it might print 5 "by luck" (the stack slot hasn't been reused yet) or crash or print garbage — nothing is guaranteed.
What happens here? `int *f(void) { int x = 42; return &x; }` then the caller dereferences the returned pointer.	Undefined behavior for the same reason: `x` is a local with automatic storage duration, and its address becomes dangling the instant `f` returns. Most compilers emit a "returning address of local variable" warning here — never ignore it.
What happens here? `int a[3] = {1,2,3}; int *p = a + 3; printf("%d", *p);`	Undefined behavior, but subtly: `a + 3` (one past the last element) is a *valid pointer value* to compute and compare — the standard explicitly allows a one-past-the-end pointer to exist. What's UB is *dereferencing* it, since `a[3]` doesn't exist. The riddle: computing the pointer is fine; reading through it is not.
What happens here? `char *p = NULL; p += 5; printf("%p", (void*)p);`	Undefined behavior — pointer arithmetic is only defined relative to an actual array object (or one past its end); a null pointer doesn't point into any object, so adding to it is UB even though most implementations will happily compute "address 5" and print it without complaint.
What happens here? `int a, b; int *p = &a, *q = &b; if (p < q) printf("less");`	Undefined behavior — `p` and `q` point into two unrelated objects (not the same array), and ordering comparisons (`<`, `>`, `<=`, `>=`) between pointers into different objects are UB. In practice it "just compares addresses" on nearly every real system, printing something, but the standard makes no guarantee — only `==`/`!=` between arbitrary pointers, or ordering *within the same array*, is well-defined.
