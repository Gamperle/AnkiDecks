# 4.6 Toolchain, Debugging, Testing & Analysis
What do the `-O` optimization levels mean in gcc/clang?	`-O0` none (fast compile, best debugging), `-O1`/`-O2` progressively more optimization, `-O3` aggressive (may grow code), `-Os` optimize for size, `-Ofast` `-O3` plus non-conforming fast math. Combine with `-g` for debug info; `-Wall -Wextra -Werror` turns warnings into build-blocking errors.
How do you inspect compiler output and binaries?	`gcc -E` shows preprocessed source, `-S` shows assembly. On binaries: `objdump -d` disassembles, `nm` lists symbols, `readelf` dumps ELF headers/sections, `strings` finds embedded text, and `ldd` shows shared-library dependencies.
What can you do with gdb/lldb?	Set breakpoints and watchpoints (stop when a variable changes), single-step, inspect the call stack with backtraces, examine and modify variables/memory, and load a core dump to diagnose a crash after the fact. Compile with `-g` for source-level debugging.
What runtime memory/UB errors do the sanitizers and Valgrind catch?	AddressSanitizer: heap/stack/global overflows, use-after-free, double-free. UBSan: signed overflow, bad shifts, misalignment. ThreadSanitizer: data races. MemorySanitizer: uninitialized reads. LeakSanitizer: leaks. Valgrind's memcheck catches many of these by interpretation (no recompile). Run your tests under them.
What is the difference between static and dynamic analysis tools?	Static analysis (`clang-tidy`, `cppcheck`, `scan-build`, Coverity) inspects source without running it, flagging suspicious patterns and possible UB across all paths. Dynamic analysis (Valgrind, sanitizers) observes an actual run, catching real errors on exercised paths. They complement each other.
When and why would you fuzz C code?	When it parses untrusted input (file formats, network protocols). A fuzzer (libFuzzer, AFL++) generates and mutates inputs against a small harness, running under sanitizers to surface crashes, hangs, and memory-safety bugs that hand-written tests miss.
What C unit-testing frameworks exist?	Unity (tiny, embedded-friendly), CMocka (with mocking support), Check (fork-isolated tests), and Criterion (modern, auto-registered tests). At minimum, assertion-based tests with `assert`-style macros in a test binary catch regressions.
What do profilers like `perf`, `gprof`, and cachegrind tell you?	`perf` samples where CPU time and cache misses/branch mispredictions occur (low overhead, whole-system). `gprof` gives call-graph timing from instrumented builds. cachegrind (Valgrind) simulates the cache to pinpoint cache-unfriendly code. Use them to find real hot paths before optimizing.
What build and packaging tools are common for C?	Make (classic dependency-driven builds), CMake and Meson (portable build-system generators), autotools (`./configure`), and `pkg-config` (discovering library flags). Cross-compilation toolchains build for a different target architecture than the host.


# 4.7 Compiler Extensions & Inline Assembly
What common GCC/Clang `__attribute__`s should you know?	`packed`/`aligned` (layout), `noreturn` (function never returns), `deprecated`, `always_inline`, `constructor`/`destructor` (run before/after `main`), `format(printf,...)` (enable format checking on your own functions), `cleanup` (run a function when a variable leaves scope), and `warn_unused_result`.
What are the MSVC counterparts to GCC attributes?	`__declspec(...)` (e.g. `__declspec(noreturn)`, `dllexport`/`dllimport`, `align`) and MSVC-specific `#pragma`s (like `#pragma pack`) and intrinsics. Portable code hides these behind macros selected by compiler-detection `#if`s.
What do the common compiler builtins do?	`__builtin_expect(cond, expected)` hints branch likelihood; `__builtin_unreachable()` marks impossible code for optimization; `__builtin_*_overflow` do checked arithmetic; `__builtin_types_compatible_p` and `__builtin_offsetof` support generic macros. They give access to hardware/optimizer features from C.
What are SIMD intrinsics and vector extensions?	Intrinsics like those in `<immintrin.h>` map to CPU SIMD instructions (SSE/AVX/NEON) to process multiple data lanes per instruction, and GCC's `vector_size` attribute defines portable vector types. They accelerate data-parallel loops (image, audio, math) beyond what auto-vectorization achieves.
What is inline assembly, and what are its extended-syntax parts?	`asm`/`__asm__` embeds assembly in C. Extended GCC syntax specifies output operands, input operands, and a clobber list (registers/memory the code modifies) with constraints binding them to C variables, so the compiler schedules around it correctly. Used for privileged instructions and micro-optimizations.
What are some useful pragmas?	`#pragma once` (include-guard shortcut), `#pragma GCC diagnostic push`/`ignored "-Wxxx"` (locally suppress a warning and restore it), and `#pragma pack(n)` (set struct packing/alignment). They give per-region control the command-line flags can't.
What are statement expressions and other common GNU C extensions?	A statement expression `({ int t = a; t*t; })` lets a block yield a value — used to write safe macros with local temporaries. Other GNU extensions include `typeof`, case ranges (`case 1 ... 5:`), and zero-length arrays. They are non-standard, so guard them for portability.


# 4.8 Custom Memory Management
What is an arena (region) allocator?	An allocator that hands out memory by bumping a pointer through a large pre-allocated block, with no per-object free — you free the whole arena at once. Extremely fast and fragmentation-free, ideal when many objects share a lifetime (per-request, per-frame).
What is an object pool / free list?	A pre-allocated set of fixed-size slots linked in a free list; allocation pops a slot and free pushes it back — both O(1) with no fragmentation. Ideal for frequently created/destroyed same-size objects and for deterministic embedded/real-time allocation.
What is slab allocation?	A kernel-style scheme (Linux slab/slub) that keeps caches of pre-initialized objects of a given type/size, so allocation avoids repeated construction and reduces fragmentation. Objects are grouped in "slabs" of pages per size class.
Why is `alloca` dangerous?	`alloca(n)` allocates on the stack and is auto-freed at return, but it has no failure indication — a large or attacker-controlled `n` silently overflows the stack (crash/exploit), and its interaction with inlining/loops is subtle. Prefer a bounded VLA or `malloc`.
How do you allocate aligned memory for SIMD/DMA?	Use `aligned_alloc(alignment, size)` (C11) or `posix_memalign`, or over-allocate and round the pointer up to the required boundary yourself (storing the original for `free`). Alignment matters for SIMD loads/stores and DMA engines that require aligned buffers.
What are `malloc` internals worth knowing?	Allocators (e.g. glibc) split memory into chunks tracked by size-class bins and use per-thread arenas to reduce lock contention. Understanding chunk headers, bins, and how freed blocks coalesce explains fragmentation, performance, and heap-exploitation techniques.
How can you replace the memory allocator?	Link against a different allocator like jemalloc or tcmalloc (better multithreaded performance/fragmentation), or use `LD_PRELOAD`/allocator hooks to interpose `malloc`/`free` at runtime — useful for profiling, debugging, or tuning without changing source.
What are ownership and lifetime conventions in C APIs?	Since C has no automatic memory management, an API must document who allocates and who frees each object (e.g. "caller must `free` the returned buffer"). Patterns include caller-owns, callee-owns, and reference counting to share objects with a tracked lifetime.


# 4.9 Secure Coding Standards & Hardening
What is the CERT C Secure Coding Standard?	A set of rules and recommendations for secure C grouped by topic — INT (integers), STR (strings), MEM (memory), FIO (file I/O), ERR (error handling), etc. — each pairing a risky pattern with its compliant fix. Widely used as a checklist and for static-analysis rulesets.
What is MISRA-C and where is it used?	A coding standard for safety-critical/embedded systems (automotive, medical, aerospace) that restricts C to a safer, analyzable subset: no (or controlled) dynamic memory, no recursion, no reliance on undefined/unspecified behavior, strong typing, and single-exit rules.
How do common C vulnerability classes map to CWE IDs?	CWE-119/787/125 = out-of-bounds write/read (buffer errors), CWE-416 = use-after-free, CWE-190 = integer overflow/wraparound, CWE-78 = OS command injection, CWE-134 = uncontrolled format string, CWE-476 = null pointer dereference. These dominate the CWE Top 25 for C programs.
What is the first step in threat-modeling a C program?	Identify the trust boundaries and attack surface — every place untrusted input enters (argv, files, network, environment, IPC) — then trace each input to its sinks (allocation sizes, indices, format strings, command strings, paths) and ensure validation happens before use. Mitigations layer on top of validation, not instead of it.
Which compiler/linker hardening flags should you enable?	`-fstack-protector-strong` (canaries), `-D_FORTIFY_SOURCE=2/3` (buffer-size checks), `-fPIE -pie` (ASLR for the executable), `-Wl,-z,relro,-z,now` (read-only GOT), and `-Wformat -Wformat-security -Wall -Wextra`. Run `-fsanitize=address,undefined` in CI.
What hardware-assisted control-flow protections exist?	Shadow stacks and indirect-branch tracking via Intel CET, pointer authentication (ARM PAC) that signs return addresses/pointers, and branch-target identification (ARM BTI). They enforce control-flow integrity in hardware, making ROP/JOP and return-address overwrites much harder.
What runtime mechanisms enforce least privilege on Linux?	`seccomp` filters restrict which syscalls a process may make; Linux capabilities split root's powers into droppable fine-grained bits; explicit privilege dropping (`setuid`/`setgid` to an unprivileged user after setup); and namespaces/sandboxes isolate the process — limiting the blast radius of an exploit.
What are safer-by-construction patterns to avoid raw pointer+length bugs?	Carry a buffer's size with it — a "fat pointer"/slice struct `{ ptr, len }` passed as one unit — so length is never separated from the data, and use bounds-checked accessors. Compiler options like `-fbounds-safety` enforce this, eliminating whole classes of overflow.


# 4.10 Performance & Micro-Optimization
Why do cache misses dominate performance more than raw instruction count?	Modern CPUs execute instructions in ~1 ns but a main-memory access takes ~100 ns. A loop chasing linked-list pointers spends most of its time stalling on cache misses. Keeping data in L1/L2 cache is the single biggest performance lever.
What is spatial locality and why should C arrays be traversed row-major?	Spatial locality means accessing addresses close together lets the CPU prefetch cache lines. A C 2D array a[R][C] is stored row-major — iterating a[i][j] by incrementing j is sequential. Column-first traversal (a[j][i]) jumps by C*sizeof(a[0][0]) bytes per step, causing cache misses.
What does restrict tell the compiler and how does it improve performance?	restrict on a pointer parameter promises no other pointer in the function aliases the same memory. This lets the compiler eliminate redundant loads and enables auto-vectorization of loops that would otherwise be blocked by potential aliasing.
What is __builtin_expect and when should you use it?	__builtin_expect(cond, likely_value) hints which path is taken most often, letting the compiler lay out code so the common path has no branch jump. Use it for error checks that almost never fire (e.g. __builtin_expect(ptr != NULL, 1)).
What is profile-guided optimization (PGO)?	Compile with -fprofile-generate, run representative workloads to record branch frequencies and call counts, then recompile with -fprofile-use. The compiler inlines hot functions and reorganizes cold/hot paths — yielding 10–30% speedups on real programs.
What is false sharing and how do you fix it?	Two threads update different variables that share a 64-byte cache line. Every write by one core invalidates the line on the other, forcing a coherence roundtrip — performance collapses despite no logical sharing. Fix: pad or align per-thread hot variables to separate cache lines with alignas(64).
When does loop unrolling help vs hurt?	Unrolling reduces loop-overhead instructions and enables better scheduling. It hurts when the expanded body exceeds the I-cache window, causing instruction-cache misses. Profile before unrolling manually; compilers do it automatically at -O2/-O3.
What does perf stat measure and what are key counters to watch?	perf stat ./program reports task-clock (wall time), cache-misses (last-level cache), branch-misses (mispredictions), instructions, and cycles. Derived IPC (instructions per cycle) < 1 suggests cache-bound or misprediction-bound execution; near 3–4 suggests compute-bound.
