# 1.1 Variables, Types & Expressions
What are C's primitive integer and floating types?	Integers: `char`, `short`, `int`, `long`, `long long`, each `signed` or `unsigned`. Floats: `float`, `double`, `long double`. The standard fixes only minimum widths (e.g. `int` ≥ 16 bits, `long` ≥ 32, `long long` ≥ 64); exact sizes are platform-dependent.
What does `unsigned` change about an integer type?	It removes the sign bit, so the type holds only non-negative values but twice the positive range (e.g. `unsigned char` is 0–255 vs `signed char` −128–127). Unsigned arithmetic wraps modulo 2^N and never overflows in the UB sense.
What are the "usual arithmetic conversions" / integer promotions?	Before most binary operators, operands narrower than `int` are promoted to `int` (or `unsigned int`), then both operands are converted to a common type. This is why `char a=200,b=100; a+b` is computed in `int` and does not overflow at char width.
What is the difference between signed and unsigned overflow behavior?	Unsigned overflow is defined: it wraps modulo 2^N. Signed overflow is undefined behavior — the compiler may assume it never happens and optimize on that basis. So `INT_MAX+1` is UB but `UINT_MAX+1u` is defined as 0.
Why can mixing `int` and `unsigned int` in one expression be a pitfall?	The signed operand is converted to unsigned, so a negative value becomes a huge positive one. `-1 < 0u` is false because `-1` becomes `UINT_MAX`. Comparisons and arithmetic mixing signedness are a classic bug source.
What does the `sizeof` operator give, and why does it vary by platform?	`sizeof x` yields the size of `x` in bytes as a `size_t`. Because `int`/`long`/pointer widths differ across platforms and ABIs, `sizeof(long)` may be 4 or 8. Use `<stdint.h>` fixed-width types when an exact size is required.
What are the fixed-width types in `<stdint.h>` for?	Types like `int32_t`, `uint8_t`, `int64_t` guarantee an exact width and signedness on every platform, unlike `int`/`long`. Use them for file formats, network protocols, hardware registers, and any code where representation must be portable.
What is the difference between `#define`, `const`, and `enum` constants?	`#define N 10` is an untyped, unscoped text macro. `const int n = 10;` is a typed, scoped variable (may take storage, has an address). `enum { N = 10 };` is a scoped named `int` constant with no storage. Prefer `const`/`enum` for typed constants.
What does `typedef` do, and what is a downside of typedef'ing pointers?	It creates an alias for an existing type (`typedef unsigned long ulong;`) — not a new distinct type. Hiding a pointer behind a typedef (`typedef struct S *Handle;`) can improve encapsulation but obscures that the value is a pointer, hurting `const`-correctness and readability.
What do integer and floating-point literal suffixes mean?	Integer suffixes set the type: `u`(unsigned), `l`(long), `ul`, `ll`(long long). Bases: `0x` hex, leading `0` octal (`010`==8!), `0b` binary (GNU/C23). Float suffixes: `f`(float), `l`(long double); no suffix is `double`.
What is the difference between `'a'` and `"a"`?	`'a'` is a character constant of type `int` in C (value 97), a single value. `"a"` is a string literal: a `char[2]` array holding `'a'` and a terminating `'\0'`. They are not interchangeable.
What is a compound literal?	An unnamed object created inline as `(type){ initializers }`, e.g. `(int[]){1,2,3}` or `(struct Point){.x=1}`. It has automatic (block) storage duration unless at file scope, and can be passed directly to a function expecting that type.
What is the difference between an lvalue and an rvalue?	An lvalue names an object with a location and can appear on the left of `=` (a variable, `*p`, `arr[i]`). An rvalue is just a value (`3`, `a+b`) and cannot be assigned to; `a+b = 5;` is an error.
Why is `if (x = 0)` almost always a bug?	`=` assigns, so `x = 0` sets `x` to 0 and evaluates to 0 (false) — the branch never runs and `x` is clobbered. The intended `if (x == 0)` compares. "Yoda" style `if (0 == x)` turns the typo into a compile error.
How does short-circuit evaluation of `&&` and `||` work?	`&&` stops and yields 0 at the first false operand; `||` stops and yields 1 at the first true operand. The right side is not evaluated if the result is already known, enabling guards like `if (p && p->x)`.
What is the difference between the comma operator and a comma separator?	The comma *operator* evaluates its left operand, discards it, and yields the right (`a = (b, c)` assigns `c`). A comma *separator* between function arguments or declarators is not the operator — `f(a, b)` passes two arguments, it does not sequence them.
What is the type of a ternary expression `cond ? a : b`?	The common type of `a` and `b` after the usual conversions, regardless of which branch runs. A common misuse: `cond ? 1 : "x"` mixes incompatible types, and mixing signed/unsigned or int/double in the two arms silently converts the result.
What is the difference between `*p++` and `(*p)++`?	`*p++` is `*(p++)`: dereference `p`, then increment the pointer `p`. `(*p)++` dereferences `p` and increments the pointed-to value, leaving `p` unchanged. The precedence of postfix `++` over unary `*` is the reason.
Why does `a & b == c` not do what it looks like?	`==` has higher precedence than `&`, so it parses as `a & (b == c)`. To test bits you must write `(a & b) == c`. Bitwise operators binding looser than comparison is one of C's most notorious precedence traps.
How do you set, clear, toggle, and test a single bit?	Set: `x |= (1u << n)`. Clear: `x &= ~(1u << n)`. Toggle: `x ^= (1u << n)`. Test: `if (x & (1u << n))`. The bitwise operators are `&` AND, `|` OR, `^` XOR, `~` NOT, `<<`/`>>` shifts.
Is `sizeof` evaluated at compile time or run time, and is its operand executed?	Compile time for everything except variable-length arrays (whose size is computed at run time). The operand is not evaluated: `sizeof(i++)` yields the size and does not increment `i`.


# 1.2 Storage Classes, Scope & Lifetime
What are C's storage-class specifiers?	`auto` (default for locals, automatic storage), `register` (hint, address cannot be taken), `static` (static storage / internal linkage), `extern` (declaration referring to a definition elsewhere), and `_Thread_local` (one instance per thread).
What is the difference between block, file, and function-prototype scope?	Block scope: visible inside the enclosing `{}` (locals). File scope: visible from declaration to end of the translation unit (globals). Function-prototype scope: parameter names in a prototype, visible only within that declaration.
What are the four storage durations in C?	Automatic (locals — exist during their block), static (whole program run), thread (whole life of a thread, C11 `_Thread_local`), and allocated (from `malloc` until `free`). Duration is about lifetime, distinct from scope (visibility).
What does `static` on a local variable do?	It gives the variable static storage duration: a single instance, initialized once (to zero if no initializer), that retains its value across calls. `int next(void){ static int n=0; return ++n; }` returns 1, 2, 3, ….
What is the difference between `static` and `extern` at file scope?	`static` gives internal linkage — the name is private to its translation unit. `extern` declares a name defined in another translation unit (external linkage), letting you reference a shared global/function without redefining it.
Are uninitialized variables zeroed in C?	Only objects with static or thread storage duration (globals, `static` locals) are zero-initialized. Automatic (local) variables are not — they contain indeterminate garbage, and reading them is undefined behavior.
How can a variable's lifetime differ from its scope?	A `static` local is in scope only inside its block (you can only name it there) but has a lifetime spanning the whole program run. So it keeps its value between calls even though it is not visible elsewhere.
What does the `register` storage class do today?	It is a hint that a variable is used heavily; modern optimizing compilers ignore it for register allocation. Its one remaining semantic effect: you may not take the address (`&`) of a `register` variable.


# 1.3 Pointers & Memory
Are `int *p`, `int* p`, and `int * p` different declarations?	No — whitespace is irrelevant; all three declare a pointer to `int`. Beware `int* a, b;`: only `a` is a pointer, `b` is a plain `int`, because `*` binds to the declarator, not the type.
How far does `p + 1` move a pointer?	By `sizeof(*p)` bytes — one element of the pointed-to type, not one byte. For `int *p` with 4-byte ints, `p + 1` is 4 bytes further. All pointer arithmetic is in units of the element type.
What happens when you dereference a `NULL` pointer?	Undefined behavior. In practice it usually faults (crash), but the standard guarantees nothing and the optimizer may assume it cannot happen. Always check pointers that might be null before dereferencing.
What is a pointer to a pointer used for?	`int **pp` holds the address of a pointer. Uses: output parameters that must modify the caller's pointer (`bool alloc(int **out)`), arrays of pointers (`char *argv[]`, i.e. `char **`), and mutating linked structures.
Explain `const int *p` vs `int * const p` vs `const int * const p`.	`const int *p`: pointer to const int — cannot change `*p`, can repoint `p`. `int * const p`: const pointer to int — can change `*p`, cannot repoint. `const int * const p`: neither changeable. Read right-to-left.
What is array-to-pointer decay?	In most expressions an array name is implicitly converted to a pointer to its first element (`arr` → `&arr[0]`). This is why a parameter `int a[]` is really `int *a`. Exceptions: operands of `sizeof`, `&`, and string-literal initialization.
Is there any difference between `array[i]`, `*(array + i)`, and `i[array]`?	No — `array[i]` is defined as `*(array + i)`, and since addition commutes, `i[array]` is equivalent (though obscure). `array[i]` is the conventional readable form.
What is the difference between stack and heap allocation?	Stack: automatic variables, allocated/freed automatically as functions enter/exit, fast, limited size. Heap: `malloc`/`free`, manually managed, larger, lives until explicitly freed. Forgetting to `free` heap memory leaks it; using stack memory after return dangles.
What is a dangling pointer?	A pointer to memory that is no longer valid — after `free(p)`, or a pointer to a local variable whose function has returned. Dereferencing it is undefined behavior. Setting freed pointers to `NULL` makes accidental reuse fail loudly.
What is a memory leak?	Heap memory that was allocated but never freed and is no longer reachable, so it cannot be reclaimed while the program runs. Repeated leaks exhaust memory. Every `malloc` needs a matching `free` on all paths.
Why must a `void *` be converted before dereferencing?	`void *` has no element type, so it has no size for arithmetic or dereference. Convert it to a concrete pointer first: `int *ip = vp; *ip = 5;`. The conversion is implicit in C, but requires a cast in C++.
Is an uninitialized pointer the same as a NULL pointer?	No. `int *p;` holds indeterminate garbage; dereferencing is UB and may not crash. Only `int *p = NULL;` is guaranteed null. Initialize pointers to `NULL` when you cannot give them a valid target immediately.
What is the difference between pointer identity and the objects pointed to?	Two pointers can be equal (same address, same object) or unequal yet point to equal *values*. `p == q` compares addresses; comparing what they point at needs dereferencing (`*p == *q`) or `strcmp`/`memcmp` for aggregates.


# 1.4 Arrays & Strings
How are partially-initialized arrays filled?	Elements you do not explicitly initialize are zero-initialized. `int a[5] = {1,2};` gives `{1,2,0,0,0}`; `int a[100] = {0};` zeroes the whole array.
What are designated array initializers?	Initializing specific elements by index: `int a[10] = {[0]=1, [9]=5};` sets those two and zeroes the rest. Order-independent and useful for sparse or lookup-table arrays.
How is a 2D array `int m[3][4]` laid out in memory?	Row-major: all of row 0's four ints, then row 1's, then row 2's — contiguous. `m[i][j]` is at offset `i*4 + j` ints. Iterating with the last index innermost is cache-friendly.
What is the difference between `char *argv[]` and `char (*p)[N]`?	`char *argv[]` is an array of pointers to char (each element a separate string). `char (*p)[N]` is a pointer to an array of N chars (one contiguous block). The parentheses change binding entirely.
What is a variable-length array (VLA), and what is its risk?	An array whose size is a runtime value: `void f(int n){ int a[n]; }` (C99; optional since C11). It lives on the stack, so a large or attacker-controlled `n` can overflow the stack. Prefer `malloc` for big or untrusted sizes.
Why do C strings need a `\0` terminator?	C tracks no separate length; functions like `strlen`, `printf %s`, and `strcpy` scan until they hit the `\0` byte. A missing terminator makes them read past the buffer — a common crash and security bug.
Where are string literals stored, and can they be shared?	In read-only (static) memory; identical literals may be pooled to the same address. Writing through `char *s = "hi"; s[0]='H';` is undefined behavior. Use `const char *` for literals so writes are caught at compile time.
What is the difference between `char buf[] = "hi";` and `char *p = "hi";`?	`char buf[]` creates a modifiable local array (3 bytes here) that you own and can write. `char *p` points at a read-only literal; writing through it is UB. Use the array form when you need a mutable string.
What happens to an array's size information when passed to a function?	The array decays to a pointer, so the parameter is a pointer and the size is lost. You must pass the length separately (`void f(int *a, size_t n)`); `sizeof` inside the function gives the pointer size, not the array's.
When does `sizeof` give the array size vs the pointer size?	It gives the true byte size only where the array is a real array in scope (`int a[10]; sizeof a` == 40). Once the array has decayed to a pointer (e.g. a function parameter), `sizeof` gives the pointer's size instead.
What does `argv[argc]` equal in `main`?	It is guaranteed to be a `NULL` pointer. `argv` holds `argc` string pointers followed by a null terminator, so you can loop with an index up to `argc` or walk until you reach `NULL`.
Why does iteration order matter for `arr[i][j]` vs `arr[j][i]`?	Because 2D arrays are row-major, walking with the last index fastest (`arr[i][j]` inner loop over `j`) touches contiguous memory and is cache-friendly; swapping to `arr[j][i]` strides across rows, causing cache misses and slower loops.
How are wide characters and UTF-8 handled in C?	`wchar_t` and `L"..."` literals with `<wchar.h>` provide wide characters (width is platform-dependent). UTF-8 text is just bytes and is stored in ordinary `char[]`; multibyte handling needs care, but no special type is required for storage.
