# 2.1 <stdio.h> — I/O Functions
What is the difference between `printf`, `fprintf`, `sprintf`, and `snprintf`?	`printf` writes to `stdout`; `fprintf` to a given `FILE*`; `sprintf` into a `char` buffer with no size limit (overflow-prone); `snprintf(buf, size, ...)` into a buffer capped at `size` bytes and always null-terminated. Prefer `snprintf` for fixed buffers.
What do `scanf`, `fscanf`, and `sscanf` read from?	`scanf` reads formatted input from `stdin`, `fscanf` from a `FILE*`, and `sscanf` from a string. All return the number of items successfully assigned (or `EOF`); always check that count, and bound `%s` fields (e.g. `%31s`) to avoid overflow.
What do `fopen`, `fclose`, and `freopen` do, and what do mode strings mean?	`fopen(path, mode)` opens a stream (`NULL` on failure), `fclose` flushes and closes it, `freopen` reopens a stream on a new file (e.g. redirecting `stdout`). Modes: `"r"` read, `"w"` truncate/create, `"a"` append, `"r+"` update; add `"b"` for binary.
What are `fread` and `fwrite` for?	Binary I/O of raw bytes/records: `fread(ptr, size, count, fp)` reads up to `count` elements of `size` bytes and returns how many were read; `fwrite` writes them. Use them (with `"rb"`/`"wb"`) for non-text data and check the returned element count.
What is the difference between `fgets` and `fputs`?	`fgets(buf, n, fp)` reads at most `n-1` chars (stopping at newline or EOF) and null-terminates — a bounds-safe line reader. `fputs(s, fp)` writes a string without adding a newline. Prefer `fgets` over `gets`, which has no bound.
What do `fgetc`, `fputc`, and `ungetc` do?	`fgetc(fp)` reads one character (returns an `int`, `EOF` at end), `fputc(c, fp)` writes one, and `ungetc(c, fp)` pushes one character back onto the stream so the next read returns it — useful for one-character lookahead in parsers.
What do `fseek`, `ftell`, `rewind`, `fgetpos`, and `fsetpos` do?	They manage the file position: `fseek(fp, off, whence)` moves it (`SEEK_SET`/`CUR`/`END`), `ftell` reports it, `rewind` resets to the start. `fgetpos`/`fsetpos` save/restore a position portably (for large files where `long` may be too small).
What do `feof`, `ferror`, and `clearerr` report?	`feof(fp)` is true only after a read has already hit end-of-file; `ferror(fp)` is true after a stream error; `clearerr(fp)` resets both flags. Note `feof` becomes true *after* the failed read, so drive loops by the read's return value, not `feof`.
What are `tmpfile` and `tmpnam`, and why is one safer?	`tmpfile()` creates and opens an auto-deleted temporary file atomically (safe). `tmpnam()` only generates a name, leaving a TOCTOU race between naming and creation that a symlink attack can exploit — prefer `tmpfile` or POSIX `mkstemp`.
What does `perror` do?	`perror("prefix")` prints your prefix, a colon, and the human-readable message for the current `errno` to `stderr` (e.g. `open: No such file or directory`). Call it immediately after a failing library call, before `errno` is overwritten.
What do `remove` and `rename` do?	`remove(path)` deletes a file (or empty directory) and `rename(old, new)` renames/moves one, both returning 0 on success and non-zero on failure. Check the return value; `rename` across filesystems may fail with `EXDEV`.
What do `setvbuf` and `setbuf` control?	Stream buffering: `setvbuf(fp, buf, mode, size)` selects full (`_IOFBF`), line (`_IOLBF`), or no (`_IONBF`) buffering and an optional buffer; `setbuf` is a simpler on/off form. Set it before any I/O on the stream.
What does `fflush` do, and what is its non-portable use?	`fflush(fp)` forces buffered output to be written to the underlying file/device. `fflush(NULL)` flushes all output streams. Calling `fflush` on an *input* stream is undefined by the standard (though some libcs extend it) — don't rely on it.
What does POSIX `getline` offer over `fgets`?	`getline(&buf, &cap, fp)` reads a whole line into a `malloc`/`realloc`-grown buffer, resizing as needed and returning the length — no fixed size limit and no truncation. You must `free` the buffer. It is the safe, convenient way to read arbitrary-length lines.

# 2.1 <stdio.h> — Usage Patterns
Why prefer `snprintf` over `sprintf`?	`sprintf` writes as many bytes as the output needs with no knowledge of the destination size, so long/untrusted input overflows. `snprintf(buf, sizeof buf, ...)` caps the write and returns the length that *would* have been written, letting you detect truncation.
How do you read a whole file into a buffer with `fread`?	`size_t n = fread(buf, 1, bufsize, fp);` reads up to `bufsize` bytes and returns the count actually read; loop or size the buffer to the file, and use `feof`/`ferror` to tell EOF from error. Open with `"rb"` for binary data.
How should you check `fgets`'s return value?	It returns `buf` on success and `NULL` on EOF or error, so loop as `while (fgets(buf, sizeof buf, fp)) { ... }` and never use the buffer after a `NULL`. Unlike `gets`, it bounds the read and null-terminates.
What do the common `printf` format specifiers mean?	`%d`/`%i` signed int, `%u` unsigned, `%ld` long, `%zu` `size_t`, `%f` double (fixed), `%lf` double in `scanf`, `%s` string, `%p` pointer, `%x` hex, `%%` a literal percent. Matching the specifier to the argument type is mandatory (mismatch is UB).
What do width and precision do in a format like `%10.2f` or `%-20s`?	Width sets a minimum field width (right-justified by default; `-` left-justifies), and precision (`.n`) sets decimals for floats or a maximum length for strings. `%05d` zero-pads an int to 5 digits; `%10.2f` is at least 10 wide with 2 decimals.
What are the three stream buffering modes?	Fully buffered (flushed when the buffer fills — typical for files), line buffered (flushed on newline — typical for an interactive terminal `stdout`), and unbuffered (each write goes out immediately — `stderr`). This affects when output actually appears.
Why check `printf`'s return value?	It returns the number of characters written, or a negative value on error (e.g. a closed pipe / disk full). For robust programs writing important output, checking it detects write failures that would otherwise be silently lost.
Why must you never pass user-controlled data as the format argument?	Because `%` sequences in it are interpreted as conversions: `printf(user)` lets an attacker read memory with `%x`/`%s` or write with `%n`. Always use a literal format and pass the data as an argument: `printf("%s", user)`.

# 2.2 <stdlib.h> — Functions
What is the difference between `malloc`, `calloc`, `realloc`, and `free`?	`malloc(n)` gives `n` uninitialized bytes; `calloc(count, size)` gives zeroed memory and checks `count*size` for overflow; `realloc(p, n)` resizes a block (possibly moving it); `free(p)` releases it. Every successful allocation needs exactly one `free`.
What is the problem with `atoi`, `atol`, and `atof`?	They convert a string to a number with no error reporting: invalid input yields 0 (indistinguishable from a real "0"), and overflow is undefined. They are unsafe on untrusted input — use the `strtol` family instead.
What do the `strtol` / `strtoul` / `strtod` family add over `atoi`?	Robust error detection: they take an `endptr` telling you where parsing stopped (so you can detect trailing garbage) and set `errno == ERANGE` on overflow. `strtoll`/`strtoull` handle 64-bit; a base argument supports hex/octal/etc.
What do `abs`, `labs`, and `llabs` do (and one pitfall)?	They return the absolute value of an `int`/`long`/`long long`. Pitfall: `abs(INT_MIN)` is undefined because `-INT_MIN` is not representable in `int`. Use the width matching your type and guard the minimum value.
What do `div` and `ldiv` compute?	`div(num, den)` returns a `div_t` struct with both `quot` and `rem` in one call (well-defined truncation toward zero), and `ldiv`/`lldiv` do the same for `long`/`long long`. Useful when you need both quotient and remainder efficiently.
What are `rand` and `srand`, and their key limitation?	`rand()` returns a pseudo-random `int` in `[0, RAND_MAX]`; `srand(seed)` sets the sequence. They are not cryptographically secure and are often low quality — never use them for tokens, keys, or nonces; use a CSPRNG for security.
What is the difference between `exit`, `_Exit`, `atexit`, and `quick_exit`?	`exit(status)` ends the program running `atexit` handlers and flushing streams; `_Exit` ends immediately with no handlers/flush; `atexit(fn)` registers a cleanup handler (LIFO); `quick_exit` runs `at_quick_exit` handlers instead. Choose based on whether cleanup should run.
What does `abort` do?	It causes abnormal program termination, typically by raising `SIGABRT`, without running `atexit` handlers or flushing streams (unless a handler intervenes). It is how `assert` failures and unrecoverable errors bail out, often producing a core dump.
What do `getenv`, `setenv`, `putenv`, and `unsetenv` do?	`getenv(name)` returns the value of an environment variable (or `NULL`); POSIX `setenv`/`putenv` set one and `unsetenv` removes it. The returned string must not be modified/freed. In setuid programs, treat environment variables (`PATH`, `IFS`, `LD_*`) as untrusted.
Why is `system` dangerous?	`system(cmd)` runs `cmd` through a shell (`/bin/sh -c`), so any shell metacharacters (`;`, `|`, `` ` ``, `$()`) in untrusted data execute arbitrary commands — command injection. Prefer `fork` + `exec*` with an argument vector, which involves no shell.
What is `qsort`, and its comparator signature?	`qsort(base, count, size, cmp)` sorts an array in place using a comparator `int cmp(const void *a, const void *b)` that returns negative/zero/positive. Cast the void pointers to the element type; avoid subtraction (`*x-*y`) that can overflow — use comparisons.
What does `bsearch` do?	`bsearch(key, base, count, size, cmp)` performs a binary search over a *sorted* array using the same comparator style as `qsort`, returning a pointer to a matching element or `NULL`. The array must already be sorted by the same comparison.
What does `aligned_alloc` provide?	`aligned_alloc(alignment, size)` (C11) returns memory whose address is a multiple of `alignment` (a power of two, with `size` a multiple of it), for SIMD/DMA/cache-line needs. Free it with ordinary `free`; POSIX offers `posix_memalign` as an alternative.
What do `mblen`, `mbtowc`, and `wctomb` do?	They convert between multibyte characters (e.g. UTF-8 byte sequences) and wide characters: `mblen` measures a multibyte char's length, `mbtowc` decodes one to `wchar_t`, `wctomb` encodes one back. Behavior depends on the current locale (`setlocale`).

# 2.2 <stdlib.h> — Usage Patterns
Why must you check `malloc`/`calloc`/`realloc` for `NULL`?	Allocation can fail (returning `NULL`), and dereferencing a `NULL` result is undefined behavior/crash. Always test before use: `p = malloc(n); if (!p) { handle_error(); }`. Ignoring this is a common source of crashes and vulnerabilities.
Why prefer `calloc(n, size)` over `malloc(n * size)`?	`calloc` zero-initializes the memory and, crucially, checks `n * size` for overflow (returning `NULL` if it would wrap), whereas `malloc(n * size)` can under-allocate when the product overflows `size_t` — leading to a heap overflow.
What is the safe `realloc` idiom?	Assign to a temporary: `void *tmp = realloc(p, n); if (tmp) p = tmp; else { /* p still valid */ }`. Writing `p = realloc(p, n)` directly leaks the original block if `realloc` returns `NULL`, since you overwrite the only pointer to it.
How do you write a correct `qsort` comparator?	Cast the `const void *` parameters to the element type and compare without overflow: `const int *x=a,*y=b; return (*x>*y)-(*x<*y);`. Returning `*x - *y` can overflow for large ints; the subtraction-of-comparisons trick avoids it.
Why prefer `strtol`/`strtoul` over `atoi`/`atol`?	Because they report errors: check `endptr` to confirm digits were consumed and detect trailing junk, and check `errno == ERANGE` for overflow. `atoi` cannot distinguish a valid "0" from invalid input and has UB on overflow — unsafe for untrusted data.
Why is `atoi` unsafe on untrusted input?	It returns 0 for any unparseable string with no error signal, so you cannot tell "the user typed 0" from "the user typed garbage", and overflow is undefined. Robust parsing needs `strtol` with `endptr`/`errno` checks.
Why set a pointer to `NULL` after `free`?	`free(p)` leaves `p` dangling; a later accidental use or second `free(p)` is undefined behavior (use-after-free / double-free). Setting `p = NULL` makes such reuse crash predictably and makes `free(NULL)` (a safe no-op) harmless.

# 2.3 <string.h> — Functions
What does `strlen` return, and what does it not count?	The number of characters before the terminating `\0`, not including it — so a buffer must be at least `strlen(s)+1` bytes to hold the string. It scans for `\0`, so calling it on a non-terminated array reads out of bounds.
What is the danger of `strcpy` vs `strncpy`?	`strcpy(dst, src)` copies until `\0` with no size check, overflowing a too-small `dst`. `strncpy(dst, src, n)` copies at most `n` bytes but does not null-terminate if `src` is `n`+ chars — you must terminate manually. Prefer `snprintf`/`strlcpy`.
What is the risk with `strcat` and `strncat`?	`strcat(dst, src)` appends with no bound, overflowing `dst`. `strncat(dst, src, n)` appends at most `n` bytes *plus a `\0`* — note `n` is the max to copy, not the buffer size, which is easy to miscompute. Prefer building strings with `snprintf`.
What is the difference between `strcmp` and `strncmp`?	`strcmp(a, b)` compares whole strings, returning negative/zero/positive; `strncmp(a, b, n)` compares at most `n` characters. Both compare content (not addresses). Use them instead of `==`, which compares pointers.
What do `strchr` and `strrchr` find?	`strchr(s, c)` returns a pointer to the first occurrence of character `c` in `s` (or `NULL`); `strrchr` returns the last occurrence. Both include the terminating `\0` as a searchable character, useful for finding a string's end or extension.
What does `strstr` do?	`strstr(haystack, needle)` returns a pointer to the first occurrence of the substring `needle` within `haystack`, or `NULL` if not found. It is the standard substring search for C strings.
What does `strpbrk` find?	`strpbrk(s, set)` returns a pointer to the first character in `s` that appears in the character set `set` (or `NULL`) — "find any of these characters", useful for tokenizing on multiple delimiters.
What do `strspn` and `strcspn` return?	`strspn(s, set)` returns the length of the initial run of `s` made up only of characters in `set`; `strcspn(s, set)` returns the length of the initial run containing *none* of them. Together they help scan/skip character classes when parsing.
Why is `strtok` awkward, and what replaces it?	It modifies its input in place (writing `\0` over delimiters) — so it can't tokenize string literals — and keeps hidden static state, making it non-reentrant. Use `strtok_r(str, delim, &saveptr)` (POSIX), which is thread-safe and nesting-safe.
What does `memset` do, and one common mistake?	`memset(ptr, byte, n)` fills `n` bytes with a single byte value. Mistake: `memset(arr, 1, n)` fills with `0x01` bytes, not the integer 1 — it is byte-wise. Common valid use: `memset(&s, 0, sizeof s)` to zero a struct.
What is the difference between `memcpy` and `memmove`?	Both copy `n` bytes, but `memcpy` requires non-overlapping regions (overlap is UB) while `memmove` handles overlap correctly, as if via a temporary buffer. Use `memmove` when shifting data within one array.
What does `memcmp` compare, and why is it wrong for secrets?	`memcmp(a, b, n)` compares `n` bytes and returns negative/zero/positive. It is byte-wise and typically returns at the first difference, so its timing leaks how many leading bytes matched — a side-channel unsuitable for comparing passwords/MACs; use a constant-time compare.
What does `memchr` find?	`memchr(ptr, byte, n)` searches the first `n` bytes of a memory block for a given byte value and returns a pointer to it (or `NULL`). Unlike `strchr` it does not stop at `\0`, so it works on binary data of a known length.
What do `strdup` and `strndup` do?	`strdup(s)` allocates (via `malloc`) and returns a copy of a string; `strndup(s, n)` copies at most `n` chars and null-terminates. Both are POSIX (not ISO C) and the caller must `free` the result — forgetting to leaks memory.
What do `strerror` and `strerror_r` return?	`strerror(errnum)` returns a human-readable message for an `errno` value, but into a shared static buffer (not thread-safe). `strerror_r` writes into a caller-supplied buffer and is the reentrant, thread-safe choice.

# 2.3 <string.h> — Usage Patterns
Why must the destination always have room for the `\0`?	C string functions rely on the terminator, so a buffer must hold `strlen(src)+1` bytes; omitting the extra byte truncates the terminator and makes later `strlen`/`printf %s` read past the end. Size allocations and buffers with the `+1` in mind.
Why use `strtok_r` instead of `strtok`?	`strtok` stores its progress in a hidden static variable and mutates its input, so it breaks in multithreaded code and in nested/interleaved tokenizations. `strtok_r` keeps state in a caller-provided `char **saveptr`, making it reentrant and safe.
How do you zero out a struct, and its caveat?	`memset(&s, 0, sizeof s)` sets every byte (including padding) to zero. Caveat: it is byte-fill, so it cannot set members to a nonzero value like -1 portably, and it should not be used to "securely" wipe secrets (the compiler may elide it) — use `explicit_bzero`.
What safer string-copy alternatives exist to `strncpy`?	BSD/POSIX `strlcpy`/`strlcat` take the full destination size and always null-terminate (though not in every libc). Failing that, use `snprintf(dst, sizeof dst, "%s", src)`, or `strncpy` followed by `dst[n-1] = '\0'`.
How does `sizeof` on the real array help avoid truncation bugs?	Sizing a copy with `sizeof dst` (where `dst` is a true array in scope) uses the actual capacity, so `snprintf(dst, sizeof dst, ...)` can't overflow. But if `dst` has decayed to a pointer, `sizeof` gives the pointer size — pass the length explicitly there.
Why does comparing secrets with `memcmp` leak information?	`memcmp` usually returns at the first differing byte, so the time it takes reveals how many leading bytes are correct — an attacker can recover a password/MAC byte-by-byte from timing. Use a constant-time comparison that inspects every byte.

# 2.4 <math.h> — Functions
What do `sqrt` and `cbrt` compute?	`sqrt(x)` returns the square root of `x` (domain error / NaN for negative `x`), and `cbrt(x)` returns the cube root, which is defined for negative values too. Both operate on and return `double` (with `f`/`l` variants for other precisions).
What does `pow` do, and a precision tip?	`pow(base, exp)` raises `base` to the power `exp` for floating-point values. For exact small integer powers, direct multiplication (`x*x`) is faster and avoids rounding; `pow` can also signal domain/range errors (e.g. `pow(-1, 0.5)`).
What does `fabs` do, and how does it differ from `abs`?	`fabs(x)` returns the absolute value of a `double` (`fabsf`/`fabsl` for other precisions), while `abs` is for `int`. Using `abs` on a floating value truncates it to `int` first — a common bug; use `fabs` for floats.
What do `ceil`, `floor`, `round`, `trunc`, `nearbyint`, and `rint` do?	`ceil` rounds up, `floor` down, `round` to nearest (halves away from zero), `trunc` toward zero. `nearbyint`/`rint` round using the current rounding mode (`rint` may raise the inexact flag). All return a `double`, not an integer type.
What do `fmod` and `remainder` compute?	`fmod(x, y)` returns the floating-point remainder of `x/y` with the sign of `x`; `remainder(x, y)` returns the IEEE remainder rounded to the nearest integer quotient (result can be negative). Use `fmod` for a positive-style modulo of floats.
What do `exp`, `log`, `log2`, and `log10` compute (plus `expm1`/`log1p`)?	`exp(x)` is e^x, `log` is natural log, `log2`/`log10` are base-2/base-10 logs. `expm1(x)` computes e^x−1 and `log1p(x)` computes log(1+x) accurately for small `x`, avoiding cancellation error near zero.
What trigonometric functions does `<math.h>` provide?	`sin`, `cos`, `tan` and their inverses `asin`, `acos`, `atan`, plus `atan2(y, x)` which returns the angle of the point (x, y) using both signs to get the correct quadrant. Arguments/results are in radians.
What are the hyperbolic functions `sinh`, `cosh`, `tanh`?	They compute the hyperbolic sine, cosine, and tangent (`(e^x±e^-x)/2`, etc.), used in physics, catenary curves, and activation functions. Large arguments to `sinh`/`cosh` can overflow to `HUGE_VAL`.
What do the floating-point classification macros do?	`isnan(x)` tests for NaN, `isinf(x)` for infinity, `isfinite(x)` for a normal/subnormal/zero value, `isnormal(x)` excludes zero/subnormal/NaN/inf, and `signbit(x)` reports the sign bit (even for -0.0). They safely classify results without tricky comparisons.
What are `HUGE_VAL`, `NAN`, and `INFINITY`?	`HUGE_VAL` is the value math functions return on overflow (typically infinity); `INFINITY` is a positive-infinity constant; `NAN` is a quiet not-a-number constant. Use them with the classification macros, not `==`, since NaN never compares equal.
What does `fma` provide over `a*b + c`?	`fma(a, b, c)` computes `a*b + c` with a single rounding step (the product is not rounded before adding), giving better accuracy and often mapping to a hardware fused-multiply-add instruction. Important in numerical code where rounding accumulates.
Why link with `-lm`?	On most Unix systems the math functions live in a separate library (`libm`) from the C runtime, so you must add `-lm` when linking or get "undefined reference to `sqrt`" errors. Windows/MSVC bundles them, so no separate flag is needed.

# 2.4 <math.h> — Usage Patterns
How do you detect that a math call failed?	Check for special results with `isnan`/`isinf`, or set `errno = 0` before the call and inspect it afterward (domain errors set `EDOM`, range/overflow set `ERANGE`). For example `log(-1)` yields NaN and sets `EDOM`.
Why should you never compare floats with `==`?	Rounding makes many values inexact (`0.1 + 0.2 != 0.3`), so exact equality usually fails unexpectedly. Compare within a tolerance: `fabs(a - b) < epsilon`, using a relative epsilon for large magnitudes.
Why can repeated `float` operations lose precision?	`float` has ~7 significant digits, so accumulating many operations (e.g. summing a long series) magnifies rounding error. Using `double` (~15 digits) or compensated summation (Kahan) preserves accuracy in long computations.

# 2.5 <ctype.h> — Functions
What do `isalpha`, `isdigit`, and `isalnum` test?	Whether a character is a letter, a decimal digit, or alphanumeric (letter or digit), respectively, returning nonzero for true. They classify by the current locale's rules for the C/"POSIX" locale by default.
What does `isspace` consider whitespace?	Space, form feed `\f`, newline `\n`, carriage return `\r`, horizontal tab `\t`, and vertical tab `\v`. It is the standard test for skipping whitespace while parsing text.
What do `isupper` and `islower` check?	Whether a character is an uppercase or lowercase letter, respectively. They are locale-sensitive, and like all `<ctype.h>` functions require the argument to be representable as `unsigned char` or `EOF`.
What do `toupper` and `tolower` do to non-letters?	They convert a lowercase letter to uppercase (`toupper`) or vice versa (`tolower`), and return any other character unchanged. Behavior can shift under a non-C locale.
What do `isprint`, `ispunct`, and `iscntrl` classify?	`isprint` is any printable character including space; `ispunct` is a printable non-alphanumeric, non-space (punctuation/symbols); `iscntrl` is a control character (e.g. `\n`, `\t`, DEL). Useful for sanitizing or displaying input.
What does `isxdigit` test?	Whether a character is a hexadecimal digit: `0`–`9`, `a`–`f`, or `A`–`F`. Handy when parsing hex numbers or escape sequences.
What does `isgraph` test?	Whether a character has a visible glyph — printable and not a space. It is `isprint` minus the space character, i.e. any character that actually marks the page.

# 2.5 <ctype.h> — Usage Patterns
Why must you cast to `unsigned char` before calling `isdigit`/`toupper`/etc.?	These functions are defined only for values representable as `unsigned char` or `EOF`. On platforms where plain `char` is signed, passing a byte ≥ 0x80 gives a negative value — undefined behavior. Use `isdigit((unsigned char)c)`.
How does locale affect `<ctype.h>` functions?	Their classification/conversion can change under `setlocale` (e.g. which characters count as letters or how case maps in different alphabets). By default programs run in the C locale; call `setlocale(LC_ALL, "")` to honor the environment.

# 2.6 <time.h> — Functions
What does `time` return?	`time(NULL)` returns the current calendar time as a `time_t` (typically seconds since the Unix epoch, 1970-01-01 UTC), or `(time_t)-1` on failure. It is the starting point for most date/time computation.
What does `difftime` compute?	`difftime(end, start)` returns the difference between two `time_t` values as a `double` number of seconds, portably handling whatever representation `time_t` uses. Prefer it over subtracting `time_t` values directly.
What does `clock` measure?	`clock()` returns approximate processor time used by the program, in units of `CLOCKS_PER_SEC`; divide the difference of two readings by `CLOCKS_PER_SEC` for CPU seconds. It measures CPU time, not wall-clock time (use `time`/`clock_gettime` for elapsed real time).
What do `localtime`, `gmtime`, and their `_r` variants do?	They convert a `time_t` to a broken-down `struct tm`: `localtime` in local time (with timezone/DST), `gmtime` in UTC. The plain versions use shared static storage (not thread-safe); the `_r` variants write into a caller-supplied struct.
What does `mktime` do?	`mktime(&tm)` converts a broken-down local `struct tm` back to a `time_t`, normalizing out-of-range fields (e.g. day 32 becomes the next month) and filling in `tm_wday`/`tm_yday`. It interprets the struct as local time.
What does `strftime` do?	`strftime(buf, size, format, &tm)` formats a `struct tm` into a string using specifiers like `%Y-%m-%d %H:%M:%S`, bounded by `size` and locale-aware. It is the safe, flexible way to render dates/times as text.
Why avoid `asctime` and `ctime`?	They format time into a fixed shared static buffer, are non-reentrant, and are deprecated; crafted `struct tm` fields can even overflow their internal buffer. Use `strftime` (bounded, flexible) instead.
What does `timespec_get` provide?	`timespec_get(&ts, TIME_UTC)` (C11) fills a `struct timespec` with seconds and nanoseconds, giving higher resolution than `time`. It is the standard C way to get sub-second timestamps (POSIX offers `clock_gettime`).

# 2.6 <time.h> — Usage Patterns
Why prefer `localtime_r`/`gmtime_r` in threaded code?	The non-`_r` versions return a pointer to a single shared static `struct tm`, so concurrent or even sequential nested calls overwrite each other's result. The reentrant `_r` variants write into your own struct, avoiding the data race.
Why not trust `asctime`/`ctime` with attacker-influenced `struct tm`?	Their classic implementations format into a fixed-size internal buffer assuming reasonable field ranges; out-of-range year/day values can overflow it — historically a real vulnerability. Use `strftime` with an explicit buffer size instead.

# 2.7 <errno.h> & <assert.h>
What is `errno`, and when is it valid?	`errno` is a thread-local integer that failing library functions set to an error code. It is only meaningful immediately after a call documented to set it *fails*; it is not cleared on success. Read it right after detecting failure, before another call overwrites it.
Name some common `errno` codes.	`EINVAL` (invalid argument), `ENOMEM` (out of memory), `ENOENT` (no such file), `EACCES` (permission denied), `ERANGE` (result out of range), `EOVERFLOW`, `EEXIST` (already exists), `EAGAIN` (try again). Translate them with `strerror`/`perror`.
What does `strerror` do (and its thread-safety caveat)?	`strerror(errnum)` returns a human-readable message for an `errno` value. It may use a shared static buffer, so it is not thread-safe; use `strerror_r` in multithreaded code.
What does `perror` do?	`perror("prefix")` prints your prefix plus the message for the current `errno` to `stderr`. Call it right after a failing call so `errno` still reflects that failure.
What does `assert(expr)` do, and when is it disabled?	`assert(expr)` aborts with a diagnostic (file, line, expression) if `expr` is false, catching programmer-bug invariants during development. Defining `NDEBUG` before `<assert.h>` compiles all `assert`s out — so they must not carry side effects or security checks.
What is the difference between `assert` and `static_assert`?	`assert` is a runtime check (stripped by `NDEBUG`). `static_assert(cond, "msg")` / `_Static_assert` is checked at compile time and fails the build if false, with zero runtime cost — ideal for verifying type sizes and struct layouts.

# 2.7 Usage Patterns
Why must you not use `assert` for input validation in release builds?	`assert` is removed entirely when `NDEBUG` is defined (typical release builds), so any validation or security check inside it silently vanishes. Validate untrusted input with real `if` checks that remain in the shipped binary.
Why check the function's failure indicator before reading `errno`?	Many functions do not reset `errno` to 0 on success, so a stale value from an earlier failure can mislead you. Confirm the call actually failed (via its return value), then inspect `errno`; if a call can validly return -1, set `errno = 0` beforehand.

# 2.8 <stddef.h>
What is `size_t`, and why use it for sizes/indices?	`size_t` is the unsigned type returned by `sizeof` and used throughout the library for sizes and counts; it can represent the size of any object. Using it consistently for lengths/indices avoids signed/unsigned mismatch bugs and warnings.
What is `ptrdiff_t` for?	It is the signed integer type produced by subtracting two pointers into the same array — large enough to hold the result on the platform. Use it for pointer differences and array-index deltas that can be negative.
What is `NULL`?	The null pointer constant from `<stddef.h>` — a value guaranteed not to point to any object, used to initialize pointers and signal "no result"/failure from functions returning pointers. Dereferencing it is undefined behavior.
What does `offsetof(type, member)` give, and where is it used?	The byte offset of `member` within `type`. It powers the "container_of" idiom (recovering the enclosing struct from a member pointer), binary serialization, and hardware register-map layouts.
What is `max_align_t`?	A type whose alignment is at least as strict as every scalar type's — the "maximum fundamental alignment". Allocators (like `malloc`) return memory suitably aligned for any type, i.e. `alignof(max_align_t)`.

# 2.8 Usage Patterns
Why use `size_t` consistently for lengths and indices?	Because the library uses it everywhere and it is unsigned and wide enough for any object size; mixing it with `int` invites signed/unsigned comparison bugs (e.g. `i < strlen(s)` with a signed `i`) and truncation on large sizes.
What are practical uses of `offsetof`?	Serializing/deserializing structs field-by-field, implementing intrusive containers via `container_of`, and mapping hardware registers by offset — anywhere you need a member's position within a struct without an instance.

# 2.9 <stdint.h> & <inttypes.h>
What do the exact-width types like `int32_t`/`uint8_t` guarantee?	Exactly the stated width (8/16/32/64 bits) with the stated signedness, on any platform that provides them. Use them for file formats, network protocols, hardware registers, and bit manipulation where representation must be portable.
What are `intptr_t` and `uintptr_t` for?	Integer types wide enough to hold a pointer value without loss, so you can convert a pointer to an integer and back portably (e.g. for tagging or alignment math). Plain `int`/`long` may be too narrow on 64-bit platforms.
What is `ssize_t`?	A POSIX signed counterpart to `size_t`, used by functions like `read`/`write` that return a byte count or -1 on error. It can represent "-1" plus the full positive size range, unlike unsigned `size_t`.
What are `int_least*_t` and `int_fast*_t`?	`int_leastN_t` is the smallest type with at least N bits (space-efficient); `int_fastN_t` is the fastest type with at least N bits (speed-efficient). Use them when you need a minimum width but exact width isn't required.
What are the range-constant macros like `INT8_MAX`/`UINT32_MAX`/`SIZE_MAX`?	Compile-time limits for the fixed-width and standard integer types (`INT8_MIN`, `UINT32_MAX`, `SIZE_MAX`, etc.). Use them for portable bounds and overflow checks instead of hardcoding magic numbers.
What are the `PRI`/`SCN` macros in `<inttypes.h>`?	Format-string fragments for fixed-width types: `printf("%" PRId32, x)` prints an `int32_t`, `PRIu64`/`PRIx64` handle `uint64_t`, and `SCNd32` is for `scanf`. They expand to the correct length modifier per platform, avoiding format/type mismatch UB.

# 2.9 Usage Patterns
How do you use `SIZE_MAX` to prevent an allocation overflow?	Before `malloc(n * sizeof(*p))`, check `if (n > SIZE_MAX / sizeof(*p)) { /* would overflow */ }`. This catches the multiplication wrapping `size_t` to a small value that would under-allocate. `calloc` performs this check internally.
Why prefer fixed-width types for on-disk/network formats?	Because the exact byte layout must match on all machines; `int`/`long` vary in width and signedness by platform, but `int32_t`/`uint16_t` are unambiguous. Combined with byte-order conversion, they make serialized data portable.

# 2.10 <stdarg.h>
What is a `va_list`?	An opaque type holding the iteration state over a variadic function's `...` arguments. You initialize it with `va_start`, read arguments with `va_arg`, and release it with `va_end`.
What does `va_start(ap, last)` do?	Initializes the `va_list ap` to point at the first variadic argument; `last` must be the last *named* parameter before the `...`. Call it before any `va_arg`.
What does `va_arg(ap, type)` do?	Returns the next variadic argument, interpreting it as `type`, and advances the `va_list`. You must request the promoted type (e.g. `int` for a char, `double` for a float) and you must know the count/types from a format string or count parameter.
What is `va_copy(dst, src)` for?	It clones a `va_list` so you can traverse the arguments twice (e.g. one pass to measure, one to format). Each copy needs its own `va_end`. Reusing a `va_list` after `va_arg` without copying gives undefined results.
What does `va_end(ap)` do?	Performs any cleanup needed to finish using the `va_list`, and must be called before the variadic function returns (once per `va_start`/`va_copy`). Omitting it is undefined behavior on some ABIs.

# 2.10 Usage Patterns
How do you forward variadic arguments to `vprintf`/`vsnprintf`?	Capture them in a `va_list` and pass it to the `v*` variant: `void logf(const char *fmt, ...){ va_list ap; va_start(ap, fmt); vfprintf(stderr, fmt, ap); va_end(ap); }`. The `v*` functions exist precisely to accept a `va_list`.
Why can't a variadic function know its argument count/types by itself?	The language passes no metadata about the `...` arguments, so the function must be told: via a format string (like `printf`), an explicit count parameter, or a sentinel terminator value. Reading more/other-typed args than were passed is undefined behavior.
What type must `va_arg` request for a `char` or `float` argument?	The promoted type — `int` for any integer narrower than `int` (including `char`/`short`), and `double` for `float` — because default argument promotions apply to variadic arguments. `va_arg(ap, char)` or `va_arg(ap, float)` is UB.

# 2.11 <signal.h>
What does `signal` register?	`signal(signum, handler)` sets the action for a signal to `SIG_DFL` (default), `SIG_IGN` (ignore), or a function pointer handler. Its cross-platform semantics are weak (handler reset, masking), so prefer `sigaction` for robust code.
What does `raise` do?	`raise(sig)` sends signal `sig` to the current process (thread), synchronously invoking its handler. It is used to trigger signals programmatically, e.g. `raise(SIGABRT)`.
Name common signals and their meanings.	`SIGINT` (Ctrl-C interrupt), `SIGTERM` (polite termination request), `SIGSEGV` (invalid memory access), `SIGFPE` (arithmetic error like divide-by-zero), `SIGABRT` (from `abort`), `SIGHUP` (hangup), `SIGCHLD` (child stopped/exited); `SIGKILL` cannot be caught or ignored.
What is `sig_atomic_t`, and why `volatile`?	`sig_atomic_t` is the only type guaranteed to be read/written atomically with respect to signals. Flags shared between a handler and main code should be `volatile sig_atomic_t` — `volatile` so the compiler re-reads it, atomic so the handler can't be seen mid-update.
What are async-signal-safe functions?	Only a small POSIX-defined set of functions (e.g. `write`, `_exit`, `signal`) may be safely called inside a signal handler; others (`printf`, `malloc`, most of libc) may be interrupted mid-operation, so calling them in a handler is undefined behavior/deadlock-prone.
Why prefer `sigaction` over `signal`?	`sigaction` gives portable, explicit control: which signals are blocked during the handler, whether interrupted syscalls auto-restart (`SA_RESTART`), and reliable persistent (not one-shot) handling — avoiding `signal`'s historically inconsistent behavior.
What do `sigprocmask`, `sigemptyset`, and `sigaddset` do?	They manipulate the process's signal mask (the set of currently blocked signals): `sigemptyset`/`sigaddset` build a signal set, and `sigprocmask` installs it to block/unblock signals — used to protect critical sections from being interrupted.

# 2.12 <setjmp.h>
What does `setjmp` do?	`setjmp(env)` saves the current execution context (stack pointer, registers, program counter) into `env` and returns 0 on this initial call. A later `longjmp` makes it appear to return again with a nonzero value.
What does `longjmp` do?	`longjmp(env, val)` restores the context saved by `setjmp`, transferring control back to that point, which then "returns" `val` (or 1 if `val` is 0). Execution never continues past the `longjmp` call itself.
What is the classic use case for `setjmp`/`longjmp`?	Non-local error recovery: unwind out of deeply nested calls back to a recovery point in one jump, without manually propagating an error code through every intermediate return. It approximates exceptions in C.
What is the `setjmp`/`longjmp` local-variable pitfall?	Non-`volatile` locals modified between `setjmp` and the `longjmp` back may hold indeterminate values afterward (the compiler could have kept them in registers). Declare locals you rely on after the jump as `volatile`.

# 2.13 <stdbool.h>, <limits.h>, <float.h>
What does `<stdbool.h>` provide?	The `bool` type plus `true`/`false` macros (aliases for `_Bool`, 1, 0). Since C23 these are proper keywords and the header is unnecessary. Using `bool` for logical flags documents intent better than `int`.
What key limits does `<limits.h>` define?	Ranges of the integer types and `CHAR_BIT` (bits per byte, usually 8): `INT_MIN`/`INT_MAX`, `UINT_MAX`, `LONG_MAX`, `CHAR_MIN`/`CHAR_MAX`. Note the signedness of plain `char` is implementation-defined, reflected in `CHAR_MIN`.
What does `<float.h>` define?	Floating-point characteristics: `FLT_EPSILON`/`DBL_EPSILON` (smallest distinguishable step near 1.0), `FLT_MAX`/`DBL_MIN`, `FLT_RADIX` (usually 2), and precision/exponent limits. Use them for tolerance-based comparisons and overflow/underflow reasoning.

# 2.13 Usage Patterns
How do the `<limits.h>` macros help write portable overflow checks?	They let you check before the operation instead of after: `if (a > 0 && b > INT_MAX - a) overflow();` uses `INT_MAX` rather than a magic number, staying correct across platforms with different int widths.
How do you use `*_EPSILON` for float comparison?	Compare within a tolerance scaled to the magnitude: `fabs(a - b) <= DBL_EPSILON * fmax(fabs(a), fabs(b))` for a relative check, or a fixed epsilon for values near a known scale — never `a == b` directly.

# 2.14 Concurrency: <threads.h> & <pthread.h>
What does C11 `<threads.h>` provide?	Portable threading: `thrd_create`/`thrd_join` for threads, `mtx_t` with `mtx_lock`/`mtx_unlock` for mutexes, `cnd_t` condition variables, `thread_local` storage, and `call_once` for one-time initialization. It is the standard (if not universally implemented) threading API.
What does POSIX `<pthread.h>` provide?	The widely-used Unix threading API: `pthread_create`/`pthread_join`, `pthread_mutex_t` mutexes, `pthread_cond_t` condition variables, `pthread_once` one-time init, and `pthread_rwlock_t` reader-writer locks. Link with `-pthread`.
What does `<stdatomic.h>` offer for concurrency?	Atomic types and operations — `atomic_int`, `atomic_load`/`atomic_store`, `atomic_fetch_add`, `atomic_compare_exchange` — each taking an optional memory-order argument. They provide race-free lock-free access to shared scalars without a mutex.

# 2.14 Usage Patterns
How do you correctly protect shared state with a mutex?	Lock before every access (reads included) and unlock after, keeping the critical section small: `mtx_lock(&m); shared++; mtx_unlock(&m);`. Every thread must use the same mutex for that data; an unsynchronized access elsewhere is still a data race (UB).
Why must a condition-variable wait use a predicate loop?	Because of spurious wakeups (a wait can return with no signal) and stolen wakeups (another thread changes the state first). Re-test in a loop: `while (!ready) cnd_wait(&cv, &m);`. An `if` would wrongly proceed on a false wakeup.
When is an atomic preferable to a full mutex?	For simple shared scalars — counters, flags, single-word state — an atomic (`atomic_fetch_add`, `atomic_load`/`store`) is lock-free and cheaper than a mutex. Use a mutex when you must update several fields together while preserving an invariant.
Why avoid calling unknown callbacks while holding a lock?	The callback might block, run for a long time, or re-enter code that tries to take the same lock — causing deadlock or priority issues. Establish a consistent lock ordering and release locks before invoking caller-supplied callbacks.

# 2.15 Specialized & Platform Headers
What does `<complex.h>` provide?	Complex arithmetic: the `double complex` (and float/long double) types, the imaginary unit `I`, and functions like `creal`/`cimag` (real/imag parts) and `cabs` (magnitude). It lets C do native complex-number math.
What does `<fenv.h>` control?	The floating-point environment: exception status flags (`FE_DIVBYZERO`, `FE_OVERFLOW`, `FE_INVALID`, `FE_INEXACT`) you can test/clear, and the rounding mode via `fesetround`/`fegetround`. Used in careful numerical code and reproducibility work.
What does `<locale.h>` do?	`setlocale(LC_ALL, "")` switches the program from the C locale to the environment's locale, affecting number/date formatting, currency (`localeconv`), string collation, and `<ctype.h>` classification. It governs locale-dependent behavior across the library.
What does `<uchar.h>` provide?	The `char16_t` and `char32_t` types (UTF-16/UTF-32 code units) and conversion functions (`mbrtoc16`/`c32rtomb`, etc.) for translating between multibyte and these Unicode encodings.
What do `<wchar.h>` and `<wctype.h>` provide?	Wide-character counterparts of the string and ctype libraries: `wchar_t` strings with `wcslen`/`wcscpy`/`fwprintf`, and wide classification like `iswalpha`/`iswspace`. They support locales whose characters don't fit in a single `char`.
What does POSIX `<unistd.h>` provide?	Core Unix syscall wrappers: `fork`/`exec*` (processes), `read`/`write`/`close`/`lseek` (low-level I/O), `pipe`, `dup`/`dup2` (fd plumbing), `getuid`/`geteuid` and `setuid`/`seteuid` (credentials), and `access` (permission checks). It is the heart of POSIX systems programming.
What does `<fcntl.h>`'s `open` add over `fopen`, and what do its flags mean?	`open(path, flags, mode)` returns a raw file descriptor with fine control: `O_RDONLY`/`O_WRONLY`/`O_RDWR`, `O_CREAT` (create), `O_EXCL` (fail if exists — race-free creation), `O_APPEND`, and `O_CLOEXEC` (close on exec). It underlies the buffered `FILE*` layer.
What does `<sys/stat.h>` provide?	File metadata and permissions: `stat`/`fstat`/`lstat` fill a `struct stat` (size, mode, times, owner), the mode bit macros (`S_ISDIR`, `S_IRUSR`, …), plus `mkdir` and `umask` (the default-permission mask for new files).
What networking calls do `<sys/socket.h>` and friends provide?	The Berkeley sockets API: `socket`, `bind`, `listen`, `accept`, `connect`, and `send`/`recv`, plus byte-order helpers `htons`/`htonl`/`ntohs`/`ntohl` from `<arpa/inet.h>`. They implement TCP/UDP network communication.
What does `<dlfcn.h>` do?	Runtime dynamic loading: `dlopen` loads a shared library by name, `dlsym` looks up a symbol (function/variable) address in it, and `dlclose` unloads it. It enables plugins and lazy loading; `dlerror` reports failures.
What is the difference between real, effective, and saved UID?	The real UID is who launched the process; the effective UID (EUID) governs permission checks; the saved UID lets a setuid program drop and later regain privilege. Reap children with `wait`/`waitpid`; a setuid-root binary should drop to the real UID before risky work.

# 2.15 Usage Patterns
How do you create a file race-free with `O_CREAT | O_EXCL`?	`open(path, O_CREAT | O_EXCL | O_WRONLY, 0600)` atomically creates the file and fails if it already exists, so an attacker cannot pre-create or symlink it between check and creation. For temp files, `mkstemp` does this with a unique name.
Why use `fork`+`exec*` instead of `system()`?	`fork` duplicates the process and `execv(path, argv)` replaces the child with a new program, passing arguments as a vector with no shell involved — so shell metacharacters in the arguments cannot inject commands. `system()` runs a shell and is injection-prone.
Why convert integers with `htons`/`htonl` before sending over a socket?	Machines differ in byte order; network byte order is big-endian. Convert host-to-network before sending (`htons`/`htonl`) and network-to-host after receiving (`ntohs`/`ntohl`) so both endpoints agree regardless of architecture.
Why always check the return values of privilege and file syscalls?	Calls like `setuid`, `open`, `chdir`, and `chown` can fail silently (returning -1) — e.g. `setuid` failing means privileges were *not* dropped, leaving code running as root. Unchecked failures here are a classic root cause of real security vulnerabilities.

# 2.16 Secure Coding — Safer Alternatives
Why was `gets` removed from the C standard?	It reads a line with no bounds check, so any input longer than the buffer overflows it — an unconditional vulnerability. Deprecated in C99 and removed in C11. Use `fgets(buf, sizeof buf, stdin)`, which takes a size limit.
When should you prefer `snprintf` over `sprintf`/`strcpy`/`strcat`?	Whenever a fixed-size buffer meets untrusted or variable-length input. `snprintf(buf, sizeof buf, "%s%d", s, n)` caps the write and null-terminates, whereas `sprintf`/`strcpy`/`strcat` have no bound and overflow. It is the general-purpose safe formatting/copy tool.
How do `strlcpy`/`strlcat` improve on `strncpy`/`strncat`?	They take the full destination buffer size and always null-terminate, returning the length needed so you can detect truncation. `strncpy` may leave the result unterminated and `strncat`'s size argument is easy to misuse. (They are BSD/POSIX, not in every libc.)
Why doesn't `strncpy` guarantee null-termination?	If the source is `n` or more characters, `strncpy(dst, src, n)` copies exactly `n` bytes and writes no terminator, leaving `dst` unterminated. Always terminate manually: `strncpy(dst, src, n-1); dst[n-1] = '\0';`.
What are the C11 Annex K bounds-checked functions, and their caveat?	Optional `_s` variants like `strcpy_s`, `sprintf_s`, `memcpy_s` that take destination sizes and fail loudly on overflow. The caveat: Annex K is optional and unevenly implemented (glibc omits it), so know they exist but don't assume they're available.
How do you securely erase a secret from memory?	Use `explicit_bzero` (BSD/glibc), `memset_s` (C11 Annex K), or `SecureZeroMemory` (Windows) — these are guaranteed not to be optimized away, unlike a plain `memset(key, 0, n)` before `free`, which the compiler may delete as a dead store.
Why isn't `memcmp`/`strcmp` safe for comparing secrets?	They typically return at the first differing byte, so their timing reveals how many leading bytes matched — an attacker can recover a password/MAC/token byte-by-byte. Use a constant-time comparison that always inspects every byte.
Why are `rand()`/`srand()` unsuitable for security?	They are predictable pseudo-random generators (often seeded from the time), so their output can be reproduced or guessed — fatal for session IDs, keys, and nonces. Use a CSPRNG: `getrandom`, `/dev/urandom`, `arc4random`, or a platform crypto API.
Why avoid `system()`/`popen()` with untrusted data?	Both invoke a shell, so metacharacters in the data run arbitrary commands (injection). Prefer `fork`+`exec*` with an argument array, which passes arguments literally with no shell parsing. If you must build a command, rigorously validate/escape the inputs.
Why prefer `mkstemp` over `tmpnam`/`tmpfile` naming?	`tmpnam` only produces a predictable name, leaving a TOCTOU window for a symlink/pre-creation attack. `mkstemp` atomically creates and opens a uniquely-named file with safe permissions, eliminating the race.
How does canonicalizing paths with `realpath` help security?	`realpath` resolves `..`, symlinks, and redundant separators to an absolute canonical path, which you can then verify stays within an allowed base directory — defeating `../` path-traversal that would otherwise escape a sandbox.
Why check every `malloc`, size-arithmetic, and privilege-change result?	Treating these as "can't fail" is a recurring root cause of real CVEs: an unchecked `malloc` NULL leads to a crash/UAF, unchecked size arithmetic overflows to an undersized buffer, and an unchecked `setuid` leaves privileges undropped. Validate each.
Name useful compiler hardening flags for C.	`-D_FORTIFY_SOURCE=2` (compile-time buffer checks), `-fstack-protector-strong` (stack canaries), `-Wformat -Wformat-security` (catch format-string bugs), and `-Wall -Wextra`. Add `-fPIE -pie`, `-Wl,-z,relro,-z,now`, and `-fsanitize=address,undefined` in testing/CI.

# 2.17 <tgmath.h> — Type-Generic Math
What does <tgmath.h> provide?	Type-generic macros that automatically dispatch math calls (sin, sqrt, etc.) to the float, double, or long double variant based on the argument's type. sin(x) selects sinf, sin, or sinl automatically — no manual f/l suffixes needed.
When should you include <tgmath.h> instead of <math.h>?	When writing precision-generic code where the operation should follow the argument type automatically — e.g. a macro or template-like helper that works equally on float and double arrays without code duplication.

# 2.18 <dirent.h> (POSIX) — Directory Traversal
What do opendir, readdir, and closedir do?	opendir(path) opens a directory stream (returns DIR*, NULL on error). readdir(dir) returns a struct dirent* for the next entry or NULL at end/error. closedir(dir) releases the stream. Together they are the standard POSIX directory-listing API.
How do you distinguish end-of-directory from a read error in readdir?	Set errno = 0 before the loop. When readdir returns NULL, check errno != 0 — non-zero means error; still-zero means normal end-of-directory. Never rely on NULL alone to mean end of directory.
What are the key fields of struct dirent?	d_name (null-terminated file name), d_ino (inode number), d_type (DT_REG, DT_DIR, DT_LNK, DT_UNKNOWN, etc.). d_type is not reliable on all filesystems (tmpfs, NFS may return DT_UNKNOWN) — fall back to lstat when needed.
Why must you skip . and .. in a readdir loop?	Every directory contains . (itself) and .. (parent). A recursive traversal that doesn't skip them loops forever or processes the wrong subtree. Filter: strcmp(entry->d_name, ".") == 0 || strcmp(entry->d_name, "..") == 0.
What does scandir do?	scandir(dir, &namelist, filter, compar) reads an entire directory, applies an optional filter callback, sorts with a comparator, and stores results in a struct dirent ** array. The caller must free each entry and the array. alphasort and versionsort are ready-made comparators.

# 2.19 <regex.h> (POSIX) — Regular Expressions
What does regcomp do?	Compiles a pattern string into an opaque regex_t. Returns 0 on success. Key cflags: REG_EXTENDED (ERE syntax), REG_ICASE (case-insensitive), REG_NOSUB (skip subexpression tracking).
What does regexec do and what does pmatch contain?	regexec(preg, string, nmatch, pmatch, 0) matches the compiled pattern. Returns 0 on match, REG_NOMATCH otherwise. pmatch[0] holds rm_so/rm_eo byte offsets of the whole match; pmatch[1], [2], ... hold subexpression offsets.
What is the difference between POSIX BRE and ERE?	BRE (default): (, ), {, }, +, ?, | must be escaped to be metacharacters. ERE (REG_EXTENDED): those characters are metacharacters unescaped — closer to modern regex syntax and generally preferred for readability.
Why must you always call regfree?	A successful regcomp allocates memory inside the regex_t. Not calling regfree leaks that memory. Call it even if regexec was never called — once regcomp succeeds you own the resources.

# 2.20 <glob.h> & <fnmatch.h> — Pathname Expansion & Wildcard Matching
What does glob do?	glob(pattern, flags, errfunc, &pglob) expands a shell-style wildcard pattern (*, ?, [...]) against the real filesystem and stores the sorted matching paths in pglob.gl_pathv. Call globfree afterward to release memory.
What does fnmatch do and how is it different from glob?	fnmatch(pattern, string, flags) tests whether a single string matches a wildcard pattern — it does not access the filesystem at all. Use fnmatch to filter readdir results; use glob to expand patterns to actual filesystem paths.
What does FNM_PATHNAME do?	Prevents * and ? from matching /, so *.c matches foo.c but not dir/foo.c. Without it * matches any character including directory separators, which can be surprising for filename-only matching.

# 2.21 <termios.h> (POSIX) — Terminal I/O Control
What does struct termios represent?	The full set of terminal I/O parameters: c_iflag (input modes), c_oflag (output modes), c_cflag (control modes including baud rate), c_lflag (local/line-discipline modes including echo and canonical processing), and c_cc[] (control characters like VMIN, VTIME, VINTR).
How do tcgetattr and tcsetattr work?	tcgetattr(fd, &tios) reads current terminal settings. tcsetattr(fd, when, &tios) applies new settings. when: TCSANOW (immediate), TCSADRAIN (after output drains), TCSAFLUSH (drain and discard pending input).
How do you put a terminal into raw mode?	Save the original termios. Clear ICANON and ECHO in c_lflag, set c_cc[VMIN]=1 and c_cc[VTIME]=0, then call tcsetattr(TCSANOW). Restore original settings via an atexit handler and a SIGINT/SIGTERM handler.
Why must you restore terminal settings before exit?	Raw-mode changes persist in the kernel after the program exits — the user's shell is left with no echo and no line editing. Always register an atexit handler that calls tcsetattr to restore the saved original settings.

# 2.22 <sys/wait.h> & <sys/resource.h>
What do WIFEXITED and WEXITSTATUS do?	WIFEXITED(status) is non-zero if the child exited normally. WEXITSTATUS(status) extracts the 8-bit exit code. Always check WIFEXITED first — WEXITSTATUS is meaningless if the child was killed by a signal.
What do WIFSIGNALED and WTERMSIG do?	WIFSIGNALED(status) is non-zero if the child was killed by an unhandled signal. WTERMSIG(status) extracts the signal number. Use these to detect crashes (SIGSEGV, SIGABRT) in a child process.
Why must you waitpid for every forked child?	A child that exits before the parent collects it becomes a zombie — its process-table entry persists until waited for. Many zombies exhaust the PID space. Use waitpid(-1, &s, WNOHANG) in a SIGCHLD handler to reap children asynchronously.
What does WNOHANG do in waitpid?	Makes waitpid return immediately (with 0) if no child has changed state yet, instead of blocking. Essential in a SIGCHLD handler or polling loop where you want to reap finished children without stalling the parent.
What does getrlimit do, and how is it used for sandboxing?	getrlimit(resource, &rlim) queries the soft and hard limits (RLIMIT_NOFILE, RLIMIT_AS, RLIMIT_NPROC, etc.). Before exec-ing an untrusted child, lower these limits to bound how much damage it can do — a lightweight sandboxing measure.
What does getrusage provide?	User and system CPU time (as struct timeval), maximum resident set size, page fault counts, and voluntary/involuntary context switches. RUSAGE_SELF gives current process stats; RUSAGE_CHILDREN gives aggregated stats for all waited-for children.

# 2.23 Minimal Standard Headers
What does <iso646.h> provide?	Alternative spellings for C operators: and (&&), or (||), not (!), bitand (&), bitor (|), xor (^), compl (~), and_eq (&=), or_eq (|=), xor_eq (^=), not_eq (!=). Intended for keyboards that lack &, |, !, ^, ~.
What do <stdalign.h> and <stdnoreturn.h> provide?	<stdalign.h> (C11) defines alignas and alignof as macros expanding to _Alignas/_Alignof. <stdnoreturn.h> (C11) defines noreturn expanding to _Noreturn. Both are thin convenience wrappers so you can use keyword-like names without the _-prefixed forms.
