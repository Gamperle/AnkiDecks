# 4.1 Language Standards & Evolution
What are the major C standard revisions?	C89/C90 (ANSI C, the classic baseline), C99, C11, C17 (bug-fix only), and C23. Each adds features while staying largely backward compatible. Select one with `-std=c11` etc.; check `__STDC_VERSION__` at compile time.
Name key features introduced in C99.	`//` line comments, `inline` functions, variable-length arrays, designated initializers, `<stdint.h>` fixed-width types, `<stdbool.h>`, compound literals, `restrict`, mixed declarations and statements, and `long long`.
Name key features introduced in C11.	`_Static_assert`, `_Generic` type-generic selection, atomics (`<stdatomic.h>`), threads (`<threads.h>`), anonymous structs/unions, `_Alignas`/`_Alignof`, `_Noreturn`, optional bounds-checked functions (Annex K), and removal of `gets`.
What did C17 change?	Nothing functionally new — C17 is a defect-report/clarification release that fixes wording and inconsistencies in C11, so code targeting it uses the same features with cleaner specification.
Name key features introduced in C23.	`nullptr`, `constexpr`, `typeof`, `#embed`, making `bool`/`true`/`false`/`static_assert` keywords, binary literals (`0b`), digit separators, `[[attributes]]`, and checked integer arithmetic helpers.
What is the difference between a freestanding and a hosted implementation?	A hosted implementation provides the full standard library and starts at `main` under an OS. A freestanding implementation (kernels, bare-metal firmware) guarantees only a minimal header subset (`<stddef.h>`, `<stdint.h>`, `<limits.h>`, `<stdbool.h>`, etc.), no `malloc`/`stdio`, and may use a custom entry point.
How do you select a C standard and check which is in effect?	Pass `-std=c11`/`-std=c17`/`-std=c23` (add `-pedantic` for strict ISO, or use `-std=gnu11` for GNU extensions), and read the predefined `__STDC_VERSION__` macro (e.g. `201710L` for C17) to branch on the standard at compile time.


# 4.2 Concurrency & the C Memory Model
What are the "sequenced-before", "happens-before", and "synchronizes-with" relations?	They define ordering of memory effects: sequenced-before orders operations within one thread; synchronizes-with links a release operation to the acquire that reads it across threads; happens-before is the transitive combination that decides which writes a read must observe.
What does "a data race is undefined behavior" mean in C?	If two threads access the same non-atomic object, at least one writing, with no synchronization ordering them, the entire program's behavior is undefined — not just a wrong value. Use mutexes or atomics to establish a happens-before edge between the accesses.
What do the C memory orders permit the compiler/CPU to reorder?	`relaxed`: atomicity only, any reordering. `acquire`: later accesses can't move before this load. `release`: earlier accesses can't move after this store. `acq_rel`: both, for read-modify-write. `seq_cst`: a single global total order (strongest, default).
What is false sharing?	When two threads modify different variables that share a cache line, the cache-coherence protocol bounces the line between cores, destroying performance despite no logical sharing. Fix by padding/aligning hot per-thread data onto separate cache lines.
What is thread-local storage in C?	Per-thread variables declared `_Thread_local` (C11) or `__thread` (GCC), giving each thread its own independent instance — useful for per-thread errno-like state or caches without locking. Each thread initializes and destroys its own copy.
How do you do safe lazy one-time initialization?	Use `call_once` (C11) / `pthread_once` to run an init function exactly once across threads. For a hand-rolled double-checked lock, the flag and pointer must be atomics with acquire/release ordering — otherwise the classic double-checked-locking bug reappears.
When would you choose a mutex vs a spinlock vs a read-write lock?	Mutex: general mutual exclusion, sleeps when contended (good for longer/blocking sections). Spinlock: busy-waits, only worth it for very short critical sections on multiple cores. Read-write lock: many concurrent readers but exclusive writers, when reads dominate.
What is the ABA problem, and how is it mitigated?	In lock-free code, a compare-and-swap sees a value change A→B→A and wrongly assumes nothing changed, though the state (e.g. a freed-and-reused node) did. Mitigations: tagged pointers with version counters, and hazard pointers to defer reuse.
What is the correct pattern for a condition-variable wait?	Hold the mutex and loop on the predicate: `while (!ready) cond_wait(&cv, &m);`, because waits can wake spuriously or be stolen. Barriers and producer-consumer queues build on the same wait-in-a-loop discipline.


# 4.3 Embedded & Bare-Metal
What characterizes a freestanding bare-metal environment?	No operating system, so no `malloc`/`stdio` by default, a custom startup routine (`_start`/reset handler) that sets up the stack and copies/zeros data sections, and only the freestanding subset of headers. Your code owns the hardware directly.
Why must memory-mapped hardware registers be accessed through `volatile`?	A peripheral register can change on its own (status bits) and writes have side effects (triggering hardware), so `volatile` forces the compiler to perform every read/write exactly as written instead of caching or eliding "redundant" accesses.
How do you set, clear, and toggle a bit in a hardware register?	Set: `REG |= (1u << n);` Clear: `REG &= ~(1u << n);` Toggle: `REG ^= (1u << n);` Test: `if (REG & (1u << n))`. `REG` is a `volatile`-qualified pointer/macro so the read-modify-write actually reaches the hardware.
Why keep interrupt service routines (ISRs) short, and how do they share data?	An ISR preempts normal code, so long ISRs add latency/jitter and can miss other interrupts. Do minimal work (set a flag, enqueue data) and defer processing to the main loop; share state via `volatile sig_atomic_t`-style flags, mindful of reentrancy.
What is fixed-point arithmetic, and when is it used?	Representing fractional values as scaled integers (e.g. Q16.16: an `int32_t` where the low 16 bits are the fraction), used on MCUs without a floating-point unit. It gives deterministic, fast math but requires manual scaling on multiply/divide.
Why avoid dynamic allocation in embedded/real-time systems?	The heap can fragment, `malloc` timing is non-deterministic (bad for hard real-time), and there's often no MMU/swap so out-of-memory is fatal. Embedded code favors static allocation, fixed pools, and arenas with bounded, predictable behavior.
What are linker scripts and memory sections for?	A linker script maps code/data into the chip's memory: `.text`/`.rodata` (code/constants in flash), `.data` (initialized RAM globals, copied from flash at startup), `.bss` (zeroed RAM). Custom sections via `__attribute__((section(...)))` place things at specific addresses.
How are constants placed in flash/ROM, and what is a vector table?	Marking data `const` lets the toolchain place it in read-only flash instead of RAM, saving RAM. The interrupt vector table — an array of handler addresses at a fixed location — plus the reset/startup code are placed by the linker script at the addresses the hardware expects.
Why pack structs for wire/register layouts, and what is the trade-off?	`__attribute__((packed))` / `#pragma pack` removes padding so the struct exactly matches a hardware register or on-wire byte layout. The trade-off: members may become unaligned, making access slower or fault-prone on some architectures.
What are weak symbols used for in embedded code?	A `__attribute__((weak))` default (e.g. a default interrupt handler) can be overridden by a strong definition elsewhere without a link error. Firmware provides weak default handlers so applications can override only the ones they need.
Why does endianness matter in embedded protocols and serialization?	Different devices may store multi-byte values in different byte orders, so a struct dumped raw on one machine is misread on another. Serialize with an explicit byte order (often big-endian/network order) and convert on both ends.
What is a ring (circular) buffer used for in embedded systems?	A fixed-size FIFO with head/tail indices that wrap around, giving lock-free-ish producer-consumer (e.g. ISR produces, main loop consumes) without dynamic memory. Careful index/atomic handling makes single-producer/single-consumer use safe without locks.
What are watchdog timers, and why avoid optimizer-exploitable UB in embedded code?	A watchdog resets the system if the code fails to "kick" it periodically, recovering from hangs. Because embedded builds run at high optimization for years unattended, any undefined behavior the optimizer can exploit (signed overflow, aliasing) risks subtle, hard-to-debug failures — so keep timing deterministic and code UB-free.


# 4.4 Real-Time Operating Systems (RTOS)
What distinguishes hard, soft, and firm real-time systems?	Hard real-time: a missed deadline is a failure (airbag, motor control). Soft real-time: occasional misses degrade quality but are tolerable (media). Firm: late results are useless but not catastrophic. An RTOS prioritizes determinism over average throughput.
What scheduler types does an RTOS use?	Preemptive fixed-priority (the common default — the highest-priority ready task runs, preempting lower ones), round-robin/time-sliced (equal-priority tasks share the CPU in turns), and cooperative (tasks yield voluntarily). Preemptive priority scheduling gives bounded latency.
What are the typical states of an RTOS task?	Running (on the CPU), Ready (able to run, waiting for the scheduler), Blocked (waiting on a resource/event/delay), and Suspended (explicitly paused). The scheduler moves tasks between Ready and Running by priority.
What is the tick interrupt, and what is tickless idle?	A periodic timer interrupt (`SysTick`) drives time slicing, delays, and timeouts, and triggers context switches between tasks. Tickless idle stops the periodic tick when the system is idle to save power, waking only for the next scheduled event.
What synchronization primitives does an RTOS provide?	Mutexes (with priority inheritance), binary and counting semaphores, event flags/groups (waiting on bit combinations), and message queues/mailboxes for passing data between tasks. Each has an ISR-safe variant for use from interrupts.
What is priority inversion, and how is it solved?	A high-priority task blocks on a mutex held by a low-priority task, which a medium-priority task then preempts — so the high task waits indirectly on the medium one. Fixes: priority inheritance (the low task temporarily inherits the high priority) or priority-ceiling protocols.
What are deadlock and starvation in a real-time context?	Deadlock: tasks each hold a resource the other needs, so none proceeds (avoided by consistent lock ordering / timeouts). Starvation: a low-priority task never runs because higher-priority tasks monopolize the CPU (avoided by priority design, aging, or bounded execution).
Why must you use "…FromISR" API variants inside an ISR?	Regular blocking RTOS calls can suspend the caller, which is illegal in interrupt context. The `…FromISR` variants (e.g. `xQueueSendFromISR`) are non-blocking and ISR-safe, and report whether a higher-priority task was woken so the ISR can request a context switch on exit.
How are task stacks and heaps managed in an RTOS?	Each task has its own fixed stack; stack-overflow detection (guard words / MPU) catches overruns, which are a common bug. Memory comes from static allocation or fixed pools rather than a general heap, keeping usage bounded and deterministic.
How do RTOS software timers and precise periodic tasks work?	Software timers schedule callbacks after a delay/period off the tick. For precise periodic work a task uses an absolute-deadline delay (e.g. `vTaskDelayUntil`) that accounts for its own run time, avoiding the drift that a relative `vTaskDelay` accumulates.
What latency concepts matter in an RTOS?	Interrupt latency (time from an interrupt to its handler running), scheduling latency (time for the right task to be dispatched), jitter (variation in these), and worst-case execution time (WCET) — the analyzed upper bound needed to prove deadlines are met.
What are rate-monotonic (RMS) and earliest-deadline-first (EDF) scheduling?	RMS is a fixed-priority scheme for periodic tasks where shorter periods get higher priority — optimal among fixed-priority policies, schedulable below a utilization bound (~69% for many tasks). EDF is dynamic (nearest deadline runs first) and can reach 100% utilization.
How does an RTOS protect memory between tasks?	Using the MPU (memory protection unit) to give each task access only to its own stack/data, so a fault in one task can't silently corrupt another — plus memory pools instead of a shared heap to avoid fragmentation. Full MMUs are rare on MCUs.
Name common RTOSes.	FreeRTOS, Zephyr, ThreadX/Azure RTOS, RT-Thread, µC/OS, VxWorks, and RTEMS. They range from tiny open-source kernels for MCUs (FreeRTOS, Zephyr) to certified commercial systems for safety-critical use (VxWorks).
How do you get real-time behavior on Linux?	Apply the `PREEMPT_RT` patch (now largely mainline) for a fully preemptible kernel, use `SCHED_FIFO`/`SCHED_RR` real-time scheduling policies, call `mlockall` to prevent page-fault jitter, and pin work to isolated CPUs (CPU isolation/affinity).
What are core FreeRTOS API calls?	`xTaskCreate` (create a task), `vTaskDelay`/`vTaskDelayUntil` (sleep/periodic), `xQueueSend`/`xQueueReceive` (message queues), `xSemaphoreTake`/`xSemaphoreGive` (semaphores/mutexes), `taskENTER_CRITICAL`/`taskEXIT_CRITICAL` (critical sections), and `configTICK_RATE_HZ` (tick frequency).


# 4.5 Linux / POSIX Systems Programming
What is the difference between a system call and a libc wrapper, and how is `errno` set?	A system call is a direct kernel request (e.g. `read`, `open`); a libc function may wrap one or be pure user space (`strlen`). The `syscall()` interface invokes one by number. On failure syscalls return -1 and set `errno`; the wrapper propagates that.
What does the file-descriptor model mean, and what is `O_CLOEXEC`?	Files, pipes, sockets, and devices are all small integer descriptors used with the same `read`/`write`/`close`. `dup`/`dup2` duplicate/redirect them. `O_CLOEXEC` marks a descriptor to close automatically on `exec`, so children don't inherit it — important for security and leak avoidance.
What is `mmap` used for, and what does `mprotect` do?	`mmap`/`munmap` map a file or anonymous memory into the address space: memory-mapped file I/O, large/aligned allocations, and shared memory (`MAP_SHARED`) or private copies (`MAP_PRIVATE`). `mprotect` changes a region's permissions (e.g. read-only or executable).
Why use `epoll` over `select`/`poll` for many connections?	`select`/`poll` scan the whole fd set each call (O(n)), and `select` is capped by `FD_SETSIZE`. `epoll` registers interest once and returns only the ready fds (O(ready)), scaling to tens of thousands of connections; it supports level- and edge-triggered modes.
What causes a zombie or orphan process, and how do you handle each?	A zombie is a dead child whose exit status the parent hasn't reaped — reap with `wait`/`waitpid` or handle `SIGCHLD`. An orphan is a child whose parent exited first; it is re-parented to `init`, which reaps it. Process groups/sessions organize related processes.
What does `sigaction` offer over `signal`, and what is `SA_RESTART`?	`sigaction` gives reliable, portable control: a signal mask applied during the handler, flags, and `SA_RESTART` to auto-restart interrupted slow syscalls (otherwise they fail with `EINTR`). `signalfd` lets you receive signals as readable file-descriptor events instead.
What IPC mechanisms does POSIX provide?	Pipes and FIFOs (byte streams), System V and POSIX shared memory (fastest, shared address space), semaphores and message queues (synchronization/messaging), and Unix domain sockets (local bidirectional streams/datagrams, can pass file descriptors). Choose by data shape and performance needs.
What are the basics of network sockets on Linux?	Create a `socket` (TCP `SOCK_STREAM` or UDP `SOCK_DGRAM`), resolve addresses with `getaddrinfo`, then `bind`/`listen`/`accept` (server) or `connect` (client), and `send`/`recv`. Sockets can be blocking or non-blocking (for use with `epoll`).
How do you measure time on Linux, and monotonic vs realtime clocks?	`clock_gettime(CLOCK_MONOTONIC, &ts)` gives elapsed time unaffected by clock adjustments (use for intervals/timeouts), while `CLOCK_REALTIME` gives wall-clock time (can jump). `timerfd` delivers timer expirations as fd events; `nanosleep` sleeps with nanosecond resolution.
How do you parse command-line options and read the environment?	`getopt`/`getopt_long` parse `argv` into options and arguments (handling `-x`, `--long`, and option arguments). Environment variables come via `getenv`, and `argv[0]` is the program name; treat all of these as untrusted input in privileged programs.
What are daemonization, `syslog`, and `/proc` and `/sys`?	Daemonizing detaches a process from its controlling terminal to run in the background (fork, `setsid`, redirect std streams). `syslog` sends log messages to the system logger. `/proc` and `/sys` are virtual filesystems exposing process and kernel/device state as readable files.
What is dynamic linking, and what does `LD_PRELOAD` do?	At load time the dynamic linker resolves shared-library symbols, guided by `RPATH`/`RUNPATH` search paths, and supports symbol interposition. `LD_PRELOAD` forces a library to load first so its symbols override others (for profiling/mocking) — and is ignored for setuid programs for safety. `dlopen` loads libraries at runtime.
What are the differences between glibc and musl, and what are feature-test macros?	glibc is the large, feature-rich default on most Linux distros; musl is a small, simple, static-linking-friendly libc (common in Alpine/containers) with stricter standards conformance. Feature-test macros like `_GNU_SOURCE`, `_POSIX_C_SOURCE`, and `_DEFAULT_SOURCE` expose specific extension sets and must be defined before headers.
