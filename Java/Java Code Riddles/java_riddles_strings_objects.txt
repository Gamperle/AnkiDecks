# Format: Front[TAB]Back
# Predict-the-output riddles on String interning, ==, equals/hashCode, and object identity quirks.

# 1. String Pool & Interning
What does this print? `String a = "ab"; String b = "a" + "b"; System.out.println(a == b);`	`true` — both operands of `"a" + "b"` are compile-time constants, so the compiler folds the concatenation into a single constant `"ab"` at compile time, which is interned in the string pool just like the literal `a`. Same reference.
What does this print? `String a = "hello"; String b = new String("hello"); System.out.println(a == b); System.out.println(a.equals(b));`	`false` then `true` — `new String(...)` always allocates a fresh heap object regardless of pool contents, so identity differs even though the character content is equal.
What does this print? `String s = "hel"; String a = "hello"; String b = s + "lo"; System.out.println(a == b);`	`false` — this is the classic gotcha: because `s` is a variable (not a compile-time constant), `s + "lo"` is evaluated at *runtime* via a `StringBuilder`, producing a new, non-pooled `String` object even though its value equals the literal.
What does this print? `String s = "hel"; String a = "hello"; String b = (s + "lo").intern(); System.out.println(a == b);`	`true` — `.intern()` explicitly looks up (or registers) the string in the pool and returns the canonical pooled reference, making it `==`-equal to the literal.
What does this print? `String s = "abc"; s.concat("def"); System.out.println(s);`	`abc` — `String` is immutable; `concat()` returns a *new* string instead of modifying `s`. Since the return value is discarded here, the original is untouched. A very common beginner bug is forgetting to reassign: `s = s.concat("def");`.

# 2. equals/hashCode Contract
What happens here? A class overrides `equals()` but not `hashCode()`; you `add()` two "equal" instances to a `HashSet`.	Both get added — the set ends up with two elements that are `.equals()` to each other. `HashSet` uses `hashCode()` to pick a bucket before ever calling `equals()`; with the inherited `Object.hashCode()` (identity-based), the two instances almost certainly land in different buckets and are never compared. This is why the contract requires: equal objects **must** have equal hash codes.
What does this print? `record Point(int x, int y) {} System.out.println(new Point(1,2).equals(new Point(1,2)));`	`true` — records auto-generate `equals()`/`hashCode()` based on all components, unlike a plain class (where the inherited `Object.equals()` is reference identity and the same code would print `false`).
What does this print? `enum Color { RED, GREEN } System.out.println(Color.RED == Color.valueOf("RED"));`	`true` — enum constants are compiler-guaranteed singletons (one instance per constant, per classloader), so `==` is always safe and correct for enum comparisons — unlike ordinary objects or boxed wrappers.

# 3. Compile-Time Type vs Runtime Behavior
Does this compile? `Object obj = "hi"; if (obj instanceof String s) { } else { System.out.println(s); }`	No — the pattern variable `s` from `instanceof` pattern matching is only definitely assigned (in scope) inside the `if` branch where the match succeeded; in the `else` branch (or after, without a `return`/`throw` in the `if`), `s` is not guaranteed to exist, so it's a compile error.
What does this print? `Object o = 42; switch (o) { case Integer i -> System.out.println("int:" + i); default -> System.out.println("other"); }`	`int:42` — pattern matching for `switch` (finalized Java 21) lets a `case` label test the runtime type of the selector and bind it to a typed variable in one step, without a manual `instanceof` + cast.
What does this print? `String day = "MON"; switch (day) { case "MON": System.out.println("start"); case "TUE": System.out.println("early"); break; default: System.out.println("other"); }`	`start` then `early` — `switch` on `String` compares by content (via `hashCode`/`equals` under the hood, not `==`), but this is still a classic *fall-through* trap: the missing `break` after `case "MON":` lets execution continue into `case "TUE":`.
What is the value of `"""\n    hi\n    """` (a Java text block)?	`"hi\n"` — the compiler strips the *incidental* leading whitespace common to all lines (based on the least-indented line, including the closing delimiter's line) and normalizes line terminators, leaving only the deliberate content plus a trailing newline before the closing `"""`.
